# 界面指南

> 定位：插件在 DSH 界面中的全部出入口与交互。

## 「远程工作区」面板

侧边栏面板，注册在 `sidebar.panellist` 插槽，入口图标为服务器图标（`ServerIcon`），标题「远程工作区」。

主机卡片逐条展示存储与 `~/.ssh/config` 回退的全部主机，字段为别名、`user@host:port`、认证方式、来源（store / ssh-config），以及「密钥未就绪」提示（key 认证且 `keyPath` 在本机不存在时）。每张卡片提供：

- **测试连接**：调用 `POST /api/dsh-ssh-workspace/test` 实连一次，**然后释放这条连接**——「测试」回答的是「这台主机是否可达」，不是「替我连上」。结果以页面顶部 toast 呈现（成功附往返毫秒数），**统一 7 s 后自动消失**（成功 / 失败 / 中性同一窗口），点击或 Esc 可提前关闭；指针悬停暂停、移开重计满。错误提示可就地展开诊断码与原始错误、复制整段诊断，并在该动作可安全重放时提供「重试」——规则见「顶部提示（toast）」。连接指示点因此不会被一次探测点亮：刷新读的是实际剩下的连接，而不是假定测试留下了一条。
- **断开**：仅在该主机的连接状态为 `connected` 时显示（连接状态指示绿点内联在主机名之后；`broken` 与后台重连中**不出现**「断开」——同一行已经写着「已断开 / 重连中（第 N 次）」，再给一个「断开」是在提供一个不存在的状态，这两种状态改由「立即重连」承担）。点击调用 `POST /api/dsh-ssh-workspace/hosts/disconnect` 关闭该主机的池化连接，**并连带拆除该主机上的全部端口转发**（响应里的 `closedForwards` 报告拆了几条，toast 据此改写为「已断开连接，同时关闭 N 条端口转发」）。拆除的结果与在端口转发行上点「断开」**完全一致**：映射保留、意图置为断开、不记任何失败原因——主动断开不是故障，面板不该对它亮红字或提示「下次启动会自动开启」。连接上有操作进行中（进行中数量大于 0）时按钮禁用并给出提示。断开无需确认——下一次操作会按需重连。
- **立即重连**：仅在该主机处于后台重连状态时出现（等待中或已停止）。等待中的下一次尝试可能还有几十秒，`POST /api/dsh-ssh-workspace/hosts/reconnect` 跳过退避立刻试一次；成功显示「已恢复连接」，失败把真实错误放进 toast。主机卡片上的状态文字是「重连中（第 N 次，M 秒后）」/「重连中（第 N 次）」/「重连已停止」，并用黄点与「已连接」的绿点区分——重连中既不是连接正常，也不是刚刚断开。只要列表里还有在重连的主机，面板每 5 秒自动刷新一次，否则倒计时会停在原地（刷新只在浏览器可见时进行，无重连任务时完全停止）。
- **忘记主机密钥**：调用 `POST /api/dsh-ssh-workspace/hosts/forget-key` 清掉该别名的 TOFU 主机密钥记录（需就地确认），用于主机确实重装系统或更换密钥之后——见 [hosts.md](./hosts.md) 的「主机密钥校验」。
- **浏览目录**：打开该主机的目录浏览器（见下节）。它与「新建远程工作区」里的目录选择是**两个不同的组件**（这里是 `DirectoryBrowser`，那里是 `RemoteWorkspaceDialog`）：两者都只列目录、只为选路径；差别只在挂载入口——「浏览目录」本身就能挂载，而从主机卡片点进来，多半就是为了挂载。
- **编辑 / 删除**：编辑打开主机表单；删除为就地确认，删除只影响存储条目，不会自动卸载已挂载的工作区。

表单要点：密码与密钥口令**从不回传浏览器**，编辑时留空表示保留原值（见 [hosts.md](./hosts.md) 的「认证与凭据」）；切换认证方式时必须重新填写新凭据。

## 添加工作区双入口

插件占用两个 directoryFlow 插槽：侧边栏的 `sidebar.workspaces.directoryFlow` 与会话页的 `conversation.hero.workspace.directoryFlow`，以负优先级（`-100`）遮蔽部署自带的本地选择器——插槽核心渲染优先级**最低**的占用者，负优先级因此胜出，且不卸载内建实现。

触发后弹出锚定菜单（宽约 300px），包含两行：

- **本地**（FolderIcon）：转交 DSH 原生目录选择器——桌面端走 preload 桥 `__DSH_DIRECTORY_PICKER__`，否则走 `uiWorkspace.pickDirectory()`。
- **远程**（远程标记图标）：打开「新建远程工作区」对话框。

锚定机制：触发按钮不传给插槽占用者，因此插件在捕获阶段监听 `mousedown` 记住最近一次按钮位置（3 秒内有效，避免键盘快捷键打开时菜单"瞬移"），弹出层定位在按钮右侧 8px 处，并钳制在视口内；窗口 resize 时重新定位。点击菜单外部或按 Esc 关闭。

## 浏览目录对话框

点主机卡片的「浏览目录」打开 `DirectoryBrowser`（`lib/client.js`）。它与「新建远程工作区」里的目录选择**不是同一个组件**（后者是 `RemoteWorkspaceDialog`，只列目录、只为选路径），因此两者能力不同：

- 顶部：返回上级、当前绝对路径；
- 列表：目录在前、按名排序；文件行显示大小，**目录行是唯一的可点对象**（进入下一级）。这里**不提供上传、下载或选择**：文件行只是静态展示，没有勾选框、批量条或行内传输按钮；
- 底部：「挂载此目录」——按当前路径创建远程工作区，成功后附**能力提示**（`capabilityNotes`：`rg` / `git` / `inotifywait` 的缺失项，只报探测出的确定缺失）。

首帧路径为 `null`，首次 `GET /ls`（不带 `path`）返回 SSH 登录目录后回填，所以「挂载此目录」永远指向一个真实绝对路径。加载中 / 空目录 / 无法加载是三种独立状态。

这个对话框只负责**浏览与挂载**：上传与下载只从文件树行右键菜单进入，进度留在文件面板头部的队列入口或完成提示里；对话框内不展开队列条，同一份 store 不再有第二个展示面。

## 顶部提示（toast）

所有面板、文件树与传输反馈共用**同一个** DOM toast 控制器（`notifyUser` / `transferNotice`），同一时刻只有一个节点；新提示替换旧提示时旧计时器一并取消。文案全部走 i18n，中英同键。

| 场景 | 计时与关闭 | 可做的动作 | 焦点 |
| --- | --- | --- | --- |
| 成功 / 中性（`ok` / `muted`） | 7 s；指针悬停暂停、移开重计满；点击、Esc 提前关闭 | 无动作按钮 | 出现不抢焦点，关闭不移动焦点 |
| 错误（`err`） | 同上；`role="alert"` 立即播报 | 「详情」默认收起，`aria-expanded` 翻转，展开诊断码 + 原始错误；「复制」复制整段诊断；「重试」仅在该动作可安全重放时渲染 | 出现不抢焦点；用户 Tab / 点击进入后关闭，焦点回到来源 |
| 不可重放错误 | 同上 | 只有「详情 / 复制」；**不渲染灰色或禁用的「重试」** | 同上 |
| 传输进行中 → 结果 | 在途不计时；结果就地改写同一节点并从结果时刻起算 7 s | 结果失败带诊断码 / 原始错误，可详情 / 复制；整批不提供重试（重试在队列行上） | 同上 |

规则：

- **只有一个节点**：复制、详情、重试、在途→结果的反馈都就地改写同一元素，不新增第二条 toast，也不重置原来的 7 秒窗口；重试成功同样在原节点变成成功态。
- **重试门控**：仅「测试连接、立即重连、断开、启用、自检、打开诊断报告」提供重试；卸载、忘记主机密钥、转发保存 / 切换 / 记住、启动自动开启、重命名 / 删除、传输批次不提供——这些动作可能已经部分落地，重放不是幂等。
- **复制失败不静默**：剪贴板 API 缺失或被拒时，自动展开详情、用 `Range` / `Selection` 选中整段诊断（诊断码 + 原始错误），并在同一节点写「已选中，可按 Ctrl+C 复制」；不另开提示。
- **焦点**：`tabIndex=0` 让提示可键盘到达，但出现时不调用 `focus()`；关闭时仅在 `activeElement` 确实在提示内部时才把焦点还给来源。`muted` 与成功态同样不抢焦点。

## 三个对话框的遮罩关闭（`backdropDismiss`）

`HostEditor`、`DirectoryBrowser`、`RemoteWorkspaceDialog` 三处共用 `backdropDismiss(close)`：判据是**按下与松开都落在遮罩上**，而不是「click 落在遮罩上」。

差别不是学究式的。`click` 的事件目标取**按下点与松开点的最近公共祖先**——在输入框里拖选一段文字、把鼠标拖到对话框外再松开，按下在对话框内、松开在遮罩上，浏览器仍会把 click 派发到遮罩，于是 `onClick: onClose` 会在用户选字的半途把整个流程关掉。按下点才是可靠信号。

四条附带规则，每条都对应一种会回退的行为：

- **只认主键**（`event.button === 0` 才置位）。`click` 从不为副键派发，若不加这道门，「右键按在遮罩上松开」会凭空多出一个关闭动作，而右键本该只弹上下文菜单。**松开侧刻意不设这道门**：touch / pen 的 `pointerup` 在部分引擎里报 `button: -1`，门住它会让触屏点空白再也关不掉。
- **状态写在元素上，且每次 `pointerdown` 无条件覆写**。按下后把鼠标拖出窗口再松手，多数平台根本不派发 `pointerup`；若靠「松手时清理」，残留的「已按下」会漏到下一次手势里，反而在用户从对话框内按下时误关。因为遮罩是祖先节点，来自对话框内部的按下会冒泡到它并把标志覆写为 false。
- **忙碌时关闭被拒**：编辑对话框存盘中、目录浏览器传输中、创建工作区接纳中都不可用遮罩关闭（各自的门禁写在组件的 `dismissBackdrop` 里），否则会把仍在进行的请求连同它唯一的反馈一起丢掉。
- **对话框本身没有 Escape 关闭**。三个组件都没绑键盘关闭，遮罩收紧后唯一的出口是各自可见的「取消 / 关闭」按钮与标题栏的 ×。这是现状而非遗漏：加 Escape 必须处理「下拉框或文件选择器正吞这个键」的先后，需要真机浏览器验证，不在 0.2.5 范围内。

## 新建远程工作区对话框

一次完成"选主机 → 选目录 → 命名 → 挂载"：

1. 拉取主机列表，默认选中第一台；主机列表为空或出错时给出对应空态。
2. 目录浏览：`GET /api/dsh-ssh-workspace/ls?alias=…&path=…` 逐级浏览远端目录，只列目录、按名称排序；提供「返回上级」、加载中 / 空目录 / 无法加载三种状态。
3. **可写探测**：`/ls` 同时回报 `writable`。目录不可写时显示红色警告（"当前 SSH 账号对这个目录没有写入权限……"）并禁止创建——写入能力是 Agent 工作的前提。
4. 创建：`POST /api/dsh-ssh-workspace/mount`，携带 `{alias, remotePath, title, register: true}`。**先注册、后接纳**：挂载路由在宿主接纳该路径之前就按所填名称登记工作区，宿主随后解析到既有记录，避免以派生标题重复建条目。成功后刷新标记数据源，把路径交还吸附链路；对话框在接纳期间保持禁用，背景点击可取消（创建中除外）。

## 远程工作区标记

远程工作区不以文件夹图标示人，而是显示 SSH 标记。DSH 的行图标没有插件插槽，实现为 **DOM 装饰**（`lib/client.js` 的 "Remote-workspace marks" 段），三条原则：

- **React 安全**：从不删除或搬迁 React 拥有的节点——仅通过内联 `style` 隐藏文件夹字形（React 不会重写这些节点的 `style`），在旁插入自带 `data-sshwsp-mark` 的 svg。
- **自愈**：`MutationObserver` 监听 `document.body`，React 重建行节点后自动重新施加替换；工作区不再远程时同样自动还原。
- **身份匹配**：从 live `workspaces` store 的 `getSnapshot()` 取 id / title 集合（服务不可达时退回 `/status` 的 `workspaces` 数组）。侧栏行按工作区 **id** 匹配；选择器菜单行与会话页 hero 工作区按钮只有标题，按 **title** 匹配，hero 在会话刚建立时可能显示路径 basename，故 basename 也计入标题集合。

### 同名工作区：标题只是一半身份

一个标题可以由两个工作区同时使用——本仓库本身就同时是本机检出和一个
`ssh://qiyk/.../dsh-ssh-workspace` 挂载。只按标题判定时，本地那一行会被换成
远端标记（停用清单同理，会把本地行置灰成不可点）。

规则因此拆成两半：**远端集合**由 ssh:// 工作区的 title / basename 构成，
**本地集合**由其余工作区的 title / basename 构成，两边都有的标签**不标识任何一方**：

```js
remoteMarks.titles.has(text) && !remoteMarks.localTitles.has(text)
```

`collectRemoteWorkspaces` 收本地标题（`remoteMarks.localTitles`），
`remoteTitleMatch` / `detachedTitleMatch` 是唯一的判定入口，四处展示
（侧栏行、选择器菜单、hero 按钮、停用置灰）都调用它们，不各写一份。
侧栏行的 **id** 命中仍然直接算远程，所以共享标题不会反过来藏掉真正的远端行。

同一条规则也解释了为什么标题匹配要等一次**完整**的收集：`/status` 只回报远程工作区，
按它判「没有本地同名」必然误判，所以 `titlesSettled` 只在读过 DSH 自己的 store 之后
才置真，此前一律不按标题标记；服务不可达时那次回退只做 id 匹配。id 匹配不受这条限制
——停用清单照旧先按路径与 id 生效。

装饰同时覆盖三处展示：侧栏工作区行、侧栏选择器菜单行、会话页 hero 工作区按钮。

### 停用工作区的置灰

已停用（`detach` 过）的工作区，侧栏那一行会被打上 `data-sshwsp-disabled="1"`，
由 CSS 降到 50% 不透明度并在行尾加一枚 `⏻` 标记，**同时把这一行里的按钮变成不可点**：

```css
[data-sshwsp-disabled="1"] button,
[data-sshwsp-disabled="1"] [role="button"] { pointer-events: none; opacity: 0.4; }
```

置灰只是装饰，真正拒绝点击的是这条规则。一个看灰了却仍能触发「新建会话」「重命名」
「删除」的行是在谎报，用户只有点下去、拿到错误之后才会发现。用 CSS 而不是拦 DSH 的
点击处理器，是因为后者属于和宿主抢控制权，宿主一改版就会崩；选择器写成通用的 `button`
而不是本插件自己的类，是因为那些按钮是 DSH 画的。

**工作区标题那一行本身仍然可点击**：展开分组是看清「停用保留了哪些会话」的唯一途径。
所以规则只落在 `button` / `[role="button"]` 上，不落在标题行上。

**它下面的会话行则整行不可点**——这里的情况相反：会话行本身就是「打开会话」那个控件，
只把它的按钮置灰会把唯一要紧的动作留着。这类行按行键单独作用域：

```css
[data-row-key^="session:"][data-sshwsp-disabled="1"] { pointer-events: none; cursor: not-allowed; }
```

`pointer-events` 只挡鼠标，键盘路径由脚本补 `inert` + `tabindex="-1"`。会话行是 `session:<id>`，
**不携带任何工作区信息**，所以成员关系由 `/status` 的 `workspaces[].sessionIds` 下发。

真正的恢复入口是面板里的「启用」按钮。

身份匹配需要 id 与标题两套集合。这里有个容易踩的坑：`readLiveWorkspaces()` 会从
DSH 自己的 store 重新收集身份，而那个 store **不知道**本插件的停用清单，所以停用
路径单独保存在 `knownDisabledPaths` 里并在每次重新收集时传回去——否则置灰会在
下一次 MutationObserver 回调时消失。

## 面板：已挂载与已停用

「远程工作区」面板把工作区分成两段，互斥：

| 分区 | 内容 | 每行操作 |
| --- | --- | --- |
| 已挂载的工作区 | `/status` 的 `mounted[]` | 「卸载」→ 就地展开确认行 |
| 已停用的工作区 | `/status` 的 `disabled[]` | 「启用」 |

**卸载是两步的**：第一次点击只展开确认行（附带「同时删除工作区记录」复选框），
第二次点击「确认卸载」才真正执行。这个动作会影响到该工作区登记的全部会话，一次点击
就执行不合适。

两种模式的后果**只写在「卸载」按钮的悬停提示里**（`mounted.detachHint`，展开确认行后
由「确认卸载」沿用同一个 `title`）：未勾选则工作区记录与会话都保留、左侧那一行仍在
（置灰）、随时可重新启用；勾选则工作区记录被删除、会话归档。不再在确认行里另起一行
常驻文字——那行说明会随复选框变化而要重写一遍，而提示只需要说清两种模式的区别。

两个模式分别对应什么，是这一段的验收口径：

| 复选框 | 模式 | 侧栏那一行 | 面板这一行 | 会话 |
| --- | --- | --- | --- | --- |
| 不勾（默认） | `detach` | **保留**，置灰且按钮不可点 | 移到「已停用」分区，可「启用」 | **保留，不归档** |
| 勾选 | `deregister` | **删除** | **删除** | 归档，不删除 |

「保留记录却不保留会话」是自相矛盾的：`detach` 留住侧栏那个分组，就是为了让用户还能
点开它；把会话归档等于把分组内容清空——行还在，点开却是空的，比删掉更让人困惑。所以
归档跟随「删除记录」这个勾选，而不是独立开关。

勾选时的「两边都删除」是**必须同时成立**的：删掉工作区记录已经让侧栏那一行消失，
而面板的「已停用」分区由持久化的停用标记驱动——如果只删记录、不清标记，面板会继续
为一条在任何地方都不存在的记录提供「启用」按钮，而运行时围栏又拒绝这个已经无法
再启用的路径。所以 `deregister` 会同时清掉**持久清单**与**运行时围栏**两处标记。

「已停用分区始终渲染」只针对 `detach`：这是用户得知「卸载之后还留了个东西可以
启用」以及「它去哪了」的唯一途径——如果只在有内容时才渲染，第一次卸载的用户会
以为工作区被永久删除了。

已停用行的样式是 `opacity: .62` 加一个「已停用」小标签，**不使用
`pointer-events: none`**：这一行存在的意义就是它的「启用」按钮。

## 面板：主机与端口转发

主机区每行一个 alias，右侧是「断开」；端口转发区列出**已存映射**与临时隧道，
顶部有「启动时自动开启隧道」总开关。

### 两条「断开」路径必须在面板上不可区分

面板读的只有三个字段：`live`（是否真有 listener）、`enabled`（用户的意图）、
`error`（是否需要解释）。两个入口都指向同一个关闭方法，所以三者逐字段相同：

| 入口 | 走的路径 | `live` | `enabled` | `error` | 面板那一行 |
| --- | --- | --- | --- | --- | --- |
| 主机行的「断开」 | `savedForwards.closeAlias(alias)` → 逐条 `closeById` | `false` | `false` | 无 | 已断开 + 开启，**无红字** |
| 端口行的「断开」 | `closeById(id)` | `false` | `false` | 无 | 同上 |
| 连接意外掉线 | `ForwardManager.closeForAlias()` → `onClosed` | `false` | `true` | `"SSH connection closed"` | 已断开 + 开启 **+ 红字「连接已断开」** |

第三行才是故障：连接断得不是时候，所以要保留意图（下次可一键恢复）并留下原因向用户
解释。前两行是用户主动完成的动作，留下原因等于把成功的操作报成故障，后面还会跟着
「启动时自动开启隧道」的暗示——而用户刚刚明确关掉了它。`forwards.lost`
（「连接已断开」）只在 `error` 里含 `connection` 时渲染，因此主动断开后不会出现。

主机行「断开」的 toast 在拆掉了隧道时报数：`hosts.disconnectOkForwards`
（「已断开连接，同时关闭 {n} 条端口转发」），`n` 来自响应的 `closedForwards`；
没有隧道时用 `hosts.disconnectOk`。失败时同一提示带 `SSHWSP-E-HOST-DISCONNECT`
与原始错误，可就地展开 / 复制，并在原节点重放「断开」——主动断开成功不会被改写成故障。

### 面板：持久远端会话

`status.shells` 非空时才出现「持久远端会话」一区，每行 `alias [session]` + 状态
（`存活` / `已结束`）。它是一个**只读**列表——这一区不提供开关或关闭按钮，
因为会话的生命周期归 agent 的 `ssh_workspace_shell` 管（同一 `alias` 可并存多个
命名会话）。空列表**整区不渲染**，避免暗示面板拥有一个它并不拥有的控制项。

## 面板：诊断报告

面板底部的「诊断报告」一节是插件唯一**预期被贴到公开场合**的产物：一段纯文本，
把版本、补丁判定、主机配置（含 `~/.ssh/config` 审计）、工作区、连接代次、端口转发、
每主机自检、最近命令与事件组装在一起，供用户贴进 issue。

三个入口共用同一个 `buildSupportBundle`，措辞与脱敏规则不会分叉：

| 入口 | 形态 |
| --- | --- |
| 面板「打开诊断报告」 | 取 `GET /api/dsh-ssh-workspace/support-bundle` 的文本，渲染为面板内的对话框 |
| 报告窗口内的「复制」 | 把**屏幕上这一份**文本写剪贴板；没有剪贴板权限时选中全文，让用户手动 Ctrl/Cmd+C |
| `ssh_workspace_status` 的 `supportBundle` | 字符串，agent 可直接取用 |

### 状态灯：报告本身不给结论，所以结论由判定模块给

诊断报告是**事实汇总**，不是体检报告——九个章节全是原始事实，没有一行说"这算不算问题"。
这对粘贴是对的（它不能与面板矛盾），对面板是错的：用户不该需要知道阈值才能判断
`probe: 'fixed'` 意味着"该删了"、或者主机没出现在列表里意味着它的配置被拒绝了。

所以判定被拆成独立模块 `lib/diagnosis.js`，并在报告标题后画一个圆点：

| 状态 | 颜色 | 含义 |
| --- | --- | --- |
| `ok` | 绿 | 没有需要处理的事项 |
| `warn` | 红 | 有 N 项需要处理（标题 `title` 与读屏标签给出条数） |
| `unknown` | 琥珀 | 有 N 项无法判断 |

**三态不折叠成两色。** `unknown` 既不是绿也不是红：探测不到的主机不能报成"缺了它所有的
工具"，也不能报成"一切正常"。聚合时**确定的坏压过不确定**——一个红点说"另外我还判断不了
一件事"仍然是红点，可行动的那条事实更重要。

判定只读报告**已经在打印的字段**，不探测、不连接、不读文件。它在**服务端**计算
（`/status` 的 `diagnosis` 字段），浏览器只负责渲染——两处各自推导同一套规则，是"圆点与
报告说法不一致"的开始。

**圆点必须在面板里可行动**：findings 直接列在标题下方（最多 8 条，其余显示总数）。
一个只说"有问题"却不说是什么的圆点是个谜题，不是报告。

### 圆点只回答「这个会话有没有事」，不回答「这台主机能做什么」

自检（缺 `rg`、缺 `git`、非 UTF-8 locale、watch 上限偏低）**不算 findings**，只作为
`notes` 单独呈现：折叠在 findings 下方，带自己的标题，且**不带严重度徽章**。

理由是这两类事实性质不同：

| | 例子 | 谁能改变 | 属于 |
| --- | --- | --- | --- |
| finding | 主机密钥没固定、存储读不出、重连放弃了 | 用户，通常就在面板上 | 这个会话出了事 |
| note | 缺 `rg`、locale 非 UTF-8、`inotify` 上限低 | 往往改不了（无 root、镜像受限） | 那台主机就是这样 |

把 note 混进 findings 的直接后果是**灯在健康的机器上变红**：装了个干净的 Debian、
没装 `rg`，圆点立刻是红的。会变红的灯最后一定不被读——而它一旦被忽略，就再也无法承载
真正要紧的那两条（未固定的密钥、读不出的存储）。

note 不是被藏起来：它仍然在面板里（可展开）、在报告里（`advisory (not counted in the
verdict):` 一节）、在工具返回值里（`diagnosis.notes`）。**看不见的降级仍然是禁止的**，
只是它不再冒充结论。

判定与计数只读 `findings`，`notes` 永远是 `state` / `warn` / `unknown` 的旁观者。

### 自检分区默认关闭

面板上原本有一节「远程环境自检」，每台探测过的主机一张卡片，外加一个「自检」按钮。
**这一节现在不渲染了**，由 `lib/client.js` 里的 `SHOW_SELF_CHECK_SECTION = false` 控制。

**是关掉的一棵活树，不是注释。** 两者的区别在于本仓库的测试方式：`client-shape-smoke`
几乎全部断言都是对 bundle 文本做 grep，把 JSX 注释掉会让**所有**相关断言继续绿着，
而面板什么都不显示——测试从此描述一段不存在的界面。所以这里留一个具名布尔值，两处渲染点
（标题区与列表）都带 `&& SHOW_SELF_CHECK_SECTION`，并让套件把「它是活的」也钉住：
`isLive()` 用注释配平判定某个匹配落在注释里还是代码里。改回 `true` 就恢复 0.2.8 的行为，
包括每张卡片的展开与 `/status` 优先的数据源。

**信息没有消失，只是不再占面板。** 同一批行的其余三条路径都还在：状态灯下方的
`details` 提示块、诊断报告里 `advisory (not counted in the verdict):` 一节、
`GET /self-check` 与 `ssh_workspace_status` 的 `selfCheck` 字段。一条事实都没少，
少的只是面板对一个它并不参与判定的信息又重复了一遍。

关掉的是渲染，**不是探测**：服务端仍然按需探测并缓存，因为报告和 agent 都要读它。

### 自检卡片：默认折叠，标题即开关

（以下描述的是开关打开时的形状，保留下来是因为恢复时要恢复的是这个行为，而不是它前面那个 bug。）

一张自检卡片只显示 `qiyk  2 缺失  3/7 已安装`。想知道缺的是哪两个，点标题展开——
标题是 `<button aria-expanded>`，不是 `div` 加 `onClick`：键盘可达、读屏能读出展开状态，
这两件事不该靠重新实现获得。展开状态按 alias 存在面板层，**不在卡片内部**——面板有轮询，
把状态放进行里会让它每隔几秒自己收起，比不带展开更糟。

这里曾有一个真实的 bug，值得记下因为它长得不像 bug：**切到别的页面再回来，卡片还记得
「2 缺失」，却再也说不出是哪两个**。原因是渲染取的是 `checkReports`，那是 React state，
随面板卸载一起消失；而 `missing` 计数走的是 `/status`，活了下来。于是界面停在「有数量、
无名字」——不是交互缺失，是**数据源选错了**。

修法是把 `/status` 放回第一顺位：它每次都从服务端的探测缓存重新推导同一批 `rows`，
既持久又同样新鲜；手工点「自检」拿到的报告仍然优先，因为它可能比最近一次轮询更新。
`selfCheckSummary` 因此被抽成纯函数并被测试**真实执行**——包括「有计数无行」这一种，
它是这个 bug 的独有状态，截图里永远看不到。

面板上「缺失 N 项」与「N 项未确定」是两个并列的徽章：`unknown` 不是 `absent`，
统计里分开数，展开的明细里也分开措辞。

### 报告里补上了三处它原本漏掉的事实

判定要诚实，报告就得先带上这些事实（都来自已有数据，没有新增采集）：

- **`## host keys`**：被接受但没能固定的主机密钥。这是"报告什么都没说"与"报告说一切正常"
  曾是同一个画面的地方，也是安全上唯一真正要紧的一条；
- **被跳过的主机**：`~/.ssh/config` 里存在但无法使用（如 `ProxyJump`）的条目以前**根本不出现**
  在报告里，于是"我明明配了却用不了"没有任何线索。现在带原因列出，别名照样打码；
- **连接代次**：`generation` 大于 1 时说明"重连前启动的远端进程可能仍在运行"。
  "偶发断线"与"从没连上"以前在报告里长得一样。

另外，空补丁列表的措辞不再合并两种情况：`none installed (or the projection seam was
unavailable)` 把"补丁不需要装"和"我不知道补丁装没装"写成了一句，现在只说后者。

「复制」不在面板工具栏上，而在报告窗口里。复制只在**已经有一份报告**时才有意义，而且
工具栏上的「复制」在无剪贴板权限时会悄悄改成弹出一个窗口——按钮的标签承诺了另一件事。

### 报告窗口：自动换行、打开不选中

文本用 `wrap="soft"` + `white-space: pre-wrap` **自动换行**。它曾经是 `wrap="off"` 加横向
滚动，为的是让一条被脱敏的长路径留在一行；但报告是逐行读的，横向滚动逼读者一边读一边拖，
而换不换行对内容没有区别——等宽字体下对齐照旧。

打开时**不自动全选**。`area.select()` 挂在挂载时看着贴心，实际是：整份报告在用户还在读的
时候闪成高亮，之后任何一次按键都把选区换掉，浏览器没拿到焦点时还会留下一个没人要的选区。
复制改为窗口底部的按钮，键盘用户也够得着。只有在**复制失败**（没有剪贴板权限）时，
才退而选中全文——那是用户按了「复制」之后的补救，不是打开时的惊喜。

`client-shape-smoke` 对 `ReportDialog` 内部**计数** `.select(` 的出现次数（恰好 1，且必须
在 `handleCopy` 之后），而不是断言「挂载时没有 `area.select()`」——后者会被
`areaRef.current?.select()` 这种写法绕过，反向验证时确实绕过过一次。

### 「打开」为什么不能是新窗口

「打开诊断报告」曾经是一个 `<a href="…" target="_blank">`。**在桌面端它点了没反应**，
而路由本身返回 200——失败的是新窗口这条路径，有两层原因：

1. 桌面端的文档来源是 `dsh-app://app/`，相对 `href` 于是解析到 `dsh-app://` 协议。
   主窗口的 `setWindowOpenHandler` 只放行 `http:` / `https:`，其余一律 `deny`，
   点击被静默吞掉。
2. 即便协议被放行，`shell.openExternal` 会交给系统浏览器，而那个浏览器没有 Host 的
   鉴权 cookie，只会拿到 `401 dsh web authentication required`。

所以入口改为**在面板内取同一份字节**：`fetchReportText()` 是唯一的取数点，「打开」把它
渲染进一个只读、可选中、等宽的 `ReportDialog`，复制在该窗口内完成。`client-shape-smoke` 用
「这一节里不得出现 `window.open` / `target: '_blank'`」来钉住它——断言的是**形状**
而不是「有个按钮」，因为前者才是两个壳子里都会坏的那一半。

### 标题叫「诊断报告」，标识符仍是 `support-bundle`

标题改过一次：原先叫「支持包」，那是从 Docker / Kubernetes 借来的术语，而本插件
没有支持台、产物不是归档、且**不上传任何地方**——"支持"二字暗示了一个并不存在的
接收方。新标题用「诊断报告 / Diagnostic report」。

**标识符一律不动**：路由 `/support-bundle`、工具字段 `supportBundle`、模块
`lib/support-bundle.js`、套件 `support-bundle-smoke` 都是契约面，改名没有功能收益。
这与仓库既有习惯一致——面板叫「最近的远端命令」而模块叫 `audit.js`。

避免用「插件诊断」：`ssh_workspace_status` 里已有 `diagnosticsText`（事件环容量 40 条、
它只导出最新 20 条），
两个"诊断"并存会让读者分不清该贴哪一个。「报告」二字守住了区别——这是**一份可读
文本**，不是要上传的归档。

### 脱敏是设计约束，不是选项

- 家目录段打码，保留首段与扩展名（仍能分辨 `src/index.ts` 与 `dist/app.js`）；
- alias 短写且**跨行一致**（同一主机的多条事件仍可关联）；三个字符以内整体打码；
- 登录用户打码而地址与端口保留（`<user>@10.0.0.1:22`）；
- 命令行经 `audit.js` **在写入时**脱敏，不在导出时补第二次；
- 凭据从不进入报告：存储里的 secrets 是加密的，报告读的是面板那份无密行。

**没有"原始模式"开关**——有 raw 开关的报告，一定会有人用 raw 模式贴出去。

报告末尾固定一句：`Paths, usernames and credentials are masked. Nothing was uploaded: you decide where this goes.`

这句话**只留在报告里**。面板工具栏下面那行提示原先也带着"不会上传到任何地方"，两处同时
声明让一句陈述读起来像免责声明；提示现在只说**报告包含什么、已经脱敏**，"不上传"由报告
自己的收尾句负责——那是唯一真正需要读者知道这件事的地方（他正要把它贴出去）。

## 路径的展示拼写

两处纯展示的替换，把 `ssh://alias/path` 显示为 `ssh://alias@/path`（读起来像 SSH 地址）：

- 工作区悬停卡片（hover card）中的路径；
- DSH `PathLabel` 单元格：文件面板头部、文档预览标题、交付物列表。

只改渲染文本，复制行为与所有功能消费方保持真实拼写。规则细节见 [protocol.md](./protocol.md) 的「显示规则」。

## 文件进任务：拖拽与右键

侧边栏文件树的文件与文件夹（`li[data-files-entry="file"|"directory"]`）有两种手势把路径加入当前会话的任务：

- **左键拖到输入框**：拖动经过输入卡（`[data-composer-card]`）时卡片显示虚线高亮（内联 `outline`，拖拽结束/离开即清除）。指针在 `[data-composer-input]` 内时，`dragover`/`drop` 用浏览器的 `caretRangeFromPoint` 把指针位置映射成当前草稿的 detect 偏移；第一个 chip 插在落点，后续 chip 依次跟在它后面。拖动期间输入框内画一条 2px 竖向落点光标（单例 `#sshwsp-drop-caret`，只设内联样式），离开输入区、松手或拖拽结束即隐藏。多选整批拖入时按树中顺序逐条插入、重复路径只插一次、末尾只聚焦一次；拖拽结束时清掉树行里被手势留下的文本选区，光标落在 chip 之后而不是行名上；
- **落点映射的退化**：只有“唯一可见的输入卡”且指针确实落在其输入区内、浏览器能给出 caret、边界能映射到草稿时才使用落点；以下任一情况都回退到旧行为（追加到当前选区/末尾），且不会让投放失败：

  | 条件 | 结果 |
  | --- | --- |
  | 同时可见多张输入卡，或投放卡片不是唯一可见那张 | 不使用落点 |
  | 指针在卡片内边距/边框上，但不在 `[data-composer-input]` 内 | 不使用落点 |
  | `caretRangeFromPoint` / `caretPositionFromPoint` 不可用，或返回输入框外的节点 | 不使用落点 |
  | 边界落在顶层段落之外，或偏移超出当前 draft | 不使用落点；空输入框中的空段落仍可映射到 0 |
  | 映射过程抛异常 | 捕获后回退，拖拽插入继续 |
  | 宿主拒绝该 span（越界/版本漂移） | 同一 span 走纯文本降级；再失败才提示插入失败 |

  落点只由**第一个**插入项消费；它失败或不可表示时不会污染后续项——首项不可表示则留给下一项，首次尝试失败则后续项改用实时 `captureInsertion()`。
- **右键 → 菜单**：行上弹出锚定菜单（复用 `.sshwsp-flowmenu` 样式，视口内钳制）。**多选时菜单作用于整个目标集合**（`resolveTargets`：右键落在选中之外的行会先收拢到该行，落在选中之内则保留整批），「添加到任务」与拖拽走同一个插入助手，因此一次只聚焦一次、逐条插入、重复路径只插一次；
- **空白处右键（仅本地工作区）**：菜单恰好两项——「新建文件夹」与「复制路径」。目标目录是空白处所属的那一个：落在某个已展开目录的嵌套列表里就是那个目录（宿主的子列表在该目录自己的 `li` 内，所以不能拿 `closest(li)` 当行手势），否则是树根；两者都必须在该树根之内，根是 `ssh://` 或不在根内时整条本地路径不成立。新建走共享的 `POST /mkdir` 本地分支并选中新行；「复制路径」始终可用，只读会话只禁用新建。远端工作区保留原来的空白处菜单，两种菜单不混用。

菜单内容取决于该行是否落在远端工作区：

  | 菜单项 | 出现条件 | 说明 |
  | --- | --- | --- |
  | 「添加到任务」 | 总是 | 菜单项副标题直接显示将要插入的 `@` 拼写，点击插入 |
  | 「下载到本机」 | 仅远端行 | 目录行同样可下载：整棵目录以 ZIP 归档流式下载（`?format=tar` 可改要 tar）。归档边读边写，没有 `content-length`，队列按已传字节报进度而不画百分比 |
  | 「上传文件到此目录」 | 仅远端行 | 文件行传到它的父目录，目录行传到它自己 |

  本地工作区的行只有「添加到任务」——`GET /download` 与 `POST /upload` 对本地路径没有任何可对话的对象，摆出这两项等于承诺一个该行并不具备的能力。

插入与「`@` 补全里选中候选」走同一条管线：取主会话 composer 的 `captureInsertion()` 跨度（拖放时第一项改用指针映射出的折叠跨度），经会话作用域的 `slash/input-insert-reference` 事件交给编辑器——chip 节点、序列化与失效判定因此与补全完全一致（插入后可继续输入、照常提交）。会话监听不声称该事件时降级为纯文本插入；输入框不可用或路径不可表示时给出 toast。拖放跨度只在第一次尝试中使用，文本降级复用同一个 span，不会重新 capture 后把落点丢掉。

拼写规则与 `@` 补全一致：树根即会话 cwd 时用**工作区相对路径**（`/` 分隔），否则保留绝对拼写；含空格按引号语法（目录保留开引号）。带控制字符或双引号的路径拒绝插入。

实现要点（`lib/client.js` 的 "Composer file bridge" 段）：行的 `draggable` 标记并入 DOM 装饰的同一趟 pass（`MutationObserver` 触发、rAF 合并）；拖拽只写入自定义 MIME、**不写 `text/plain`**，因此不触发输入框的文本粘贴，也不会与 DSH 的「拖入文件」浮层冲突；文档级 capture 监听 `dragover`/`drop` 判定输入卡并转发手势。**载荷是版本化 JSON**（`{v:1, items:[{path,isDir}], root}`）而不是单条路径：`dragstart` 用 `resolveTargets` + `treeSelectedItems` 得到整批目标，点在选中之外时先按 `point` 手势收拢；`drop` 先用当前事件 `dropOffsetFromEvent` 重算落点（不缓存 dragover 的值），再只调一次 `addPathsToTask(..., card, at)`。坐标映射（chip=1、managed `<br>`=0、段落间一个 `\n`、嵌套元素递归）与视觉光标各只有一处实现；光标是 `document.body` 下的单例 `#sshwsp-drop-caret`，不写 `<style>`、不动宿主样式表。浮动菜单的定位、首项聚焦、Esc / Tab、外点、滚动 / resize / 失焦全部收在 `openMenuAt` 一处，行菜单与本地空白菜单共用它。手势面向**主会话**的输入框（文件树跟随主会话，二者工作区根一致时用相对拼写）；多输入框不承诺精确路由，按上面的退化表回退追加。

## 从系统拖入文件（上传）

宿主「文件」树还有第二种拖拽方向：从系统文件管理器把文件拖进树里，上传到远端。它与「把树行拖进任务」共用同一组 document capture 监听，但进入处理函数后立刻分流：内部拖拽只带自定义 MIME，系统文件只带标准的 `Files` 类型；目标解析、插入助手和高亮都不共享。

### 两种“文件夹”

| 名称 | 指什么 | 本功能的行为 |
| --- | --- | --- |
| **目标文件夹** | 树里的目录行，是**投放目的地** | 拖文件到它上面就传进这个目录；展开或折叠都一样 |
| **拖进来的文件夹** | 系统文件管理器里被拖动的目录（`webkitGetAsEntry().isDirectory`） | v1 **拒绝**，不递归、不入队；有文件同时拖入时文件照常上传，文件夹合并成一条提示 |

把“拒绝文件夹”理解成“拒绝落在目录行上”是错的：前者是**拖入内容**，后者是**投放目的地**。两处判定分别在两个函数里，互不复用。

### 落点 → 目标目录

宿主把展开目录的子列表渲染在**该目录自己的 `li`** 内，因此 `closest` 能直接回答“这个落点归哪个目录”。实现只用 `closest`，不拼 CSS 路径，也不读展开状态：

| 落点 | 目标目录 |
| --- | --- |
| 目录行（折叠或展开） | 该行路径自身 |
| 展开目录内部的空白 / 子行之间的空隙 | 由 DOM 归属到**那个目录**，不是树根 |
| 展开目录里的子目录行 | 子目录自身 |
| 展开目录里的子文件行、不可点的 `other` 行 | 它的父目录（与行菜单上传一致） |
| 树体空白（没有任何行祖先） | 树的 `data-files-root` |
| 树的路径标签 / 头部按钮 | 树根（头部没有行祖先，但仍在树内，不交给宿主附件） |
| 树外（输入框、消息区、对话框） | 不拦截；宿主附件行为保持不变 |
| root 缺失或为空 | 不拦截 |
| 本地工作区的树 | 明确拒绝并提示；**不交给宿主**变成 composer 附件 |

实现只读 `data-files-entry` 的**值**（目录是 `"directory"`，不是 `"dir"`），不读 `aria-expanded`，也不寻找不存在的 `data-files-expanded`；不按展开状态分派，**不自动展开**目录：展开是宿主 store 的事，drop 时去点它会令行位移、子行突然出现。行命中只靠 `closest`，不拼接路径选择器（空格、引号、反斜杠都会炸）。

高亮取**行按钮**而不是整个 `li`：展开的 `li` 包含整棵子树，outline 会套住一片无关内容；树体高亮取 `[data-files-body]`。单例标记是 `data-sshwsp-osdrop`，清理走文档级属性查询，因此 HMR 替换实例后旧轮廓也能被清掉。行按钮用 `outline-offset: -2px`，树体用 `2px`；只设内联样式，不写 `<style>`、不动宿主样式表。

### 识别、拒绝与入队

- 系统文件拖拽用 `dataTransfer.types` 里的 `Files` 识别（大小写不敏感）；内部“树行 → 输入框”的拖拽只写 `application/x-dsh-ssh-workspace-file`，`types` 不含 `Files`，所以不会进入 OS 分支。`dragover` 阶段不读 `dataTransfer.files`（可能为空），`drop` 才读。
- `drop` 按宿主的同一套索引配对拆出文件夹：只取 `kind === 'file'` 的 `items`，逐个与 `files` 对齐，`webkitGetAsEntry().isDirectory` 为真即文件夹。没有 entry API、API 抛错或读取失败时按文件处理，不崩、不假装识别。
- 文件夹**整体跳过**：不入队、不遍历、不展开树；名字只列前三个，后面用省略号。文件夹与文件混合时，文件照常入队，文件夹的说明**搭在那一条批次提示的结果句上**（后接「· 已跳过文件夹：…」），不再另开一条——同一时刻只有一个 toast，两条会互相替换，先出现的那句就先消失。只拖文件夹时没有批次可搭，拒绝句就是全部结果，仍然单独出现（错误码 `SSHWSP-E-OSDROP-FOLDER`）。
- 上传不另写队列：文件交给 `queueTreeUploads`，与行菜单的 picker 共用同一个 `enqueueUploads` 与同一句超限提示（`SSHWSP-E-TRANSFER-SIZE`）；刷新也由队列完成后的 `nudgeFilesPanel` 负责，不新增第二个刷新器。只拖文件夹时队列为空，此时没有任何上传 toast 与之竞争，拒绝提示照旧单独出现。
- 本地工作区的树没有远端可写对象，整批拒绝（`SSHWSP-E-OSDROP-LOCAL`），且**不把文件交给宿主附件**；只有树外才保持宿主的“拖到此处添加”行为。

### 与宿主附件、内部拖拽的分界

- 监听挂在 **document capture** 阶段。落点在树内且能解析出目标时，OS 分支 `preventDefault + stopPropagation`，宿主附件包的 bubble `drop` 收不到这次投放；落点在树外时**不调用**这两个方法，宿主照旧把文件收成 composer 附件。
- 内部拖拽载荷没有 `Files`，OS 分支不触发；反过来 OS 分支也**不调用** `addPathsToTask`。进入一次系统文件拖拽的 `dragenter` 会清空可能残留的内部 payload，避免旧手势被 composer 分支认领；`dragleave` 在真正离开树时清除高亮，`dragend` 同时清掉高亮与内部状态。
- 树头 / 路径标签 / 刷新按钮落在树内但没有行祖先，按树根处理；这与树体空白一致，且不会触发宿主附件。

### 退化矩阵

| 条件 | 行为 |
| --- | --- |
| 树外、root 缺失/空 | 不拦截；宿主附件照常接管 |
| 本地工作区树 | 拦截 + 本地拒绝提示；无附件、无队列 |
| 只拖文件夹 | 拦截 + 一条文件夹拒绝提示；队列为空 |
| 文件夹 + 文件 | 文件入队一次；跳过说明写进同一条批次提示的结果句，不另开 toast |
| 文件超过队列上限 | 只有超限项被拒，提示复用行菜单的超限文案 |
| `dataTransfer.files` 为空 | 静默返回 |
| 无 entry API / entry 抛错 | 都当文件上传，不崩溃 |
| HMR 两套监听 | 一次事件只被一个实例消费；高亮按文档属性清理，不叠两圈 |

## 文件面板与文档预览

「工作区文件」侧边栏与文档预览无需插件改动——它们经 `ctx.fs` 读取，远程工作区下自然由 SFTP 提供（列目录、读文本、写回均同本地工具一致），大文件预览按块流式读取。

插件往这个面板加了**一个**控件：`sidebar.right.tab.files.actions` 插槽里的托盘箭头图标入口，**只在面板显示 `ssh://` 远程工作区时渲染**——本地目录沿用宿主自己的头部，底面没有 alias 可携带，队列属于远端。它读槽位给的 `absolutePath`（面板正在显示的目录），把 alias 与远端路径写在自身属性上，供文档级的空白处右键菜单定位当前目录；点击弹出进度浮层。图标空闲时是深色的裸箭头，有排队或运行中的项时整枚变蓝并套上聚合进度环（进度按字节加权，数量放在无障碍名称里）。**上传按钮已从头部移除**：上传只由行菜单的「上传文件到此目录」提供，「浏览目录」只浏览与挂载；同一个窄条里再放一个按钮会把最该随手可点的进度入口挤掉。目录不能作为一个文件下载，因此头部**没有**下载按钮——下载在行菜单里，那里目标明确。

本地目录下列表没有可上传的对端，所以行菜单也不给上传；头部也**不渲染**「传输」——本地目录沿用宿主自己的头部（队列是远端控件，底面没有 alias 可携带）。此时若仍有远端传输在跑，改由完成提示继续报告，而不是在一个与远端无关的头部放一个半真的入口。宿主版本没有声明这个槽位时该控件同样隐藏，并在面板的诊断区给出一句可读原因（不是静默消失）。在远程列表里入口**常驻**：不随队列清空而消失——一个会自己消失的入口，用户分不清是「没有传输」还是「控件坏了」，空闲时只是不亮、不戴环。

### 传输队列与进度浮层

队列是浏览器侧传输的**唯一状态**，文件面板从它读，没有第二份计数。

- 入口与定位：文件面板头部的托盘箭头图标，**进行中（排队或运行）时变蓝并戴环**（环聚合整个队列：`transferQueueProgress` 按字节加权，任一无总量的运行项让弧线旋转，仅排队时是空环），**仅在远程目录列表里出现**（本地目录不注入；此时在跑的远端传输仍由完成提示与文件面板的行内状态继续报告）；浮层 `position: fixed` 锚定按钮（按视口坐标计算），窗口 resize / 滚动时重算，面板折叠到找不到按钮时回到默认位置。
- 尺寸与滚动：宽 **400**（窄视口下不超过视口宽度减 16）、最大高 320，内部列表滚动；不因一条长文件名把面板撑出屏幕。
- 绘制顺序：排队 / 运行中的项在上、按到达顺序；已结算（完成 / 失败 / 取消）的项在下且**最新在前**。store 仍按到达顺序调度（`queueDrain` 依赖它），只有列表的绘制顺序变了——此前始终按到达顺序追加，下载几次之后最新一行落在 320px 可视区之外，打开浮层看到的是最老的行，容易被读成「这次下载没有记录」。
- 每行：方向**图标**（`UploadIcon` 托盘上箭头 / `DownloadIcon` 托盘下箭头，运行中变蓝）+ 名称（按码点截断，`title` 给全名）+ 百分比或字节 + 取消按钮。下载在跑时方向图标外面套一圈：灰色轨道 + 蓝色弧线（`TransferProgressIcon`）——已知总量按比例填充，未知总量（目录归档）转一段固定 30% 的弧，**排队中只有空环、不转**。同一个环也出现在文件面板头部；行内下载入口在下载期间禁用，避免同一路径被排两次。
- 图标而非字符的取舍：`↓` / `↑` 是字体字形，字重随宿主主题漂移，也画不进同一个环；因此下载、上传与菜单图标改为 svg 线条。下载与上传共用 `TRAY_ARROW_PATHS` 的一组托盘箭头（见 `lib/client.js` 的 `DownloadIcon` / `UploadIcon` / `TransferProgressIcon`），行内按钮与菜单的传输项用同一组路径。菜单里其余动作各用独立图形：添加到任务（对话气泡 + 号）、复制路径（双页）、重命名（铅笔）、删除（垃圾桶），不再按文件 / 文件夹类型套图标。**只有知道总量才画百分比**（单文件下载的 `content-length`、上传的本地文件大小）；目录归档没有总量，只报已传字节，不画 0% 也不画假的进度。失败行直接列出原因，不折叠。
- 速度与进度条：名称下一条浅蓝色进度条（`aria-hidden`，数字仍由文本给出）——已知总量按百分比填充，已完成填满，目录归档没有总量时用横向扫描动画，**不画 0% 或 100% 冒充**；失败 / 取消的填充转灰，表示字节停在哪里而不是方向。运行中的行同时显示速度（`45% · 1.2 MB/s · 23.4 MB`）；速率由队列状态机按动作时钟采样并平滑，**两次采样不足 250 ms 不更新**、**停顿超过 5 s 归零重测**（不把停顿平均成一个很慢的速度），结束时不再显示速度。
- 底部：常驻「刷新或关闭页面会中断传输」（刷新不会在后台继续），以及「清除已完成」——只在有终态项时可用；进行中的项不会被清除。
- 空态：远程目录列表里，队列为空时入口照常渲染，浮层显示「暂无传输」；浮层开着而队列被清空也保持打开，不再自动关闭——入口常驻之后，空队列是一个可查看的状态，而不是「面板该消失了」。
- 关闭：点击浮层外部、`Esc`、右上角 `×` 都会关闭；与对话框共用 `useDialogA11y`（焦点进入、Tab 限制、关闭后焦点回到按钮），遮罩透明但覆盖整屏，按「按下与松开会都落在遮罩」判定。
- 目录浏览对话框不再内联任何传输行：它只浏览与挂载，队列的进度留在文件面板头部这个入口里，避免同一份 store 有两套展示。
- 完成提醒：同一批传输只用一个 toast 节点，在途时写「传输队列：N 项…」，结束时**就地改写**成合并结果（「N 项完成，M 项失败」）；不会每个文件弹一条，因为互相重置计时器会把最该读到的结果挤掉。失败结果带诊断码（`SSHWSP-E-TRANSFER-UPLOAD` / `-DOWNLOAD` / `-BATCH`）与逐项原始错误，可展开详情 / 复制整段诊断；整批不提供「重试」——逐项重试属于队列行，避免 toast 与队列出现两个入口。批量里只要有一项走的是浏览器自己的保存流程（没有 File System Access API），结果就说「已开始」而不是「已传输」——页面没有看见保存，就不能声称保存。

已知差异：远端的变更监视**优先走 `inotifywait` 推送**（远端装了该工具时即时上报，不受元数据精度限制）；没有该工具时回退到**轮询式**快照比对——基础约 2 秒一次，空闲目录自适应退避到 5–10 秒、变更后立即回到 2 秒，文件树 / 预览会自动刷新。轮询路径下 SFTP 元数据无亚秒时间戳，同一秒内等长的连续改写可能不触发刷新（增、删、改名总能感知），此时重新打开或重新读取即可看到最新内容。

## 右侧「文件」树的多选

多选做在**宿主自己的「文件」标签页里**，不需要打开任何插件标签页或对话框。那棵树的 store 没有选择模型（既没有 `selected`，也没有修饰键处理），插件也不拥有它的行节点，所以插件不改它的 JSX，只做四件事：

1. 给行加 `.sshwsp-tree-row-selected` / `.sshwsp-tree-row-cursor` 两个**自有类**——不碰宿主类名，宿主改样式不会让高亮消失；
2. 给行写 `aria-selected`，给行内按钮写 roving `tabindex`；容器写 `aria-multiselectable`；
3. 用 document 捕获监听读取 `data-files-entry` / `data-files-path`，把手势喂给**同一个** `selectReduce`；
4. 宿主重渲染后由 `MutationObserver` 重新同步；宿主移除行或换根时，选择按「只能声明看得见的行」修剪；宿主把非活动标签的 body 整个卸载时，选择还要**跨重挂载**存活（见下）。

**关键在冲突**：普通单击目录照常交给宿主展开；Ctrl/Shift 命中目录时 `selectReduce` 返回 `navigate: null`，桥就据此刻在捕获阶段吞掉这次点击。于是「选择优先、导航让路」只有一处判定，不在两个 handler 里各写一遍。

**普通单击文件仍要打开它**。多选是叠加在原习惯上的，不是替换：单击文件返回 `navigate: index`，既选中该行（成为后续 Shift 的 anchor），也把这次点击放行给宿主去打开预览。只有带修饰键的单击才吃掉导航——否则「看一个文件」会从一次点击变成两次。

**选择要跨标签页重挂载存活**。打开文件会切到预览标签，宿主随即把 Files 标签的 body **整个卸载**（`keepMounted` 是 opt-in，Files 类型没有声明），`[data-files-body]` 容器换成一个新的——如果选择只挂在容器上，用户「打开一个文件再回来按 Shift」就只剩单行。所以选择按「会话 + 工作区根」记进 `treeSelectionScopes`，且**锚点存路径而不是下标**：新容器挂载时先恢复 ids 与 anchorPath，根列表晚一帧到达也能在下一次同步里把锚点解析回来。切根时旧根与新根的记忆都清掉；空列表（还在加载）不按「看不见的行」修剪，否则恢复出来的选择会在加载完成的瞬间被清空。

| 手势 | 结果 |
| --- | --- |
| 单击目录 | 宿主照常展开 / 进入；选择清空、anchor 重置 |
| 单击文件 | **既选中它，也照常打开**（导航放行） |
| Ctrl/Cmd+单击 | 切换该行；**命中目录只选中、不进入**（这一次点击被吞掉） |
| Shift+单击 | 从 anchor 到该行的连续区间；**命中目录只选中、不进入**；anchor **不**更新 |
| Ctrl/Cmd+Shift+单击 | 把该区间追加进现有选择 |
| 右键（选择之外） | 选择**收拢到该行**再出菜单；不打开、不导航 |
| 右键（选择之内） | 保留整批选择再出菜单；菜单文案不变，**目标**是整批 |
| Ctrl/Cmd+右键 | 切换该行后出菜单 |
| Shift+右键 | 从 anchor 扩区间后出菜单 |
| 单击空白 / Esc | 清空选择（Esc 保留键盘光标） |
| Ctrl/Cmd+A | 全选（含目录） |
| ↑/↓、Home/End | 移动光标并选中；Shift 扩展区间；Ctrl+↑/↓ 只移光标 |
| Enter | 打开光标所在目录 / 文件 |
| F2 / Delete | 重命名 / 删除光标所在行（与行菜单同一组动作） |

- **右键先归位，再弹菜单**：`point` 动作在 `openTaskMenu` **之前**执行（守卫 `if (container !== null)`），所以菜单渲染时读到的已经是这次右键该有的选择——菜单不该读到上一次点击留下的集合。
- **锚点属于工作区，不属于这一次 DOM**：打开文件、切去预览标签再切回 Files，容器已被宿主重建，但 Shift 仍从原锚点扩区间；锚点是路径，根列表重新异步加载也不影响。
- **视觉**：选中行背景高亮，光标行描边；**任何行都不渲染复选框，也没有“选择模式”开关**，树的下方**不浮出批量条**。
- **一个动作只有一个文案**：菜单里删除永远是「删除」、下载永远是「下载到本机」，**不随选择数变化**，也**不带数字**。以前这里有两套：只作用于右键那一行的删除，和作用于选择的「下载所选（N 项）」。两套文案就是两条代码路径，数字还算自**另一个**数组——菜单能承诺三行、却只删掉一行。现在两者都只有一个动词。
- **目标是算出来的，不是猜出来的**：`resolveTargets(clickedRow, selection)` 是唯一判决点——选中集包含该行且不止一项时，目标是整批；否则**先把选择收敛为该行**再返回。收敛发生在菜单弹出**之前**，所以「屏幕上高亮的那几行」永远是「接下来会被操作的那几行」。
- **数量搬到确认框与目标对话框**：菜单不说数字，破坏性动作在动手前说清楚。删除确认框按目标数换标题（一个文件 / 一个目录及其下 N 项 / 空目录 / N 项），正文给出目录与文件的**分项计数**（选中目录会递归数到 `DELETE_COUNT_LIMIT = 200` 项为止，触顶标 `200+`；本地目录不冒充远端、标「未知」；列目录失败仍允许确认，只是没有数字）。**确认框先出现、数字后到**：数一棵目录要一串 `/ls` 往返（真机上 27 个目录的一棵树要四十多秒），等数完再弹框就是一个看起来死掉的按钮。所以标题先用**选择本身**能回答的话（一个文件 / N 项）开框，单目录先开成「删除该目录及其下的全部内容？」，正文那一行写「正在统计目录内容…」，数完就地把同一批节点改写成分项计数，单目录的标题再精确成「…及其下 N 个文件？」——只开一个框，从不再开第二个。下载没有破坏性确认，因此数量写在两处：目标目录对话框副标题「将下载 N 项到本机」，以及入队后提示「已加入队列 N 项」。
- **批量下载只问一次位置**：目标超过一项时先确认并选**一个目标目录**，再整批入队。取目录按可用性回落，四种结局各有去向：

  | `pickDirTarget` 结局 | 怎么来的 | 队列怎么落盘 |
  | --- | --- | --- |
  | `handle` | 浏览器 `showDirectoryPicker()` 给了可写目录句柄 | 客户端流式写入该句柄 |
  | `path` | 选到了路径：桌面壳优先走 preload 桥 `__DSH_DIRECTORY_PICKER__.pick()`，页面选择器缺席或被拒时才问 `uiWorkspace.pickDirectory()` | `POST /transfer` 的 `recursive` 下载，服务端直接写到该路径 |
  | `canceled` | 用户关掉选择器（异常文案匹配 `/cancel\|abort\|dismiss/iu`） | 整批取消，**不**退化成逐个弹窗；并发一条中性提示（见下） |
  | `unsupported` | 两种选择器都没有 | 逐项回落到单文件保存对话框（旧行为） |

  `showDirectoryPicker` 存在但**被拒绝**（非 `AbortError`，如跨域 iframe 的权限策略）时也回落到宿主选择器，而不是当作取消。
- **先问桌面壳，再问页面**：`window.showDirectoryPicker()` 是 Chromium 的接口，在 Electron 壳里窗口刚打开时，第一次调用出现过「对话框已弹出、文件夹已选中、仍回 `AbortError`」——这一条 abort 被当成取消，整批静默返回，正是本轮修掉的真实故障。顺序因此是：桌面壳 preload 桥 → 页面 `showDirectoryPicker()` → `uiWorkspace.pickDirectory()`。桥拒绝（非取消）不算取消，继续往下试。
- **取消不再静默**：批量入口走到 `canceled` 时发一条**中性** toast（第三态 `muted`：不染成功绿、不染失败红、`role="status"`、不抢焦点、仍 7 秒消失），文案 `transfer.pickCanceled`。此前这是整条路径上唯一「什么都不发生」的分支，看起来像按钮坏了。错误态则按「顶部提示（toast）」表：带诊断码与原始错误、可展开 / 复制，只有可安全重放的动作才出现「重试」。
- **取消是真的取消**：`localDir` 那条路要等整个目录写完才返回，所以取消是**轮询**（150ms）`ctx.isCancelled()` 后 `controller.abort()`，中止请求即让服务端停止遍历；`finally` 里清掉定时器。等服务返回再检查等于「点了取消也拦不住」。
- **降级**：宿主换了行属性名（`data-files-entry` / `data-files-path`）时，桥找不到可选中行，表现为「点击没有选中效果」，不会报错、不会破坏宿主。

## 行菜单、重命名与删除

行菜单（宿主文件树使用自己的 DOM 菜单组件）收窄为 **220px**、单行布局、**去描述行**、行高最小 24px、内边距 3px 6px、标题字号 12px、图标 16px、**最多 8 项**、**最多三组分隔线**（「下载到本机」、远端目录的「新建文件夹」与「重命名 / 删除」各占一组）、圆角 8px。少掉的第二行原本放完整路径与「同名覆盖」说明：行本身已经写着文件名，那段文字在重复行而不是解释动作；覆盖策略改由 `title` 提示。**图标随动作区分**：添加到任务、复制路径、新建文件夹、重命名、删除各用独立线条图形，下载 / 上传仍共用托盘箭头；图标列不再把四个动作都画成一个文件 / 文件夹，动作不必先读标题才能分辨。**「新建工作区」选择菜单是唯一保留两行的菜单**（描述正是它存在的理由），宽度 250px、标题保持 13px，通过 `.sshwsp-flowmenu-roomy` 修饰；紧凑规则用 `:not(.sshwsp-flowmenu-roomy)` 限定，不会跟着缩小。

行菜单里的「重命名」「删除」对远端行与本地行都出现，走同一组 `POST /rename` 与 `POST /delete`。**「新建文件夹」只对远端目录出现**，与它们同一组，走 `POST /mkdir`，请求父目录路径 + 名称：名称必须是单个路径段，目标已存在答复 409，越界 / 只读 / 停用均在写盘前拒绝；成功后重新列目录并选中新行。本地目录行没有这一项——本地新建的唯一入口是空白处菜单，两条入口不重复。路由本身有本地分支（`path` 的拼写决定分支，边界只取自会话的工作区根，客户端的 `root` 只用于识别会话，且 `realpath` 父目录防符号链接逃逸），由空白处菜单驱动。菜单本身支持方向键 / Home / End / Enter / Escape，新项不额外做鼠标专用入口。

- **重命名在行上做**（参考 Better Sidebar）：F2 或行菜单「重命名」把文件名**原位**变成输入框，不弹模态框。输入框 portal 到 `document.body`（`.sshwsp-inline-rename`，`position: fixed`，z-index 1400），按名字 span 的 `getBoundingClientRect()` 定位；名字 span 取 `button` 内**最后一个有文字的 `<span>`**，不依赖宿主 class。
  - 提交语义三态由 `inlineRenameDecision(original, typed)` 判定：trim 后为空或等于原名 → `cancel`（不发请求）；`localNameRefusal` 拒绝（含 `/` `\`、`.`、`..`）→ `refuse`；否则 → `commit`。
  - Enter 提交；**被拒绝时输入框保持打开**并设 `aria-invalid="true"`（边框转红），而不是关掉让人重来一遍；Escape 取消；失焦且内容有改动时提交。
  - `settled` 标志保证一次编辑只提交一次（Enter 后紧跟 blur 不会发两个请求）。失败走 `notifyUser(toastError(describeRenameFailure(err), err, 'SSHWSP-E-RENAME'))`：带原始错误，可展开详情 / 复制，**不提供重试**（改名可能已经部分完成，重放不是幂等）；成功后 `refreshFilesPanel()` 并提示。
  - 只改名不换目录；目标已存在直接拒绝（提示「目标已存在」）；不内联改写宿主树的行——改完仍由刷新重读。
  - 分发器是 `requestRowRename`：`if (row instanceof Element && document.contains(row))` 才走行内，否则回落到原来的模态框（行已被宿主重渲染掉时的兜底）。
- **删除**：确认浮层写明数量、前几个名称与「不可恢复」，目录注明含子目录；确认后逐项执行，单项失败不隐藏其余结果；汇总「已删除 N 项 / M 项失败」。Delete 键与 F2 触发同一动作。
- **只读与无法定界时直接禁用**：菜单打开时向 `GET /mutation-policy` 询问该行的会话模式；`read-only` 下两项置灰并提示「只读会话」，本地路径若服务端识别不出所属会话工作区也置灰（不是点了再拒绝）。`Delete` / `F2` 走同一判定。
- **不乐观更新**：接口返回前不改列表；失败保持原样并给出原因。
- **刷新**：改完由我们发出 `refreshFilesPanel()`；宿主文件树**不自动刷新时**，插件只点它公开的 `[data-files-reload]` 控件（不是私有 API）来重读，不向宿主 DOM 注入节点。目录浏览对话框自己重读当前目录，是可信的回退。
