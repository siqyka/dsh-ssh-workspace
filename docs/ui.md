# 界面指南

> 定位：插件在 DSH 界面中的全部出入口与交互。

## 「远程工作区」面板

侧边栏面板，注册在 `sidebar.panellist` 插槽，入口图标为服务器图标（`ServerIcon`），标题「远程工作区」。

### 四个 tab

面板是一页，按功能分成四个 tab：**主机 / 工作区 / 审计 / 设置**。此前九个分区排在一条长滚动里，「端口转发表单在哪」取决于记不记得往下滚多远——tab 解决的是这件事，而不是把内容分类得更细。第一版分了五个（转发与会话、诊断各占一个），结果是 tab 行很宽、每个 tab 里只有一节内容；后来「转发与会话」「文件引用」「诊断」合成一个「设置」页，它们是「这套工作区的其余部分」，而不是用户会专门去逛的地方。审计不一样：它是一张按时间倒序的日志表，不是某个设置的开关，所以单独占第四个 tab，设置页里不再有它的入口。

| tab | 包含的分区（按页面上的顺序） |
| --- | --- |
| 主机 | 主机卡片（存储与 `~/.ssh/config` 回退、电源开关、测试 / 断开 / 立即重连 / 忘记密钥 / 浏览目录 / 编辑 / 删除） |
| 工作区 | 「已挂载」（含新建 / 添加工作区入口）与「已停用」 |
| 审计 | 命令审计表（时间 / 主机 / 通道 / 状态 / 命令 / 错误，按时间倒序）、工作区筛选、保留条数（1–2000，默认 200）与刷新；数据来自独立 `GET /audit`，不在 `/status` 轮询里 |
| 设置 | 端口转发表单与已存映射 → 持久远端会话（有会话时才出现）→ 文件引用与本机路径直通（scheme、远端缺失回退）→ 文件查看（列出文件 / 会话窗查看）→ 环境自检（默认关闭）→ 最近的远端命令（只列失败与拒绝）→ 诊断报告与 findings / notes |

行为约束，都写在 `tests/client-shape-smoke.mjs` 的「面板 tab」一组里：

- **只有选中的 pane 渲染**。不是四个都挂上再 `display: none`——那样所有分区的 effect 会同时跑，刷新与轮询也一起跑。
- **选中项存在模块级**（`panelTabChoice`）。宿主在用户回到会话时会卸载整个面板，组件内的 state 会在每次重进时退回第一个 tab；这是参照对象把 tab 放进模块 store 的同一个理由。
- **键盘是 APG 的 tablist**：`role=tablist` / `tab` / `tabpanel`、`aria-selected`、`aria-controls`、roving `tabIndex`，方向键左右环绕、Home/End 到两端，**焦点跟着选中走**；切 tab 时把新 pane 滚回顶部（否则从长分区切到另一个会长在中间）。
- **行内滚动而不是换行**：tab 多一个就换一行会让下划线跳位，面板标签也没有长到需要两行。

### 居中列

面板正文放在一个限宽的居中列里（`.sshwsp-panel-inner`：`box-sizing: border-box`、`width: 100%`、`max-width: 980px`、`margin: 0 auto`、`padding: 72px 24px 40px`）。980px 与参照的整页对齐——720px 时主机卡片读起来像一张窄表单，按钮全被挤到右边缘；72px 的上边距让标题明显离开滚动区顶边。面板贴边铺满时读起来像一页设置项；参照对象的整页也是这个形状——限宽 + 两侧留白，停靠变宽时多出来的宽度均分到两边，而不是把每一行都拉长。

居中**只能**靠 `margin: 0 auto`，不能写成 `padding: 0 calc(50% - 360px)`：百分比内边距按**包含块**（整页宽）计算，而不是按被 `max-width` 限制后的 720px，于是在 1400px 的页面上每侧算出 340px，720px 的列只剩 40px 内容——整个面板会变成一条竖排文字。`padding` 只负责窄页面的保底边距，`client-shape-smoke` 有一条断言禁止这个形状。

主机卡片逐条展示存储与 `~/.ssh/config` 回退的全部主机，字段为别名、`user@host:port`，以及一行元信息：**「密钥就绪 / 未就绪」的胶囊在最前**，其后依次是认证方式与来源（store / ssh-config）。就绪放最前是因为它是这张卡片上唯一能让连接直接失败的事实（key 认证且 `keyPath` 在本机不存在时显示「未就绪」并用警示色），认证方式与来源只是背景。每张卡片提供：

- **测试连接**：调用 `POST /api/dsh-ssh-workspace/test` 实连一次，**然后释放这条连接**——「测试」回答的是「这台主机是否可达」，不是「替我连上」。结果以页面顶部 toast 呈现（成功附往返毫秒数），**统一 7 s 后自动消失**（成功 / 失败 / 中性同一窗口），点击或 Esc 可提前关闭；指针悬停暂停、移开重计满。错误提示可就地展开诊断码与原始错误、复制整段诊断，并在该动作可安全重放时提供「重试」——规则见「顶部提示（toast）」。连接指示点因此不会被一次探测点亮：刷新读的是实际剩下的连接，而不是假定测试留下了一条。
- **开机自动连接**：每张卡片一个勾选框，**只标记存储的意图，不操作连接**。勾选 / 取消都调用 `POST /api/dsh-ssh-workspace/hosts/intent`，服务端只写 `dsh-ssh.json` 顶层的 `autoConnect` 数组：勾上不会立刻拨号，取消也不会断开当前会话（断开会用「断开」、立刻重连用「立即重连」）。勾选态只读意图、不读 socket——一台连着但从未勾过的主机显示**未勾选**，而勾过但当前没连的主机仍显示勾选（状态行自己写「已断开 / 连接中…」）。toast 明确写「当前连接未改动」。写盘失败时勾选态回到服务端的真实值，错误进 toast。别名不存在（既不在存储里、也没有对应的 `Host` 块）时路由回 404——一个没人定义的别名会在每次启动被拨一次并失败，只在诊断里留痕。
- **断开**：仅在该主机的连接状态为 `connected` 时显示（连接状态指示绿点内联在主机名之后；`broken` 与后台重连中**不出现**「断开」——同一行已经写着「已断开 / 重连中（第 N 次）」，再给一个「断开」是在提供一个不存在的状态，这两种状态改由「立即重连」承担）。点击调用 `POST /api/dsh-ssh-workspace/hosts/disconnect` 关闭该主机的池化连接，**并连带拆除该主机上的全部端口转发**（响应里的 `closedForwards` 报告拆了几条，toast 据此改写为「已断开连接，同时关闭 N 条端口转发」）。拆除的结果与在端口转发行上点「断开」**完全一致**：映射保留、意图置为断开、不记任何失败原因——主动断开不是故障，面板不该对它亮红字或提示「下次启动会自动开启」。连接上有操作进行中（进行中数量大于 0）时按钮禁用并给出提示。断开无需确认——下一次操作会按需重连。
- **立即重连**：仅在该主机处于后台重连状态时出现（等待中或已停止）。等待中的下一次尝试可能还有几十秒，`POST /api/dsh-ssh-workspace/hosts/reconnect` 跳过退避立刻试一次；成功显示「已恢复连接」，失败把真实错误放进 toast。主机卡片上的状态文字是「重连中（第 N 次，M 秒后）」/「重连中（第 N 次）」/「重连已停止」，并用黄点与「已连接」的绿点区分——重连中既不是连接正常，也不是刚刚断开。只要列表里还有在重连的主机，面板每 5 秒自动刷新一次，否则倒计时会停在原地（刷新只在浏览器可见时进行，无重连任务时完全停止）。
- **忘记主机密钥**：调用 `POST /api/dsh-ssh-workspace/hosts/forget-key` 清掉该别名的 TOFU 主机密钥记录（需就地确认），用于主机确实重装系统或更换密钥之后——见 [hosts.md](./hosts.md) 的「主机密钥校验」。
- **浏览目录**：打开该主机的目录浏览器（见下节）。它与「新建远程工作区」里的目录选择是**两个不同的组件**（这里是 `DirectoryBrowser`，那里是 `RemoteWorkspaceDialog`）：两者都只列目录、只为选路径；差别只在挂载入口——「浏览目录」本身就能挂载，而从主机卡片点进来，多半就是为了挂载。
- **编辑 / 删除**：编辑打开主机表单；删除为就地确认，删除只影响存储条目，不会自动卸载已挂载的工作区。两项**只属于纯存储主机**：`source` 为 `ssh-config` 的行（整个主机来自 `~/.ssh/config`）与带 `configAlias` 的存储行（别名同时被 `~/.ssh/config` 的 `Host` 块定义）都不出现这两项——前者这个插件从不改写，后者它只拥有一半：删掉存储条目只会露出那个 `Host` 块（主机「自己回来了」），改它则会让本机其它 ssh 客户端解析到的东西悄悄变样。带 `configAlias` 的卡片因此多打印一行 `hosts.configShadow`，直接说明去 `~/.ssh/config` 里改；服务端也做同样的拒绝（删除 / 保存均 409，只有改名到空闲别名放行）。

表单要点：密码与密钥口令**从不回传浏览器**，编辑时留空表示保留原值（见 [hosts.md](./hosts.md) 的「认证与凭据」）；切换认证方式时必须重新填写新凭据。底栏是**取消 / 测试 / 保存**：中间的「测试」把**还没保存的表单**（`POST /test` 的 `form` 分支）交给服务端真拨一次，成功后立刻断开，所以它回答的是「屏幕上这台主机现在连得上吗」，而不是「已保存的那台」——编辑时改了地址也不会测到旧地址；它**什么都不写**：不新增/修改主机记录，也不 pin 主机密钥（主机密钥只与已记录的值比对，TOFU 交给真正的连接）。保存与测试共用同一个 `buildPayload()` 与 `validate()`，两边的拒绝条件因此一致。结果就在表单底部：成功是绿色的「可连通（N ms）」，失败是红色并带服务端原话（`role="status"`，不是错误行）；**任一字段改动后结果立即消失**，旧地址的绿灯不会留在新地址上。

## 添加工作区双入口

插件占用两个 directoryFlow 插槽：侧边栏的 `sidebar.workspaces.directoryFlow` 与会话页的 `conversation.hero.workspace.directoryFlow`，以负优先级（`-100`）遮蔽部署自带的本地选择器——插槽核心渲染优先级**最低**的占用者，负优先级因此胜出，且不卸载内建实现。

触发后弹出锚定菜单（宽约 300px），包含两行：

- **本地**（FolderIcon）：渲染本部署已安装的 browse occupant 组件（`directory-picker-browse` 的 `BrowseDirectoryFlow`，与插件安装前「添加工作区」弹出的是同一个对话框、同一套 locale 与 `listDirectory`/`createDirectory` 调用，经 `ctx.slots.entries(hole)` 取原始条目复用）；部署里没有 browse occupant 时（桌面 preload 桥 / native-only 组合）才回落 `__DSH_DIRECTORY_PICKER__` / `uiWorkspace.pickDirectory()`。
- **远程**（远程标记图标）：打开「新建远程工作区」对话框。

锚定机制：触发按钮不传给插槽占用者，因此插件在捕获阶段监听 `mousedown` 记住最近一次按钮位置（3 秒内有效，避免键盘快捷键打开时菜单"瞬移"），弹出层定位在按钮右侧 8px 处，并钳制在视口内；窗口 resize 时重新定位。点击菜单外部或按 Esc 关闭。

## 浏览目录对话框

点主机卡片的「浏览目录」打开 `DirectoryBrowser`（`lib/client/client.dialogs.js`）。它与「新建远程工作区」里的目录选择**不是同一个组件**（后者是 `RemoteWorkspaceDialog`，只列目录、只为选路径），因此两者能力不同：

- 顶部：返回上级、当前绝对路径；这一条是 `position: sticky` 的，列表再长也不跟着滚走（`.sshwsp-browser` 用 `overflow: clip` 而不是 `hidden`：`hidden` 会让它成为一个从不滚动的滚动容器，sticky 子元素就黏在它身上，看起来完全没生效）；
- 列表：**只有目录行，且目录行就是按钮**（请求带 `dirs=1`，服务端在施加上限**之前**就滤掉文件，所以 `total` 与 `truncated` 数的是选择器真正显示的行）。**左键单击是「选中」**：该行高亮（`.sshwsp-entry-picked` + `aria-current`），并且成为底部「挂载此目录」的目标；**双击**才进入下一级。键盘激活（`Enter` / `Space` 产生的 `detail === 0` 点击）同样只是选中，**再按一次**才进入选中的那一行——两步手势让「挑哪一个」和「进去」分开，键盘用户两条路都有。选中项随列表刷新一起清掉（换目录、换主机、筛选变化），不会留下一个屏幕上看不见的目标。这里**不提供上传、下载或选择集合**：没有大小列、没有勾选框、批量条或行内传输按钮，选中只有一个（这个选择器只有一个动词）；
- 路径栏**跟随输入**：同一目录内的前缀只在本地收窄（大小写不敏感，零往返）；键入带尾斜杠的路径在停顿 200 ms 后只发一次列目录请求；拼全的目录名只收窄成一行、不自动进入。尾斜杠表示「在目录里」——导航后写成 `/raid/`，删掉斜杠即回到父目录并按 `raid` 过滤。输入框**没有 `onBlur` 复位**：双击的第一下会先 blur，复位会让行在两次点击之间移位；
- 底部：「挂载此目录」——按**选中的行**（没有选中时按当前路径）创建远程工作区，成功后附**能力提示**（`capabilityNotes`：`rg` / `git` / `inotifywait` 的缺失项，只报探测出的确定缺失）。因为路径栏显示的永远是**正在浏览**的目录、而按钮可能作用在选中的子目录上，目标另外用一行文字写明（`browser.picked`：`将挂载：<path>`），按钮的 `title` 也是它。

首帧路径为 `null`，首次 `GET /ls`（不带 `path`）返回 SSH 登录目录后回填，所以「挂载此目录」永远指向一个真实绝对路径。加载中 / 空目录 / 无法加载是三种独立状态。

两个对话框共用同一套骨架：**头部与表单固定，目录列表是唯一的滚动容器**。`.sshwsp-dialog-body` 是不滚动的 flex 列（`overflow: hidden`），`.sshwsp-form` 与 `.sshwsp-browser-header` 都是 `flex: 0 0 auto`，剩下的高度全归列表（`flex: 1 1 auto` + `overflow-y: auto`）。

反过来（整个 body 一起滚）也不对：表单会跟着列表滑出视野，用户挑目录时看不见自己填的工作区名。两层滚动条（列表自带 `max-height`）更糟——内层滚到底之后，外层剩下的内容永远到不了。「新建远程工作区」把这两种错都犯过。

布局要靠**高度**而不是只靠上限：`.sshwsp-dialog` 只有 `max-height` 时，内容不够高就撑不到上限，`flex: 1` 分不出空间；`.sshwsp-dialog-fill` 因此给出 `height: min(88vh, 760px)`，并把 `max-height` 一起抬到 `88vh`（否则被基类的 `80vh` 悄悄裁掉）。

窗口很矮时（`max-height: 620px` / `500px`）压缩的是**外壳**而不是列表：间距收紧，`88vh` 变成 `calc(100vh - 12px)`，「双击目录进入」的提示行直接隐藏——380px 高的窗口里，标题栏加表单加提示加底栏会把列表挤到只剩 23px。但「将挂载 / 将创建」那一行**不隐藏**：它是唯一说明按钮会作用在哪个目录上的文字，藏起来等于让用户猜。

弹窗通过 `modalLayer()` **portal 到 `document.body`**，这不是洁癖：侧栏在自己的 `.scrollArea` 上绑了 `passive: false` 的 wheel 监听，会把滚轮改成手动写给侧栏视口，对话框作为它的 DOM 后代永远收不到；`.composerSeat` 的 `will-change: transform` 又会把 `position: fixed` 的包含块从视口改写成自己。宿主对 composer 内的浮层有同样的约定（`ConversationRoot.module.css`）。

这个对话框只负责**浏览与挂载**：上传与下载只从文件树行右键菜单进入，进度留在文件面板头部的队列入口或完成提示里；对话框内不展开队列条，同一份 store 不再有第二个展示面。

### 文件行只是「这里有什么」

面板「设置」→「文件查看」勾上「同时列出目录里的文件」后，两个 picker 的列表里出现文件行：灰色、带文件图标、没有 hover、**不是控件**——它是 `div`，没有 `onClick`、没有 `onDoubleClick`、没有 `tabIndex`、不带 `aria-current`，也不参与「选中的目录」或「双击进入」。理由不是省事：这个列表的每个可点行都会被读成「选它当目标」，文件既不能挂载也不能成为工作区，把它画成按钮就是在教用户做一件做不成的事。它存在的意义只有一条——回答「这个目录里到底有什么」，让用户在点「挂载」之前确认自己挑的是对的目录。

开关关掉（默认）时列表请求带 `dirs=1`，服务端在截断之前滤掉文件；开关打开时不带，走一次往返的全量列目录，排序仍是**目录优先**，`total` / `truncated` 计的是全部条目。文件行与目录行共用同一条渲染分支，只有类型判断把它们分开，所以两种模式下目录行的单击 / 双击 / 键盘语义逐字段相同。

## 顶部提示（toast）

所有面板、文件树与传输反馈共用**同一个** DOM toast 控制器（`notifyUser` / `transferNotice`），同一时刻只有一个节点；新提示替换旧提示时旧计时器一并取消。文案全部走 i18n，中英同键。

| 场景 | 计时与关闭 | 可做的动作 | 焦点 |
| --- | --- | --- | --- |
| 成功 / 中性（`ok` / `muted`） | 7 s；指针悬停暂停、移开重计满；点击、Esc 提前关闭 | 无动作按钮 | 出现不抢焦点，关闭不移动焦点 |
| 错误（`err`） | 同上；`role="alert"` 立即播报 | 「详情」默认收起，`aria-expanded` 翻转，展开诊断码 + 原始错误；「复制」复制整段诊断；「重试」仅在该动作可安全重放时渲染 | 出现不抢焦点；用户 Tab / 点击进入后关闭，焦点回到来源 |
| 不可重放错误 | 同上 | 只有「详情 / 复制」；**不渲染灰色或禁用的「重试」** | 同上 |
| 传输进行中 → 结果 | 在途不计时；结果就地改写同一节点并从结果时刻起算 7 s | 结果失败带诊断码 / 原始错误，可详情 / 复制；整批不提供重试（重试在队列行上） | 同上 |

规则：

- **只有一个节点**：复制、详情、重试、在途→结果的反馈都就地改写同一元素，不新增第二条 toast，也不重置原来的 7 秒窗口；重试成功同样在原节点变成成功态。
- **重试门控**：仅「测试连接、立即重连、断开、启用、自检、打开诊断报告」提供重试；卸载、忘记主机密钥、转发保存 / 切换 / 记住、启动自动开启、重命名 / 删除、传输批次不提供——这些动作可能已经部分落地，重放不是幂等。
- **复制失败不静默**：剪贴板 API 缺失或被拒时，自动展开详情、用 `Range` / `Selection` 选中整段诊断（诊断码 + 原始错误），并在同一节点写「已选中，可按 Ctrl+C 复制」；不另开提示。
- **焦点**：`tabIndex=0` 让提示可键盘到达，但出现时不调用 `focus()`；关闭时仅在 `activeElement` 确实在提示内部时才把焦点还给来源。`muted` 与成功态同样不抢焦点。

## 四个对话框的遮罩关闭（`backdropDismiss`）

`HostEditor`、`DirectoryBrowser`、`ReportDialog`、`RemoteWorkspaceDialog` 四处共用 `backdropDismiss(close)`：判据是**按下与松开都落在遮罩上**，而不是「click 落在遮罩上」。

差别不是学究式的。`click` 的事件目标取**按下点与松开点的最近公共祖先**——在输入框里拖选一段文字、把鼠标拖到对话框外再松开，按下在对话框内、松开在遮罩上，浏览器仍会把 click 派发到遮罩，于是 `onClick: onClose` 会在用户选字的半途把整个流程关掉。按下点才是可靠信号。

四条附带规则，每条都对应一种会回退的行为：

- **只认主键**（`event.button === 0` 才置位）。`click` 从不为副键派发，若不加这道门，「右键按在遮罩上松开」会凭空多出一个关闭动作，而右键本该只弹上下文菜单。**松开侧刻意不设这道门**：touch / pen 的 `pointerup` 在部分引擎里报 `button: -1`，门住它会让触屏点空白再也关不掉。
- **状态写在元素上，且每次 `pointerdown` 无条件覆写**。按下后把鼠标拖出窗口再松手，多数平台根本不派发 `pointerup`；若靠「松手时清理」，残留的「已按下」会漏到下一次手势里，反而在用户从对话框内按下时误关。因为遮罩是祖先节点，来自对话框内部的按下会冒泡到它并把标志覆写为 false。
- **忙碌时关闭被拒**：目录浏览器传输中、创建工作区接纳中都不可用遮罩关闭（各自的门禁写在组件的 `dismissBackdrop` 里），否则会把仍在进行的请求连同它唯一的反馈一起丢掉。
- **对话框本身没有 Escape 关闭**。这三个组件都没绑键盘关闭，遮罩收紧后唯一的出口是各自可见的「取消 / 关闭」按钮与标题栏的 ×。这是现状而非遗漏：加 Escape 必须处理「下拉框或文件选择器正吞这个键」的先后，需要真机浏览器验证，不在 0.2.5 范围内。

文件编辑器**不在这个名单里**：它已经不是对话框了，没有遮罩可点，`Esc` 绑在它自己的 `keydown` 上（见「文件编辑」一节）。`tests/backdrop-dismiss-smoke.mjs` 把这条钉成断言——遮罩总数是 4，且编辑器 chunk 里不许出现 `sshwsp-backdrop`，所以哪天有人把它改回对话框，两处计数会当场打架。

## 新建远程工作区对话框

一次完成"选主机 → 选目录 → 命名 → 挂载"：

1. 拉取主机列表，默认选中第一台；主机列表为空或出错时给出对应空态。
2. 目录浏览：`GET /api/dsh-ssh-workspace/ls?alias=…&path=…&limit=…&dirs=1` 逐级浏览远端目录（只要目录），提供「返回上级」、加载中 / 空目录 / 无法加载三种状态；路径栏与「浏览目录」共用同一套跟随输入的行为（见上节）。**左键单击是选中**（高亮 + `aria-current`），**双击**才进入下一级；键盘第一次激活选中、再按一次进入。创建时用选中的那一行作为 `remotePath`，没有选中时用正在浏览的目录——两者可能不同，所以目标另用一行「将创建：<path>」写明，按钮的 `title` 也是它。
3. **可写探测**：`/ls` 同时回报 `writable`。目录不可写时显示红色警告（"当前 SSH 账号对这个目录没有写入权限……"）并禁止创建——写入能力是 Agent 工作的前提。
4. 创建：`POST /api/dsh-ssh-workspace/mount`，携带 `{alias, remotePath, title, register: true}`。**先注册、后接纳**：挂载路由在宿主接纳该路径之前就按所填名称登记工作区，宿主随后解析到既有记录，避免以派生标题重复建条目。成功后刷新标记数据源，把路径交还吸附链路；对话框在接纳期间保持禁用，背景点击可取消（创建中除外）。

## 远程工作区标记

远程工作区不以文件夹图标示人，而是显示 SSH 标记。DSH 的行图标没有插件插槽，实现为 **DOM 装饰**（`lib/client/client.marks.js` 的 `installRemoteWorkspaceMarks()`；`client.js` 只保留 pass-through 占位），三条原则：

- **React 安全**：从不删除或搬迁 React 拥有的节点——仅通过内联 `style` 隐藏文件夹字形（React 不会重写这些节点的 `style`），在旁插入自带 `data-sshwsp-mark` 的 svg。
- **自愈**：`MutationObserver` 监听 `document.body`，React 重建行节点后自动重新施加替换；工作区不再远程时同样自动还原。
- **身份匹配**：从 live `workspaces` store 的 `getSnapshot()` 取 id / title 集合（服务不可达时退回 `/status` 的 `workspaces` 数组）。侧栏行按工作区 **id** 匹配；选择器菜单行与会话页 hero 工作区按钮只有标题，按 **title** 匹配，hero 在会话刚建立时可能显示路径 basename，故 basename 也计入标题集合。

### 同名工作区：标题只是一半身份

一个标题可以由两个工作区同时使用——本仓库本身就同时是本机检出和一个
`ssh://dev/.../dsh-ssh-workspace` 挂载。只按标题判定时，本地那一行会被换成
远端标记（停用清单同理，会把本地行置灰）。

规则因此拆成两半：**远端集合**由 ssh:// 工作区的 title / basename 构成，
**本地集合**由其余工作区的 title / basename 构成，两边都有的标签**不标识任何一方**：

```js
remoteMarks.titles.has(text) && !remoteMarks.localTitles.has(text)
```

`collectRemoteWorkspaces` 收本地标题（`remoteMarks.localTitles`），
`remoteTitleMatch` / `detachedTitleMatch` 是唯一的判定入口，四处展示
（侧栏行、选择器菜单、hero 按钮、停用置灰）都调用它们，不各写一份。
侧栏行的 **id** 命中仍然直接算远程，所以共享标题不会反过来藏掉真正的远端行。

同一条规则也解释了为什么标题匹配要等一次**完整**的收集：`/status` 只回报远程工作区，
按它判「没有本地同名」必然误判，所以 `titlesSettled` 只在读过 DSH 自己的 store 之后
才置真，此前一律不按标题标记；服务不可达时那次回退只做 id 匹配。id 匹配不受这条限制
——停用清单照旧先按路径与 id 生效。

装饰同时覆盖三处展示：侧栏工作区行、侧栏选择器菜单行、会话页 hero 工作区按钮。

### 停用工作区的置灰

已停用（`detach` 过）的工作区，侧栏那一行会被打上 `data-sshwsp-disabled="1"`，
由 CSS 降到 50% 不透明度并在行尾加一枚**电源图形**（用 `::after` 的 SVG mask 画，
不用 `⏻` 字符：U+23FB 在随包 UI 字体里缺字形，只会渲染成一个空豆腐块）：

```css
[data-sshwsp-disabled="1"] { opacity: 0.5; }
```

**这一行不挡点击**。置灰只是状态提示：点开会话、展开分组、行内按钮全部照常，
真到用不了的地方由宿主那一层自己报错（远端读写与命令执行会拒绝，并说明「已停用，
先启用」）。这里曾经反着做过——`pointer-events: none` 挡鼠标、脚本再补
`inert` + `tabindex="-1"` 挡键盘——结果是侧栏把点击吞掉：用户只看到灰，点下去没有
反应，也不知道原因、不知道去哪儿启用。状态该被看见，动作不该被静默没收。

它下面的会话行按同一规则置灰，不另外拦截。会话行是 `session:<id>`，
**不携带任何工作区信息**，所以成员关系由 `/status` 的 `workspaces[].sessionIds` 下发。

真正的恢复入口是面板里的「启用」按钮。

**置灰的回收靠重新读取，而不是重新绘制**。装饰由一次扫描写入，而扫描只在 DOM 变化或
调用方递来新数据时触发——两者都来自这个窗口里的用户操作。这里曾经有个很安静的坑：
`client.panel.js` / `client.add-workspace.js` 解构出来的 `syncRemoteWorkspaceMarks` /
`refreshRemoteWorkspaceMarks` 是模块求值时发布的**占位函数**（真实现要等
`client.marks.js` 到达后才由 `loadBootChunks()` 赋值），而 `republishBootNames()` 起初
没补这四个名字——于是面板每次 `/status` 之后的「重画」都是空操作：停用不灰、启用不恢复。
现在这四个入口随 `republishBootNames()` 一起重新发布；另有 `installMarkWakeups()` 兜底，
在窗口重新获得焦点 / 变为可见时**重新拉 `/status` 再比对**（`MARKS_WAKE_INTERVAL_MS`
节流，focus 与 visibilitychange 往往同时到），覆盖「在别处启用」这种没有任何本地操作
可触发的路径。只跑一次扫描没用：那样只是拿造成问题的那份旧停用清单再涂一遍。监听器随
observer 一起由 `install` 返回的卸载函数摘掉。

身份匹配需要 id 与标题两套集合。这里有个容易踩的坑：`readLiveWorkspaces()` 会从
DSH 自己的 store 重新收集身份，而那个 store **不知道**本插件的停用清单，所以停用
路径单独保存在 `knownDisabledPaths` 里并在每次重新收集时传回去——否则置灰会在
下一次 MutationObserver 回调时消失。

## 面板：已挂载与已停用

「远程工作区」面板把工作区分成两段，互斥：

| 分区 | 内容 | 每行操作 |
| --- | --- | --- |
| 已挂载的工作区 | `/status` 的 `mounted[]` | 「卸载」→ 就地展开确认行；「删除」→ 就地展开两个勾选框 + 确认行 |
| 已停用的工作区 | `/status` 的 `disabled[]` | 「启用」；「删除」→ 同样两个勾选框 + 确认行 |

**主机被删掉之后，它名下的工作区在两段列表里都带一枚红色感叹号**（`.sshwsp-hostgone`，
`role="img"` + `aria-label` / `title`）：悬停提示是「主机 {alias} 已不在主机列表里：这个
工作区连不上，先重新添加该主机」。删主机不会连带删掉工作区——记录还在，点开会话才一个个
报未知主机的错，而那个错只说 alias，不说为什么；标记就是把原因提前说一次。

判据是 `/hosts` 的列表**完整读过**之后仍然找不到这个 alias。三种「没看到」都不算「它没了」：
拉取失败（`hostListingLoaded` 仍为 false）、store 读不出来（`storeError`）、config 里有被跳过的
条目（`skipped`）——否则一次失败的拉取会把每一行都盖成红的，用户学到的就是无视这个标记。
反过来，「列表成功读到了，但里面一个主机都没有」是合法答案（主机全删了、工作区还留着），
那时每行都该是红的。删除主机后动作本身会 `refresh()`，标记当场出现，不用等轮询。
**「卸载」不带任何选项**：它固定走 `detach`，工作区记录与会话都保留，左侧那一行仍在
（置灰）、随时可重新启用。悬停提示（`mounted.detachHint`）只说这一件事，并指向同一行的
「删除」——卸载不再兼职做删除，因为同一个问题在两处问，两个答案迟早会不一致。
卸载仍是两步的：第一次点击只展开确认行，第二次点「确认卸载」才执行。

**「删除」在两段列表里都有，而且是同一个动作、同一套问题**：两步确认，第一次点击只把这一行
换成两个勾选框加「确认删除 / 取消」，第二次才执行。两个勾选框默认都勾上（「删除」这个词的
意思），并且**互相独立**——四种组合都是合法答案：

| 勾选框 | 勾上 | 不勾 |
| --- | --- | --- |
| 删除工作区 | `deregister`：删记录、清持久清单与运行时围栏，侧栏与面板里这一行都消失 | `detach`：只停用，随时能启用回来 |
| 删除会话 | 归档（**不删文件**）：会话从所有列表消失，日志仍在 `sessions/` 下 | 会话留在侧栏那个分组里 |

两个都不勾就没有可做的事，确认按钮直接禁用，而不是悄悄替用户选一个。确认行会比平时宽
（两个勾选框加两个按钮），所以 `.sshwsp-mount` 允许换行（`flex-wrap: wrap`）——窄面板里
把「确认删除」挤出行外，等于藏起这个流程存在的理由。

「删除会话」是归档不是删文件，悬停提示（`workspace.deleteSessionsHint`）里写明：DSH 没有
删除会话的 API，本插件也不绕过服务层去 unlink 日志——承诺一个做不到的删除，比多一句提示更糟。
成功提示因此分三种（删工作区 + 归档 N 个 / 删工作区、会话保留 / 只停用 + 归档 N 个），
同一个按钮对应四种组合，提示必须如实说这一次到底发生了什么。失败不提供重试：请求可能
部分成功（记录已删而归档失败），重放不是同一次操作。确认行里的说明（`workspace.deleteHint`）
同时挂在未确认与确认两个按钮上，不会在按下那一刻消失。

勾选「删除工作区」时，「两边都删除」是**必须同时成立**的：删掉工作区记录已经让侧栏那一行
消失，而面板的「已停用」分区由持久化的停用标记驱动——如果只删记录、不清标记，面板会继续
为一条在任何地方都不存在的记录提供「启用」按钮，而运行时围栏又拒绝这个已经无法
再启用的路径。所以 `deregister` 会同时清掉**持久清单**与**运行时围栏**两处标记。

「已停用分区始终渲染」只针对 `detach`：这是用户得知「卸载之后还留了个东西可以
启用」以及「它去哪了」的唯一途径——如果只在有内容时才渲染，第一次卸载的用户会
以为工作区被永久删除了。

已停用行的样式是 `opacity: .62` 加一个「已停用」小标签，**不使用
`pointer-events: none`**：这一行存在的意义就是它的「启用」与「删除」两个按钮。

## 面板：主机与端口转发

主机区每行一个 alias，右侧是「断开」；端口转发区列出**已存映射**与临时隧道，
顶部有「启动时自动开启隧道」总开关。

### 卡片左侧的电源开关

存储主机（`source: 'store'`）的卡片最左侧是 `role="switch"` 的开关：`aria-checked` 直接读 `/hosts` 行的 `enabled`，不自己推导。`~/.ssh/config` 主机没有这个控件——它没有可写的记录，画一个点了没反应的开关比不画更糟。

- **关是「立刻」，不是「下次」**：确认后一次 `POST /hosts/toggle`，服务端先持久化、再关闸、再拆（在途命令、池化连接、持久 shell、正/反向转发、变更监视、远端终端），成功即 toast 并在原行把开关拨到关。
- **为什么关要确认、开不要**：关会打断正在进行的工作，所以确认框必须列出**此刻**会被打断的东西（连接 / 命令 / shell / 转发 / 反向 / 监视 / 终端，只列非零项），并写明**工作区与会话不会被删除**，之后变灰、重新打开开关即可恢复。开不打断任何东西、也不主动拨号（拨号归「开机自动连接」和首次使用），所以立即生效。
- **置灰不是锁定**：`/status.disabledHosts` 让该主机下的工作区行与会话行变暗（`data-sshwsp-hostoff`，与「已停用」的 `data-sshwsp-disabled` 是两个属性），但没有禁止点击——真用不了时由路由自己回 409 并说明「先打开主机开关」。插件不替宿主关闭会话。
- **失败留在原地**：开关请求失败时，卡片不翻转，错误留在确认框里；开开关失败走顶部 toast（带诊断码 `SSHWSP-E-HOST-POWER`），因为它没有可停留的对话框。

### 两条「断开」路径必须在面板上不可区分

面板读的只有三个字段：`live`（是否真有 listener）、`enabled`（用户的意图）、
`error`（是否需要解释）。两个入口都指向同一个关闭方法，所以三者逐字段相同：

| 入口 | 走的路径 | `live` | `enabled` | `error` | 面板那一行 |
| --- | --- | --- | --- | --- | --- |
| 主机行的「断开」 | `savedForwards.closeAlias(alias)` → 逐条 `closeById` | `false` | `false` | 无 | 已断开 + 开启，**无红字** |
| 端口行的「断开」 | `closeById(id)` | `false` | `false` | 无 | 同上 |
| 连接意外掉线 | `ForwardManager.closeForAlias()` → `onClosed` | `false` | `true` | `"SSH connection closed"` | 已断开 + 开启 **+ 红字「连接已断开」** |

第三行才是故障：连接断得不是时候，所以要保留意图（下次可一键恢复）并留下原因向用户
解释。前两行是用户主动完成的动作，留下原因等于把成功的操作报成故障，后面还会跟着
「启动时自动开启隧道」的暗示——而用户刚刚明确关掉了它。`forwards.lost`
（「连接已断开」）只在 `error` 里含 `connection` 时渲染，因此主动断开后不会出现。

主机行「断开」的 toast 在拆掉了隧道时报数：`hosts.disconnectOkForwards`
（「已断开连接，同时关闭 {n} 条端口转发」），`n` 来自响应的 `closedForwards`；
没有隧道时用 `hosts.disconnectOk`。失败时同一提示带 `SSHWSP-E-HOST-DISCONNECT`
与原始错误，可就地展开 / 复制，并在原节点重放「断开」——主动断开成功不会被改写成故障。

### 面板：持久远端会话

`status.shells` 非空时才出现「持久远端会话」一区，每行 `alias [session]` + 状态
（`存活` / `已结束`）。它是一个**只读**列表——这一区不提供开关或关闭按钮，
因为会话的生命周期归 agent 的 `ssh_workspace_shell` 管（同一 `alias` 可并存多个
命名会话）。空列表**整区不渲染**，避免暗示面板拥有一个它并不拥有的控制项。

## 新建终端的 shell 菜单

菜单是宿主「新建终端」按钮里的那个下拉，插件没有一行 UI 代码——但**菜单项的来源被
接管了**：`ssh://` 会话的 `terminalController.shells()` 改为问远端主机
（`lib/surface/shell.js` 下半），所以列出来的是**这台主机上真的存在**的 shell，而不是本机
装了什么。用户选中哪一项，终端就在远端真的跑那一支。

三种可见后果：

- **远端独有的 shell 现在可选**。此前远端有 zsh、本机没有时它根本不在菜单里；反过来
  本机独有的 pwsh 被选中后在远端只能落到 `sh`。
- **主机不可达时菜单显示 failed + 重试**，不显示任何本机 shell 名字。这是有意的：
  连不上主机时开不出终端，此时给一份本机列表就是谎报。探测失败不会被缓存，重试会
  真的再问一次。
- **换主机就连带换菜单**。答案按「主机 + 连接代次」缓存，重连（可能换了机器、也可能
  重装过 shell）后自动重探；同一代次内反复开菜单只花一次往返。
- **刷新只发生在重连那一刻**。没有定时重探，也没有手动刷新按钮：在一次不断线的会话里
  往主机上新装了一个 shell，它不会自己出现在菜单里——重连一次（或重启 DSH）就来。
  这是权衡后的取舍：定时重探会把"一次探测"变成"每隔一阵一次探测"，只换来"一直没断线
  又刚好装了新 shell"这一种情形。

已知限制：浏览器的 shell 偏好（`dsh.terminal.shell`）是**全局单值**，不区分主机。在两台
路径布局不同的主机之间来回切换时，偏好里那个路径在另一台上不存在，于是回落到那台主机
发现列表的第一项。这是宿主的行为，不是插件的 bug，写在这里是为了不让它看起来像 bug。

## 面板：文件引用设置

端口转发一区之后是「文件引用设置」一区，管的是 `ssh://` 会话里怎么点名**本机**路径。
这一区有**两级标题**，不是同一个标题换了措辞：

| 层级 | 文案（中文 / 英文） | i18n 键 | 说什么 |
| --- | --- | --- | --- |
| 区标题（`h3`，与「主机」「端口转发」同级） | 文件引用设置 / File reference settings | `passthrough.group` | 这两个控件**住在哪** |
| 块标题（`h4`） | 显式文件引用 scheme / Explicit file reference scheme | `passthrough.title` | 这套控件**是干什么的** |

两个键必须分开。`passthrough.scheme`（「本机路径前缀」/ "Host scheme"）是 scheme 输入框的
**可访问名**——第三个字符串——所以改区标题绝不能顺带把字段名改掉，否则读屏用户听到的
名字会跟着一次纯文案改动而变。`h4` 只比 `h3` 轻一档（同 12px 字号、weight 500→400、
`--dsw-alias-label-secondary` → tertiary、`margin: 24px 0 12px` → `0 0 10px`）：字号相同
才让这一区仍读作一块，靠字重与颜色显出低一级；上边距归零是刻意的，它要靠 margin
collapsing 继承区标题的下边距，再写一个 12px 会在标题与它命名的控件之间开一道缝。

- **scheme 输入框 + 「保存」**：Enter 或「保存」都提交，写穿到 live matcher，不必重启。
  Enter 与按钮走同一个提交函数，不存在两条路径。
- **「远端不存在时回退本机同名文件」勾选框**：点一下即保存，没有「应用」按钮。
- `localPassthrough` 为空（直通关闭）时这一区**照常渲染**，只是多一行
  `passthrough.disabled` 说明这两个设置此刻不生效。渲染它是因为设置要能为「以后打开直通」
  先存下来；只在启用时才画，等于让用户没法预先配置。

两个控件都是**乐观更新**：点下先把 `status.passthrough` 改成本地值，请求失败再整体回滚成
发请求前的快照并弹错误提示（`SSHWSP-E-PASSTHROUGH`）；成功时以响应的 `settings` 为准覆盖
本地值，因为 host 可能对输入做了归一（比如大小写）。保存期间两个控件一起禁用，避免在
一次往返中再发第二次。

规则本身（前缀语法、未启用前缀的拒绝、回退的三道闸门）见 [features.md](./features.md) 的
「本机路径直通」，读不到时的排查步骤见 [troubleshooting.md](./troubleshooting.md)。

## 面板：诊断报告

面板底部的「诊断报告」一节是插件唯一**预期被贴到公开场合**的产物：一段纯文本，
把版本、补丁判定、主机配置（含 `~/.ssh/config` 审计）、工作区、连接代次、端口转发、
每主机自检、最近命令与事件组装在一起，供用户贴进 issue。

三个入口共用同一个 `buildSupportBundle`，措辞与脱敏规则不会分叉：

| 入口 | 形态 |
| --- | --- |
| 面板「打开诊断报告」 | 取 `GET /api/dsh-ssh-workspace/support-bundle` 的文本，渲染为面板内的对话框 |
| 报告窗口内的「复制」 | 把**屏幕上这一份**文本写剪贴板；没有剪贴板权限时选中全文，让用户手动 Ctrl/Cmd+C |
| 报告窗口的正文 | 按行着色：`WARN` / `verdict: needs attention` 黄，`## 小节` 加粗，正文中性；只有点到具体坏掉的东西才红（`failed`、`NOT PINNED`、`store error:`、`skipped:`）。颜色只是呈现层——复制出去仍是同一段纯文本，回落到手动选择时选中的也是屏幕上这些行 |
| `ssh_workspace_status` 的 `supportBundle` | 字符串，agent 可直接取用 |

### 状态灯：报告本身不给结论，所以结论由判定模块给

诊断报告是**事实汇总**，不是体检报告——十三节（`## diagnosis` 到 `## note`）全是原始事实，没有一行说"这算不算问题"。
这对粘贴是对的（它不能与面板矛盾），对面板是错的：用户不该需要知道阈值才能判断
`probe: 'fixed'` 意味着"该删了"、或者主机没出现在列表里意味着它的配置被拒绝了。

所以判定和报告合成一个模块 `lib/report/report.js`，并在报告标题后画一个圆点：

| 状态 | 颜色 | 含义 |
| --- | --- | --- |
| `ok` | 绿 | 没有需要处理的事项 |
| `warn` | 红 | 有 N 项需要处理（标题 `title` 与读屏标签给出条数） |
| `unknown` | 琥珀 | 有 N 项无法判断 |

**三态不折叠成两色。** `unknown` 既不是绿也不是红：探测不到的主机不能报成"缺了它所有的
工具"，也不能报成"一切正常"。聚合时**确定的坏压过不确定**——一个红点说"另外我还判断不了
一件事"仍然是红点，可行动的那条事实更重要。

判定只读报告**已经在打印的字段**，不探测、不连接、不读文件。它在**服务端**计算
（`/status` 的 `diagnosis` 字段），浏览器只负责渲染——两处各自推导同一套规则，是"圆点与
报告说法不一致"的开始。

**圆点必须在面板里可行动**：findings 直接列在标题下方（最多 8 条，其余显示总数）。
一个只说"有问题"却不说是什么的圆点是个谜题，不是报告。

**每条 finding 的徽章取它自己那句话的语气**：`WARN` 是警告（黄），只有文字里真的点到
坏掉的东西（`failed`、`NOT PINNED`、`could not be saved`）才是红，「无法判断」是三者里
最弱的一档，用静默的灰。以前所有 `WARN` 都穿危险色，于是"需要注意"和"这里有东西坏了"
是同一种红——颜色用尽之后，剩下的信息就没了。同一条规则也用在报告正文的行上，
两处不会对同一条 finding 给出不同的说法。

### 圆点只回答「这个会话有没有事」，不回答「这台主机能做什么」

自检（缺 `rg`、缺 `git`、非 UTF-8 locale、watch 上限偏低）**不算 findings**，只作为
`notes` 单独呈现：折叠在 findings 下方，带自己的标题，且**不带严重度徽章**。

理由是这两类事实性质不同：

| | 例子 | 谁能改变 | 属于 |
| --- | --- | --- | --- |
| finding | 主机密钥没固定、存储读不出、重连放弃了 | 用户，通常就在面板上 | 这个会话出了事 |
| note | 缺 `rg`、locale 非 UTF-8、`inotify` 上限低 | 往往改不了（无 root、镜像受限） | 那台主机就是这样 |

把 note 混进 findings 的直接后果是**灯在健康的机器上变红**：装了个干净的 Debian、
没装 `rg`，圆点立刻是红的。会变红的灯最后一定不被读——而它一旦被忽略，就再也无法承载
真正要紧的那两条（未固定的密钥、读不出的存储）。

note 不是被藏起来：它仍然在面板里（可展开）、在报告里（`advisory (not counted in the
verdict):` 一节）、在工具返回值里（`diagnosis.notes`）。**看不见的降级仍然是禁止的**，
只是它不再冒充结论。

判定与计数只读 `findings`，`notes` 永远是 `state` / `warn` / `unknown` 的旁观者。

### 自检分区默认关闭

面板上原本有一节「远程环境自检」，每台探测过的主机一张卡片，外加一个「自检」按钮。
**这一节现在不渲染了**，由 `lib/client/client.panel.js` 里的 `SHOW_SELF_CHECK_SECTION = false` 控制。

**是关掉的一棵活树，不是注释。** 两者的区别在于本仓库的测试方式：`client-shape-smoke`
几乎全部断言都是对 bundle 文本做 grep，把 JSX 注释掉会让**所有**相关断言继续绿着，
而面板什么都不显示——测试从此描述一段不存在的界面。所以这里留一个具名布尔值，两处渲染点
（标题区与列表）都带 `&& SHOW_SELF_CHECK_SECTION`，并让套件把「它是活的」也钉住：
`isLive()` 用注释配平判定某个匹配落在注释里还是代码里。改回 `true` 就恢复 0.2.8 的行为，
包括每张卡片的展开与 `/status` 优先的数据源。

**信息没有消失，只是不再占面板。** 同一批行的其余三条路径都还在：状态灯下方的
`details` 提示块、诊断报告里 `advisory (not counted in the verdict):` 一节、
`GET /self-check` 与 `ssh_workspace_status` 的 `selfCheck` 字段。一条事实都没少，
少的只是面板对一个它并不参与判定的信息又重复了一遍。

关掉的是渲染，**不是探测**：服务端仍然按需探测并缓存，因为报告和 agent 都要读它。

### 自检卡片：默认折叠，标题即开关

（以下描述的是开关打开时的形状，保留下来是因为恢复时要恢复的是这个行为，而不是它前面那个 bug。）

一张自检卡片只显示 `dev  2 缺失  3/7 已安装`。想知道缺的是哪两个，点标题展开——
标题是 `<button aria-expanded>`，不是 `div` 加 `onClick`：键盘可达、读屏能读出展开状态，
这两件事不该靠重新实现获得。展开状态按 alias 存在面板层，**不在卡片内部**——面板有轮询，
把状态放进行里会让它每隔几秒自己收起，比不带展开更糟。

这里曾有一个真实的 bug，值得记下因为它长得不像 bug：**切到别的页面再回来，卡片还记得
「2 缺失」，却再也说不出是哪两个**。原因是渲染取的是 `checkReports`，那是 React state，
随面板卸载一起消失；而 `missing` 计数走的是 `/status`，活了下来。于是界面停在「有数量、
无名字」——不是交互缺失，是**数据源选错了**。

修法是把 `/status` 放回第一顺位：它每次都从服务端的探测缓存重新推导同一批 `rows`，
既持久又同样新鲜；手工点「自检」拿到的报告仍然优先，因为它可能比最近一次轮询更新。
`selfCheckSummary` 因此被抽成纯函数并被测试**真实执行**——包括「有计数无行」这一种，
它是这个 bug 的独有状态，截图里永远看不到。

面板上「缺失 N 项」与「N 项未确定」是两个并列的徽章：`unknown` 不是 `absent`，
统计里分开数，展开的明细里也分开措辞。

### 报告里补上了三处它原本漏掉的事实

判定要诚实，报告就得先带上这些事实（都来自已有数据，没有新增采集）：

- **`## host keys`**：被接受但没能固定的主机密钥。这是"报告什么都没说"与"报告说一切正常"
  曾是同一个画面的地方，也是安全上唯一真正要紧的一条；
- **被跳过的主机**：`~/.ssh/config` 里存在但无法使用（如带 `ProxyCommand`、端口非法、缺 `HostName`）的条目以前**根本不出现**
  在报告里，于是"我明明配了却用不了"没有任何线索。现在带原因列出，别名照样打码；
- **连接代次**：`generation` 大于 1 时说明"重连前启动的远端进程可能仍在运行"。
  "偶发断线"与"从没连上"以前在报告里长得一样。

另外，空补丁列表的措辞不再合并两种情况：`none installed (or the projection seam was
unavailable)` 把"补丁不需要装"和"我不知道补丁装没装"写成了一句，现在只说后者。

「复制」不在面板工具栏上，而在报告窗口里。复制只在**已经有一份报告**时才有意义，而且
工具栏上的「复制」在无剪贴板权限时会悄悄改成弹出一个窗口——按钮的标签承诺了另一件事。

### 报告窗口：自动换行、打开不选中

文本用 `wrap="soft"` + `white-space: pre-wrap` **自动换行**。它曾经是 `wrap="off"` 加横向
滚动，为的是让一条被脱敏的长路径留在一行；但报告是逐行读的，横向滚动逼读者一边读一边拖，
而换不换行对内容没有区别——等宽字体下对齐照旧。

打开时**不自动全选**。`area.select()` 挂在挂载时看着贴心，实际是：整份报告在用户还在读的
时候闪成高亮，之后任何一次按键都把选区换掉，浏览器没拿到焦点时还会留下一个没人要的选区。
复制改为窗口底部的按钮，键盘用户也够得着。只有在**复制失败**（没有剪贴板权限）时，
才退而选中全文——那是用户按了「复制」之后的补救，不是打开时的惊喜。

`client-shape-smoke` 对 `ReportDialog` 内部**计数** `.select(` 的出现次数（恰好 1，且必须
在 `handleCopy` 之后），而不是断言「挂载时没有 `area.select()`」——后者会被
`areaRef.current?.select()` 这种写法绕过，反向验证时确实绕过过一次。

### 「打开」为什么不能是新窗口

「打开诊断报告」曾经是一个 `<a href="…" target="_blank">`。**在桌面端它点了没反应**，
而路由本身返回 200——失败的是新窗口这条路径，有两层原因：

1. 桌面端的文档来源是 `dsh-app://app/`，相对 `href` 于是解析到 `dsh-app://` 协议。
   主窗口的 `setWindowOpenHandler` 只放行 `http:` / `https:`，其余一律 `deny`，
   点击被静默吞掉。
2. 即便协议被放行，`shell.openExternal` 会交给系统浏览器，而那个浏览器没有 Host 的
   鉴权 cookie，只会拿到 `401 dsh web authentication required`。

所以入口改为**在面板内取同一份字节**：`fetchReportText()` 是唯一的取数点，「打开」把它
渲染进一个只读、可选中、等宽的 `ReportDialog`，复制在该窗口内完成。`client-shape-smoke` 用
「这一节里不得出现 `window.open` / `target: '_blank'`」来钉住它——断言的是**形状**
而不是「有个按钮」，因为前者才是两个壳子里都会坏的那一半。

### 标题叫「诊断报告」，标识符仍是 `support-bundle`

标题改过一次：原先叫「支持包」，那是从 Docker / Kubernetes 借来的术语，而本插件
没有支持台、产物不是归档、且**不上传任何地方**——"支持"二字暗示了一个并不存在的
接收方。新标题用「诊断报告 / Diagnostic report」。

**标识符一律不动**：路由 `/support-bundle`、工具字段 `supportBundle`、模块
`support-bundle` 这个拼写、套件 `support-bundle-smoke` 都是契约面，改名没有功能收益。
这与仓库既有习惯一致——面板叫「最近的远端命令」而模块叫 `audit.js`。

避免用「插件诊断」：`ssh_workspace_status` 里已有 `diagnosticsText`（事件环容量 40 条、
它只导出最新 20 条），
两个"诊断"并存会让读者分不清该贴哪一个。「报告」二字守住了区别——这是**一份可读
文本**，不是要上传的归档。

### 第四个 tab：审计是一张表，不是一个开关

面板的 tab 行从三个变成四个（主机 / 工作区 / 审计 / 设置）。审计**不该**留在「设置」里：
设置里的每一节都是开关或输入框，而这一节是一张要读的表——「刚刚到底跑了什么」是用户
遇到怪事时打开面板的原因，埋在设置下面等于没有。

表的行为按「读」设计：

- **倒序**：最新的一行在最上面，与「刚刚发生了什么」的直觉一致；时间列只到秒，日期省掉，
  因为表里只保留保留条数之内的行（小时到天级），顺序本身就是时间轴；
- **每行五段**：时间（等宽 + 表格数字）、主机、通道（`command` / `persistent shell` /
  `background job` / `terminal input`）、状态、命令。命令是唯一可伸缩的列（`flex: 1 1 240px`），
  长行折行而不是把其它列挤走；错误另起一行并以危险色显示，**title 保留全文**；
- **状态有颜色但不只靠颜色**：拒绝是黄、非零/超时/未知是红、成功是绿，文字本身写着
  「被拒绝（未执行）」「结果未知（连接中断）」——一行被截图贴出去也要能读懂；
- **按工作区筛选**：一个主机可以承载互不相干的工作区，它们的命令不是彼此的事。成员关系
  （`sessionIds`）随 `/status` 一起来，所以筛选是本地投影，每改一次选项不发请求；
- **空态分两种**：「还没有记录到远端命令」与「这个工作区还没有记录到命令」——后者的原因
  是筛选，把它说成前者会让用户以为日志坏了；
- **刷新按钮**而不是轮询：审计不是「现在的状态」，它是一份记录，只有用户要求时才重读。

保留条数就放在这张表的上方（数字框 + 保存），而不是搬回设置：**这个数字唯一的作用
就是这张表有多长**，分开放会让「改完去别处看结果」成为一次多余的往返。改小会立刻裁剪
已经记录的行，所以服务端的答案（夹取后的值）会写回输入框，而不是保留用户敲的那串。

另外两处相关：`/status` 里的「最近的远端命令」一节仍在，但它只画失败 / 拒绝 / 未知 / 超时
的最近 10 条——那是「哪里不对劲」的提示，不是审计；完整表在审计 tab，两者读的是同一个环。

### 脱敏是设计约束，不是选项

- 家目录段打码，保留首段与扩展名（仍能分辨 `src/index.ts` 与 `dist/app.js`）；
- alias 短写且**跨行一致**（同一主机的多条事件仍可关联）；三个字符以内整体打码；
- 登录用户打码而地址与端口保留（`<user>@10.0.0.1:22`）；
- 命令行经 `audit.js` **在写入时**脱敏，不在导出时补第二次；
- 凭据从不进入报告：存储里的 secrets 是加密的，报告读的是面板那份无密行。

**没有"原始模式"开关**——有 raw 开关的报告，一定会有人用 raw 模式贴出去。

报告末尾固定一句：`Paths, usernames and credentials are masked. Nothing was uploaded: you decide where this goes.`

这句话**只留在报告里**。面板工具栏下面那行提示原先也带着"不会上传到任何地方"，两处同时
声明让一句陈述读起来像免责声明；提示现在只说**报告包含什么、已经脱敏**，"不上传"由报告
自己的收尾句负责——那是唯一真正需要读者知道这件事的地方（他正要把它贴出去）。

## 路径的展示拼写

两处纯展示的替换，把 `ssh://alias/path` 显示为 `ssh://alias@/path`（读起来像 SSH 地址）：

- 工作区悬停卡片（hover card）中的路径；
- DSH `PathLabel` 单元格：文件面板头部、文档预览标题、交付物列表。

只改渲染文本，复制行为与所有功能消费方保持真实拼写。规则细节见 [protocol.md](./protocol.md) 的「显示规则」。

## 文件进任务：拖拽与右键

侧边栏文件树的文件与文件夹（`li[data-files-entry="file"|"directory"]`）有两种手势把路径加入当前会话的任务：

- **左键拖到输入框**：拖动经过输入卡（`[data-composer-card]`）时卡片显示虚线高亮（内联 `outline`，拖拽结束/离开即清除）。指针在 `[data-composer-input]` 内时，`dragover`/`drop` 用浏览器的 `caretRangeFromPoint` 把指针位置映射成当前草稿的 detect 偏移；第一个 chip 插在落点，后续 chip 依次跟在它后面。拖动期间输入框内画一条 2px 竖向落点光标（单例 `#sshwsp-drop-caret`，只设内联样式），离开输入区、松手或拖拽结束即隐藏。多选整批拖入时按树中顺序逐条插入、重复路径只插一次、末尾只聚焦一次；拖拽结束时清掉树行里被手势留下的文本选区，光标落在 chip 之后而不是行名上；
- **落点映射的退化**：只有“唯一可见的输入卡”且指针确实落在其输入区内、浏览器能给出 caret、边界能映射到草稿时才使用落点；以下任一情况都回退到旧行为（追加到当前选区/末尾），且不会让投放失败：

  | 条件 | 结果 |
  | --- | --- |
  | 同时可见多张输入卡，或投放卡片不是唯一可见那张 | 不使用落点 |
  | 指针在卡片内边距/边框上，但不在 `[data-composer-input]` 内 | 不使用落点 |
  | `caretRangeFromPoint` / `caretPositionFromPoint` 不可用，或返回输入框外的节点 | 不使用落点 |
  | 边界落在顶层段落之外，或偏移超出当前 draft | 不使用落点；空输入框中的空段落仍可映射到 0 |
  | 映射过程抛异常 | 捕获后回退，拖拽插入继续 |
  | 宿主拒绝该 span（越界/版本漂移） | 同一 span 走纯文本降级；再失败才提示插入失败 |

  落点只由**第一个**插入项消费；它失败或不可表示时不会污染后续项——首项不可表示则留给下一项，首次尝试失败则后续项改用实时 `captureInsertion()`。
- **右键 → 菜单**：行上弹出锚定菜单（复用 `.sshwsp-flowmenu` 样式，视口内钳制）。**多选时菜单作用于整个目标集合**（`resolveTargets`：右键落在选中之外的行会先收拢到该行，落在选中之内则保留整批），「添加到任务」与拖拽走同一个插入助手，因此一次只聚焦一次、逐条插入、重复路径只插一次；
- **空白处右键（仅本地工作区）**：菜单恰好三项——「新建文件」「新建文件夹」与「复制路径」。目标目录是空白处所属的那一个：落在某个已展开目录的嵌套列表里就是那个目录（宿主的子列表在该目录自己的 `li` 内，所以不能拿 `closest(li)` 当行手势），否则是树根；两者都必须在该树根之内，根是 `ssh://` 或不在根内时整条本地路径不成立。两个新建分别走共享的 `POST /create-file` 与 `POST /mkdir` 本地分支并选中新行；「复制路径」始终可用，只读会话只禁用两个新建。远端工作区保留原来的空白处菜单，两种菜单不混用。
- **菜单只属于文件面板内部**：空白处右键的作用域是 `[data-files-page]`，**不是 document**。容器边界只能放宽到面板这一层：头部的路径标签与按钮是树体的**兄弟**，所以指针所在的最窄容器里没有那颗按钮，必须从页面找；再往外放宽就会借到**别的**面板。这是本轮修掉的缺陷：搜索曾一路放宽到 `document`，于是会话正文里任意位置右键都会弹出第一块已渲染文件面板的目录菜单，本地与远端两个面板并排时在本地一侧右键也会拿到另一台主机的目录。现在面板以外（会话正文、其它侧栏标签、对话框外）一律 `return false`，交还浏览器原生菜单；面板内部也只有一个来源：alias 与目录取自**该页面**头部按钮的 `data-sshwsp-alias` / `data-sshwsp-dir`，且树必须属于这一页（`page.contains(tree)`）。本地面板没有那颗按钮，因此它的头部空白同样是浏览器菜单。文档预览标签里的 navigator 没有 `data-files-page`，也没有空白处菜单——行菜单照旧可用，行手势（含键盘 `ContextMenu` / Shift+F10）不受此门禁影响。树根 `data-files-root` 为空只让 @ 相对拼写失去基准，不让菜单消失。

菜单内容取决于该行是否落在远端工作区：

  | 菜单项 | 出现条件 | 说明 |
  | --- | --- | --- |
  | 「添加到任务」 | 总是 | 菜单项副标题直接显示将要插入的 `@` 拼写，点击插入 |
  | 「下载到本机」 | 仅远端行 | 目录行同样可下载：整棵目录以 ZIP 归档流式下载（`?format=tar` 可改要 tar）。归档边读边写，没有 `content-length`，队列按已传字节报进度而不画百分比 |
  | 「上传文件到此目录」 | 仅远端行 | 文件行传到它的父目录，目录行传到它自己 |

  本地工作区的行只有「添加到任务」——`GET /download` 与 `POST /upload` 对本地路径没有任何可对话的对象，摆出这两项等于承诺一个该行并不具备的能力。

插入与「`@` 补全里选中候选」走同一条管线：取主会话 composer 的 `captureInsertion()` 跨度（拖放时第一项改用指针映射出的折叠跨度），经会话作用域的 `slash/input-insert-reference` 事件交给编辑器——chip 节点、序列化与失效判定因此与补全完全一致（插入后可继续输入、照常提交）。会话监听不声称该事件时降级为纯文本插入；输入框不可用或路径不可表示时给出 toast。拖放跨度只在第一次尝试中使用，文本降级复用同一个 span，不会重新 capture 后把落点丢掉。

拼写规则与 `@` 补全一致：树根即会话 cwd 时用**工作区相对路径**（`/` 分隔），否则保留绝对拼写；含空格按引号语法（目录保留开引号）。带控制字符或双引号的路径拒绝插入。

实现要点（`lib/client/client.js` 的 "Composer file bridge" 段）：行的 `draggable` 标记并入 DOM 装饰的同一趟 pass（`MutationObserver` 触发、rAF 合并）；拖拽只写入自定义 MIME、**不写 `text/plain`**，因此不触发输入框的文本粘贴，也不会与 DSH 的「拖入文件」浮层冲突；文档级 capture 监听 `dragover`/`drop` 判定输入卡并转发手势。**载荷是版本化 JSON**（`{v:1, items:[{path,isDir}], root}`）而不是单条路径：`dragstart` 用 `resolveTargets` + `treeSelectedItems` 得到整批目标，点在选中之外时先按 `point` 手势收拢；`drop` 先用当前事件 `dropOffsetFromEvent` 重算落点（不缓存 dragover 的值），再只调一次 `addPathsToTask(..., card, at)`。坐标映射（chip=1、managed `<br>`=0、段落间一个 `\n`、嵌套元素递归）与视觉光标各只有一处实现；光标是 `document.body` 下的单例 `#sshwsp-drop-caret`，不写 `<style>`、不动宿主样式表。浮动菜单的定位、首项聚焦、Esc / Tab、外点、滚动 / resize / 失焦全部收在 `openMenuAt` 一处，行菜单与本地空白菜单共用它。手势面向**主会话**的输入框（文件树跟随主会话，二者工作区根一致时用相对拼写）；多输入框不承诺精确路由，按上面的退化表回退追加。

## 从系统拖入文件（上传）

宿主「文件」树还有第二种拖拽方向：从系统文件管理器把文件拖进树里，上传到远端。它与「把树行拖进任务」共用同一组 document capture 监听，但进入处理函数后立刻分流：内部拖拽只带自定义 MIME，系统文件只带标准的 `Files` 类型；目标解析、插入助手和高亮都不共享。

### 两种“文件夹”

| 名称 | 指什么 | 本功能的行为 |
| --- | --- | --- |
| **目标文件夹** | 树里的目录行，是**投放目的地** | 拖文件到它上面就传进这个目录；展开或折叠都一样 |
| **拖进来的文件夹** | 系统文件管理器里被拖动的目录（`webkitGetAsEntry().isDirectory`） | v1 **拒绝**，不递归、不入队；有文件同时拖入时文件照常上传，文件夹合并成一条提示 |

把“拒绝文件夹”理解成“拒绝落在目录行上”是错的：前者是**拖入内容**，后者是**投放目的地**。两处判定分别在两个函数里，互不复用。

### 落点 → 目标目录

宿主把展开目录的子列表渲染在**该目录自己的 `li`** 内，因此 `closest` 能直接回答“这个落点归哪个目录”。实现只用 `closest`，不拼 CSS 路径，也不读展开状态：

| 落点 | 目标目录 |
| --- | --- |
| 目录行（折叠或展开） | 该行路径自身 |
| 展开目录内部的空白 / 子行之间的空隙 | 由 DOM 归属到**那个目录**，不是树根 |
| 展开目录里的子目录行 | 子目录自身 |
| 展开目录里的子文件行、不可点的 `other` 行 | 它的父目录（与行菜单上传一致） |
| 树体空白（没有任何行祖先） | 树的 `data-files-root` |
| 树的路径标签 / 头部按钮 | 树根（头部没有行祖先，但仍在树内，不交给宿主附件） |
| 树外（输入框、消息区、对话框） | 不拦截；宿主附件行为保持不变 |
| root 缺失或为空 | 不拦截 |
| 本地工作区的树 | 明确拒绝并提示；**不交给宿主**变成 composer 附件 |

实现只读 `data-files-entry` 的**值**（目录是 `"directory"`，不是 `"dir"`），不读 `aria-expanded`，也不寻找不存在的 `data-files-expanded`；不按展开状态分派，**不自动展开**目录：展开是宿主 store 的事，drop 时去点它会令行位移、子行突然出现。行命中只靠 `closest`，不拼接路径选择器（空格、引号、反斜杠都会炸）。

高亮取**行按钮**而不是整个 `li`：展开的 `li` 包含整棵子树，outline 会套住一片无关内容；树体高亮取 `[data-files-body]`。单例标记是 `data-sshwsp-osdrop`，清理走文档级属性查询，因此 HMR 替换实例后旧轮廓也能被清掉。行按钮用 `outline-offset: -2px`，树体用 `2px`；只设内联样式，不写 `<style>`、不动宿主样式表。

### 识别、拒绝与入队

- 系统文件拖拽用 `dataTransfer.types` 里的 `Files` 识别（大小写不敏感）；内部“树行 → 输入框”的拖拽只写 `application/x-dsh-ssh-workspace-file`，`types` 不含 `Files`，所以不会进入 OS 分支。`dragover` 阶段不读 `dataTransfer.files`（可能为空），`drop` 才读。
- `drop` 按宿主的同一套索引配对拆出文件夹：只取 `kind === 'file'` 的 `items`，逐个与 `files` 对齐，`webkitGetAsEntry().isDirectory` 为真即文件夹。没有 entry API、API 抛错或读取失败时按文件处理，不崩、不假装识别。
- 文件夹**整体跳过**：不入队、不遍历、不展开树；名字只列前三个，后面用省略号。文件夹与文件混合时，文件照常入队，文件夹的说明**搭在那一条批次提示的结果句上**（后接「· 已跳过文件夹：…」），不再另开一条——同一时刻只有一个 toast，两条会互相替换，先出现的那句就先消失。只拖文件夹时没有批次可搭，拒绝句就是全部结果，仍然单独出现（错误码 `SSHWSP-E-OSDROP-FOLDER`）。
- 上传不另写队列：文件交给 `queueTreeUploads`，与行菜单的 picker 共用同一个 `enqueueUploads` 与同一句超限提示（`SSHWSP-E-TRANSFER-SIZE`）；刷新也由队列完成后的 `nudgeFilesPanel` 负责，不新增第二个刷新器。只拖文件夹时队列为空，此时没有任何上传 toast 与之竞争，拒绝提示照旧单独出现。
- 本地工作区的树没有远端可写对象，整批拒绝（`SSHWSP-E-OSDROP-LOCAL`），且**不把文件交给宿主附件**；只有树外才保持宿主的“拖到此处添加”行为。

### 与宿主附件、内部拖拽的分界

- 监听挂在 **document capture** 阶段。落点在树内且能解析出目标时，OS 分支 `preventDefault + stopPropagation`，宿主附件包的 bubble `drop` 收不到这次投放；落点在树外时**不调用**这两个方法，宿主照旧把文件收成 composer 附件。
- 内部拖拽载荷没有 `Files`，OS 分支不触发；反过来 OS 分支也**不调用** `addPathsToTask`。进入一次系统文件拖拽的 `dragenter` 会清空可能残留的内部 payload，避免旧手势被 composer 分支认领；`dragleave` 在真正离开树时清除高亮，`dragend` 同时清掉高亮与内部状态。
- 树头 / 路径标签 / 刷新按钮落在树内但没有行祖先，按树根处理；这与树体空白一致，且不会触发宿主附件。

### 退化矩阵

| 条件 | 行为 |
| --- | --- |
| 树外、root 缺失/空 | 不拦截；宿主附件照常接管 |
| 本地工作区树 | 拦截 + 本地拒绝提示；无附件、无队列 |
| 只拖文件夹 | 拦截 + 一条文件夹拒绝提示；队列为空 |
| 文件夹 + 文件 | 文件入队一次；跳过说明写进同一条批次提示的结果句，不另开 toast |
| 文件超过队列上限 | 只有超限项被拒，提示复用行菜单的超限文案 |
| `dataTransfer.files` 为空 | 静默返回 |
| 无 entry API / entry 抛错 | 都当文件上传，不崩溃 |
| HMR 两套监听 | 一次事件只被一个实例消费；高亮按文档属性清理，不叠两圈 |

## 文件面板与文档预览

「工作区文件」侧边栏与文档预览无需插件改动——它们经 `ctx.fs` 读取，远程工作区下自然由 SFTP 提供（列目录、读文本、写回均同本地工具一致），大文件预览按块流式读取。

插件往这个面板加了**一个**控件：`sidebar.right.tab.files.actions` 插槽里的托盘箭头图标入口，**只在面板显示 `ssh://` 远程工作区时渲染**——本地目录沿用宿主自己的头部，底面没有 alias 可携带，队列属于远端。它读槽位给的 `absolutePath`（面板正在显示的目录），把 alias 与远端路径写在自身属性上，供**本文件面板内**的空白处右键菜单定位当前目录；点击弹出进度浮层。图标空闲时是深色的裸箭头，有排队或运行中的项时整枚变蓝并套上聚合进度环（进度按字节加权，数量放在无障碍名称里）。**上传按钮已从头部移除**：上传只由行菜单的「上传文件到此目录」提供，「浏览目录」只浏览与挂载；同一个窄条里再放一个按钮会把最该随手可点的进度入口挤掉。目录不能作为一个文件下载，因此头部**没有**下载按钮——下载在行菜单里，那里目标明确。

本地目录下列表没有可上传的对端，所以行菜单也不给上传；头部也**不渲染**「传输」——本地目录沿用宿主自己的头部（队列是远端控件，底面没有 alias 可携带）。此时若仍有远端传输在跑，改由完成提示继续报告，而不是在一个与远端无关的头部放一个半真的入口。宿主版本没有声明这个槽位时该控件同样隐藏，并在面板的诊断区给出一句可读原因（不是静默消失）。在远程列表里入口**常驻**：不随队列清空而消失——一个会自己消失的入口，用户分不清是「没有传输」还是「控件坏了」，空闲时只是不亮、不戴环。

### 传输队列与进度浮层

队列是浏览器侧传输的**唯一状态**，文件面板从它读，没有第二份计数。

- 入口与定位：文件面板头部的托盘箭头图标，**进行中（排队或运行）时变蓝并戴环**（环聚合整个队列：`transferQueueProgress` 按字节加权，任一无总量的运行项让弧线旋转，仅排队时是空环），**仅在远程目录列表里出现**（本地目录不注入；此时在跑的远端传输仍由完成提示与文件面板的行内状态继续报告）；浮层 `position: fixed` 锚定按钮（按视口坐标计算），窗口 resize / 滚动时重算，面板折叠到找不到按钮时回到默认位置。
- 尺寸与滚动：宽 **400**（窄视口下不超过视口宽度减 16）、最大高 320，内部列表滚动；不因一条长文件名把面板撑出屏幕。
- 绘制顺序：排队 / 运行中的项在上、按到达顺序；已结算（完成 / 失败 / 取消）的项在下且**最新在前**。store 仍按到达顺序调度（`queueDrain` 依赖它），只有列表的绘制顺序变了——此前始终按到达顺序追加，下载几次之后最新一行落在 320px 可视区之外，打开浮层看到的是最老的行，容易被读成「这次下载没有记录」。
- 每行：方向**图标**（`UploadIcon` 托盘上箭头 / `DownloadIcon` 托盘下箭头，运行中变蓝）+ 名称（按码点截断，`title` 给全名）+ 百分比或字节 + 取消按钮。下载在跑时方向图标外面套一圈：灰色轨道 + 蓝色弧线（`TransferProgressIcon`）——已知总量按比例填充，未知总量（目录归档）转一段固定 30% 的弧，**排队中只有空环、不转**。同一个环也出现在文件面板头部；行内下载入口在下载期间禁用，避免同一路径被排两次。
- 图标而非字符的取舍：`↓` / `↑` 是字体字形，字重随宿主主题漂移，也画不进同一个环；因此下载、上传与菜单图标改为 svg 线条。下载与上传共用 `TRAY_ARROW_PATHS` 的一组托盘箭头（定义在 `lib/client/client.icons.js` 的 `DownloadIcon` / `UploadIcon` / `TransferProgressIcon`），行内按钮与菜单的传输项用同一组路径。菜单里其余动作各用独立图形：添加到任务（对话气泡 + 号）、复制路径（双页）、重命名（铅笔）、删除（垃圾桶），不再按文件 / 文件夹类型套图标。**只有知道总量才画百分比**（单文件下载的 `content-length`、上传的本地文件大小）；目录归档没有总量，只报已传字节，不画 0% 也不画假的进度。失败行直接列出原因，不折叠。
- 速度与进度条：名称下一条浅蓝色进度条（`aria-hidden`，数字仍由文本给出）——已知总量按百分比填充，已完成填满，目录归档没有总量时用横向扫描动画，**不画 0% 或 100% 冒充**；失败 / 取消的填充转灰，表示字节停在哪里而不是方向。运行中的行同时显示速度（`45% · 1.2 MB/s · 23.4 MB`）；速率由队列状态机按动作时钟采样并平滑，**两次采样不足 250 ms 不更新**、**停顿超过 5 s 归零重测**（不把停顿平均成一个很慢的速度），结束时不再显示速度。
- 底部：常驻「刷新或关闭页面会中断传输」（刷新不会在后台继续），以及「清除已完成」——只在有终态项时可用；进行中的项不会被清除。
- 空态：远程目录列表里，队列为空时入口照常渲染，浮层显示「暂无传输」；浮层开着而队列被清空也保持打开，不再自动关闭——入口常驻之后，空队列是一个可查看的状态，而不是「面板该消失了」。
- 关闭：点击浮层外部、`Esc`、右上角 `×` 都会关闭；与对话框共用 `useDialogA11y`（焦点进入、Tab 限制、关闭后焦点回到按钮），遮罩透明但覆盖整屏，按「按下与松开会都落在遮罩」判定。
- 目录浏览对话框不再内联任何传输行：它只浏览与挂载，队列的进度留在文件面板头部这个入口里，避免同一份 store 有两套展示。
- 完成提醒：同一批传输只用一个 toast 节点，在途时写「传输队列：N 项…」，结束时**就地改写**成合并结果（「N 项完成，M 项失败」）；不会每个文件弹一条，因为互相重置计时器会把最该读到的结果挤掉。失败结果带诊断码（`SSHWSP-E-TRANSFER-UPLOAD` / `-DOWNLOAD` / `-BATCH`）与逐项原始错误，可展开详情 / 复制整段诊断；整批不提供「重试」——逐项重试属于队列行，避免 toast 与队列出现两个入口。批量里只要有一项走的是浏览器自己的保存流程（没有 File System Access API），结果就说「已开始」而不是「已传输」——页面没有看见保存，就不能声称保存。

已知差异：远端的变更监视**优先走 `inotifywait` 推送**（远端装了该工具时即时上报，不受元数据精度限制）；没有该工具时回退到**轮询式**快照比对——基础约 2 秒一次，空闲目录自适应退避到 5–10 秒、变更后立即回到 2 秒，文件树 / 预览会自动刷新。轮询路径下 SFTP 元数据无亚秒时间戳，同一秒内等长的连续改写可能不触发刷新（增、删、改名总能感知），此时重新打开或重新读取即可看到最新内容。

## 文件编辑

文档预览头部有一个铅笔按钮（`sidebar.right.tab.document.actions` 插槽，只在预览的是一个**文件**时出现——目录、缺失文件、二进制与超出上限的文件都不给这个入口）。点开后编辑器**盖在预览正文那一块上**（不是全屏对话框）：左边行号，右边 `textarea`，底部一行元信息（行数、行尾选 **自动 / LF / CRLF** 的选择器、是否带 BOM），而预览的头部——包括这枚按钮本身——仍然露在上面，成为退出的入口。

### 不能编辑时：红点，以及悬停才说的原因

同一个位置只放一枚铅笔，能不能用由**探测**回答（文件类型、编码、大小、会话读写模式、是否在工作区内）。不可编辑时按钮**不消失**，也不变成 `disabled`：禁用控件在部分浏览器里不弹自己的 `title`、也不能获得焦点，于是「为什么点不动」只能靠猜——这正是这枚按钮最早的样子。现在按钮保持可悬停、可聚焦，改用 `aria-disabled` 表达状态，`click` 里再守一道；图标右上角加一个 6px 红点（`--dsw-alias-state-error-primary`，外圈用背景色描边），`title` 仍是本地化原因，探测失败时再拼上服务端的原话。

红点戴在所有「不能编辑」上，包括超过 2 MiB 的分页（按钮仍可点，打开的是只读分页）、只读会话、二进制/非 UTF-8/GB18030 这类编码限制，以及工作区外与停用工作区。点放在角上而不是把整个按钮染红：红色实心按钮在这里会被读成「危险操作」（删除那一类），而这里的语义是「不可用」。

探测对**≤64 KiB 且可编辑**的文件会把正文随答案一起带回（`preload`）。点开编辑器时直接用它起稿，不再发第二次 `read-text`——编辑器打开因此不再额外付一次 stat/open/read/close，探测这一次读顺带把正文带回。令牌（`version` / `revision`）一同带回，保存时仍会发现探测与点击之间文件被改过；超过 64 KiB 的文件仍只读 8 KiB 样本，正文等点击后再取。

### 这枚按钮为什么需要自己的 Suspense

按钮在 `client.editor.js` 这个按需 chunk 里，所以注册进槽位的是 `React.lazy`。**宿主的槽渲染器只给每个占位组件包错误边界，没有 `Suspense`**——在 `app.asar` 里以 `renderOutletContent` 为锚点前后各 20k 字符内，`Suspense` 出现 0 次。把一个 `React.lazy` 直接注册进去，它一挂载就挂起、没有东西接住它，React 把那棵子树画成**空**：没有报错、没有控制台警告、没有任何断言变红，只有一枚不存在的图标。

第一版就是这么发的。修法是注册一个自带 `Suspense` 的 `FileEditActionSlot`——本文件里其他每个懒占位（`PanelSlot`、`DialogSlot`、两个选择器流程）都包了，只有这一枚漏了。套件里除了钉这一枚，还钉了一条**通用**规则：本文件里任何 `React.lazy` 都不得被直接注册进槽位，否则下一个漏包的人会重复同一个下午。

### 会话来自槽位，不是来自输入框

这个槽是 `scope: 'session'`，所以宿主渲染它时已经知道「这是哪个会话的预览」，并通过标准 prop `sessionId` 交下来（ui-session 的 `BUILTIN_SOURCE` 声明 `props: ['sessionId']`）。第一版没用它，而是读 `ctx.get('uiSession').adapter.current`——那是**编辑器当前会话**。两者在常见情况下相同，在唯一要紧的情况下不同：预览来自一个不是当前输入框所在的工作区。那时探测会去问一个看不见这个文件的会话，服务端回「could not identify the session that owns this workspace」——用户盯着文件，却被告知服务器不知道这文件归谁。现在优先用槽位给的 `sessionId`，只在宿主没给（更老的宿主）时回落到输入框会话。

### 为什么是「盖在预览正文上」而不是全屏对话框

第一版是对话框：居中、遮罩、`modalLayer()` portal 到 `document.body`。用户的一句反馈就够了——「点编辑就在文件区里编辑，别弹窗」。这句不是审美偏好：

- 对话框把文件从屏幕上拿走。编辑一个文件时最常需要的参照就是它原来在那儿的上下文（左边是树、上面是路径），而遮罩会把这些一起遮掉。
- 遮罩的每一次误触都是**丢工作**。点外部、按 `Esc`、点遮罩——三个动作原本都只是「离开」，在带未保存内容时却变成「要不要丢掉」的提问，而提问本身已经打断输入了。
- 对话框在浮动的侧栏面板里还要处理 `overflow` 与 `position: fixed` 的包含块问题（`modalLayer` 那段注释解释过为什么要 portal）。就地盖住没有这个问题：它比的是宿主自己的 rect。

实现上编辑器是 `position: fixed` + 一个量出来的盒子（`left`/`top`/`width`/`height` 来自 `getBoundingClientRect()`），而不是往宿主的 DOM 里插一层 wrapper。插 wrapper 会和面板自己的 flex 尺寸打架，而且宿主一 remount 就没了。盒子**盖的是预览的 `[data-textpreview-body]`**，不是整个预览——把头部也盖住，用户就没有退出的按钮了。用 `data-textpreview-*` 而不是 CSS module 的类名：后者是按构建哈希的，换一个宿主版本就变。

**两个祖先陷阱，一个 portal 加一次实测。** `position: fixed` 只在**没有任何祖先建立包含块**时才是相对视口；任何祖先上的 `transform` / `filter` / `perspective` / `will-change` 都会把它悄悄改成相对那个祖先（宿主对 composer 就是这么做的，`.composerSeat { will-change: transform }`）。另外，滚动型祖先会**裁剪**它——侧栏的 `.scrollArea` 会把面板切在面板边缘，坐标再准也没用。两个坑都来自祖先，所以先 `modalLayer()` **portal 到 `document.body`**；它只是 `createPortal`，不是模态——没有遮罩、没有 `role="dialog"`、没有焦点环、没有 `document` 级的 `Esc`。

portal 之后**不再推断包含块，改成实测后自校正**。第一版试过减 `offsetParent` 的原点，那是错的：`offsetParent` 是最近的**定位**祖先，跟固定定位的**包含块**不是同一个问题。结果是减掉了侧栏原点，整个编辑器跑到对话区上面去——用户截图报的就是这个。现在渲染后量一次自己的 `getBoundingClientRect()`，把差值加到 `left`/`top`：不管包含块是谁，这个校正在构造上就是精确的，宿主以后改 CSS 也照样成立。校正量必须**累加当前值**（`want - actual + current`）而不是直接用 `want - actual`，否则第二次测量会来回抖；小于半像素的差异忽略，避免反复重渲染。

量出来的盒子需要跟着变：面板被拖动/展开、窗口 resize、任何祖先滚动，都会让那个盒子移动而编辑器的 props 不变。所以挂了 `ResizeObserver` + `resize` + 捕获阶段的 `scroll`，并且用 `requestAnimationFrame` 合并到每帧最多量一次——一次滚轮手势会派发几十个 scroll 事件，每个都读一次布局就是卡顿。

代价是它不再有 `useDialogA11y` 的焦点环与 Tab 限制。这是**有意的**：一个就地编辑器不该把 `Tab` 从输入里抢走（它要用来缩进），也不该把 `Esc` 从 `document` 上截走（输入框和叠在上面的对话框仍然需要它）。`Esc` 因此绑在面板自己的 `keydown` 上，只在这个面板有焦点时生效。

### 本地路径与远端路径是同一条路

远端 `ssh://…` 与本地绝对路径走的是同一组路由（`read-text` / `write-text` / `edit-text`），只有最内层的读、写、围栏判定分成两支。所以「远端能编辑、本地不能」或者「本地保存不检查冲突」这类分裂在结构上不会出现——两边的校验顺序是同一段代码。

### 双令牌：为什么是 version 和 revision 两个

保存时客户端回传两个令牌，服务端两个都要对上才写：

- `version` 是 `ino:size:mtime`，来自 `stat`，**便宜**——一次元数据往返，不读内容。
- `revision` 是内容 sha256，**贵**——要把整个文件读回来。

两个都查，顺序是先 version 后 revision：绝大多数「别人改过」的情况（换行、插入、删除）会改大小或 mtime，version 一比对就 409，不必读文件。但 version 有它测不出来的情况：**同一秒内、同样大小的改写**。SFTP 的 mtime 没有亚秒精度，`a` → `b` 这种单字节替换在 version 上完全隐形，于是只有哈希能发现它。反过来只查哈希则每次保存都要读一遍整个文件，为了一个罕见情况让常见情况变贵。

两者都不对时服务端回 **409** 并带上当前的 `version` / `revision`，客户端据此显示冲突条。**默认动作是「重新加载」**（读回磁盘上的版本，用户自己决定怎么合并），「覆盖」排在后面且要二次确认；覆盖也不是跳过校验，而是**重新读一次拿到新令牌再写**——否则第二次写会拿旧的期望值去撞同一堵墙，用户会看到一个什么都没做的错误。

没有 `force` 参数，也不打算加。一个能跳过校验的开关，用一次就会变成习惯，而这个功能的全部价值就是「不会悄悄盖掉别人的改动」。

### 行尾与 BOM：读的时候拆开，写的时候原样装回去

读的时候服务端把两件事**分开报告**，而不是在文本里抹平：

- `text` 永远是 LF 归一化、且不含 BOM 的。
- `eol` 是 `'LF'` 或 `'CRLF'`，`bom` 是布尔。

保存时客户端把这两个事实原样回传，服务端按它们重新组装字节。这样做是因为「文件用什么行尾」和「文件有没有 BOM」是文件的事实，不是编辑器的事：一个 CRLF + BOM 的文件，编辑一行之后必须还是 CRLF + BOM，否则在 git 里整文件都变了。`eol: 'auto'` 是默认值，意思是「用磁盘上现在的风格」；显式传 `'LF'` / `'CRLF'` 才会改。底部那个行尾下拉就是**保存策略选择器**：`自动（LF/CRLF）` 显示磁盘当前风格，选 `LF` / `CRLF` 后下一次保存按选定值写；只改行尾也算未保存改动，切标签随草稿保留，保存成功回到 `自动` 并采用服务端回传的**实际**行尾。

`detectLineEndings` 与 `restoreLineEndings` 是**与 `editText` 工具同一份实现**（从 `lib/fs/remote-fs.js` 导出），不是路由层另写一套——两份实现迟早会在某个边界上分歧，而分歧的表现是「用编辑器保存会改坏行尾，用工具不会」。

### 大文件与截断

超过 2 MiB 的文件不给编辑入口（`EDIT_MAX_BYTES`）。介于「读得下」与「太大」之间的文件如果被截断读取，`revision` 是 `null`——截断的内容算出的哈希会声称它见过整个文件，那是假证据；而写路由要求 revision 是字符串，所以截断的文件**在协议层面就无法保存**，不靠客户端自觉。

### 编辑器内核：按需加载的 CodeMirror

`textarea` 能编辑，但它的上限不在颜色而在输入本身：没有多级撤销之外的历史、没有按词移动、折行后按行移动光标要靠浏览器、大文件的合成层也不是为编辑器写的。所以内核换成了 **CodeMirror 6**，但只在**能拿到它的 chunk 时**换：

- 文件先按原路径读出来、先上屏，然后面板才用 `require.async('./client.editor-engine.js')` 去取引擎。读文件与取引擎互不等待：慢的是文件，不是 744 KiB 的 chunk；反过来，为一个用户随即关掉的预览去取引擎也不值得。
- 引擎 chunk 未到、离线、缓存未命中或产物没提交，都继续用 `textarea`。失败结果被**记住**（一个 rejected 的 promise 只打一次），不会在每次 render 重试；这条路径不是「降级到不能编辑」，而是「降级到另一个能编辑的编辑器」。
- 引擎的保存 / 查找 / `Esc` 不自己实现，回调进面板自己的策略（`handlersRef`），所以两套编辑器的键位语义是同一份代码，不会出现「引擎里 Esc 关面板、回退里 Esc 关查找条」这种分裂。

产物是 `lib/client/client.editor-engine.js`（744 KiB，含 CM6 与 15 种语言的解析器），由 `npm run build:editor` 从 `editor-engine/engine.js` 构建。**其余手写 chunk 不受影响**：仍然没有 bundler、没有构建步骤，只有这一个文件是产物；`npm run check:editor` 重编译并比对，产物与源码不一致就红，已并入 `npm run check`。

构建方式有一个宿主特有的坑：宿主的 chunk 是被**求值**的（`new Function` 之类），不是 `import`，esbuild 的 IIFE 顶层 `var` 不会出现在 `window` 上。所以尾巴是先 `window.__sshwsp_engine = __sshwsp_engine`，再 `__ModuleLoader__.load({ chunk: 'client.editor-engine.js', factory: () => window.__sshwsp_engine })`——没有第一句，factory 返回 `undefined`，面板会以为引擎加载失败而悄悄退回 `textarea`。

主题不新增第二份：引擎的高亮样式与配色全部引用 `--sshwsp-hl-*`，所以下面那套深浅调色板（含 `data-ds-theme-source` 的判定与逐色对比度断言）对引擎和颜色层同时生效。

### 多标签：文件不随按钮消失

编辑按钮挂在**某个预览**上，面板随预览卸载；如果打开的文件只活在这个面板的 state 里，点另一个文件的编辑按钮就等于换掉上一个（包括它的未保存内容）。所以标签与草稿存在**模块级、按会话分组**的 `createTabStore` 里：

- 打开的文件进一条标签带；再点别的文件的编辑按钮是**加一个标签并切过去**，不是替换。
- 切换标签**先看草稿再看磁盘**：切走的脏 buffer 存在 store 里，切回来原样恢复；草稿只在「正文 ≠ 磁盘」期间存在，保存成功即删除——否则一个干净标签重开时会拿到旧草稿而不是文件本身。
- 关闭标签脏了才问；关掉当前标签时右邻顶上、末尾取左邻、全关收起面板。
- 保存不再顺手关面板：有标签之后，「保存即关闭」等于每个文件只能写一次。已保存的提示留在原地。
- 标签带**横向滚动而不换行**：第二行标签会把正文整体下移一行，正在读的那行跳一下比藏起一个标签更糟。
- 标签带**不声称是 `tablist`**：容器是 `role="group"`，当前文件用 `aria-current` 标出。没有 roving tabindex、没有 `tabpanel` / `aria-controls` 就不假装实现 APG——一个半实现的 tablist 给读屏的语义比没有更糟。完整的 ←/→/Home/End 漫游是独立事项。
- 保存成功 / 失败的提示是 `role="status"` 的实时区域，读屏能听到；冲突条是 `alertdialog`，另有 `aria-labelledby` 指向标题。

### 语法高亮：窗口化的颜色层（引擎不可用时的兜底）

引擎到位后，颜色由解析器给；下面这套覆盖层是**没有引擎时的兜底**，两者共用同一套 CSS 变量，所以配色不会因为走哪条路而不同。兜底的颜色来自盖在 `textarea` 下面的一层覆盖层（`HighlightLayer` 渲染的 `.sshwsp-editor-hl`）：`textarea` 继续负责选区、撤销、输入法和按词移动，覆盖层只把同一段文本再画一遍，按 token 上色。这样做的代价不是性能而是**像素对齐**——两层的字体、字号、行高、`tab-size` 与内边距原点必须逐项一致，否则彩色字会和透明字错位重影。所以 `client.styles.js` 里 `.sshwsp-editor-hl-line` 与 `.sshwsp-editor-area` 的这五项由 `file-editor-smoke` **互相比对**，改一处而不改另一处会当场变红。

引擎那条路上的行号栏（`.cm-gutters`）是**不透明**的：CodeMirror 把它 `position: sticky` 钉在左边，正文（关掉「自动换行」时）从它底下横向滚过，底色一旦透明，长行就直接压在行号上、两行字叠成一团。所以它取 `--sshwsp-gutter-bg`——右侧面板里是面板自己的 `--sshwsp-surface`，会话内联（铺在会话底色上）时是 `--sshwsp-bg`；兜底那条路的行号是独立的一个 `<pre>`，天然不会重叠。

行号与正文之间留出**一段空隙**（`.cm-gutterElement` 右内边距 14px，正文自己不再缩进）：行号位数是会变的（1 位到 6 位），紧贴着正文时三位数就已经顶到第一个字符，读起来像「12foo」。数字右对齐、空隙固定，位数变化只往左长。

覆盖层是**窗口化**的。2 MiB 缓冲区约 6 万行，整份重绘或每次按键整份重新分词，代价比颜色本身大得多。所以只画视口附近的行：每行绝对定位在 `行号 × EDITOR_LINE_HEIGHT`，整个块按 `textarea` 的 `scrollTop` / `scrollLeft` 做 `translate`，滚动时每帧最多更新一次且只改 transform。缓存的是**每行进入时的扫描状态**（是否在块注释 / 模板串 / 代码块里），不是整份 token：编辑时用首个差异行截断缓存，于是敲一个字只需要重新扫视口那几十行。

会让颜色**主动关闭**的三种情况，都是「画了反而错」而不是「少画一点」：

- **换行模式**：`textarea` 折行后行号不再是像素位置，按行绝对定位的窗口就对不上，所以换行时把字形还给 `textarea`、不画颜色层。
- **输入法组合中**（`compositionstart` → `compositionend`）：组合中的文字此刻只存在于 `textarea` 里，覆盖层画不出来；这段时间恢复 `textarea` 自己的字形。
- **超过 512 KiB**（`HIGHLIGHT_MAX_CHARS`）：再画下去每次按键的代价就与文件大小成正比了。

默认不换行、不组合、文件不大时，`textarea` 的正文是透明的（`color: transparent`），光标用 `caret-color` 单独指定（它默认跟随 `color`，不指定就看不见了）；选区背景刻意用半透明色，否则选中的一段会把下面的彩色字整块盖住。

token 颜色全部走 CSS 变量（`--sshwsp-hl-keyword` 等），所以换肤不需要碰分词器。默认一套深色调色板；浅色调色板认宿主真正发布的标记——`data-ds-theme-source="light"`（显式浅色偏好），或 `data-ds-theme-source="system"` 且系统是浅色。**不能只认 `prefers-color-scheme`**：那是桌面的偏好，而「深色应用跑在浅色桌面上」很常见，跟着系统走会在深色面板上画一套浅色字。`data-theme="light"` 留给用普通标记的宿主，宿主什么标记都没发布时才退回系统偏好。

两套调色板都按各自背景量过对比度：`file-editor-smoke` 用 WCAG 公式逐色算，低于 4.5:1 就红。这条不是形式主义——One Light 的字符串绿在白底上只有 3.1:1，同一角色在深色下却有 6.3:1，直接照搬会让浅色主题的小字号代码发灰；浅色那套因此把字符串、类型、函数、属性、常量、链接各压深了一档，色相不变。

分词器只看当前行加跨行状态，不做完整解析，所以有两处构造必须靠上下文猜，而猜错是**看得见**的：JavaScript 的 `/`（`= /re/`、`return /re/`、`(/re/)` 是正则，`a / b` 是除法，`++` / `--` 之后的 `/` 也按除法算）与 Rust 的 `'`（`'a'` 是字符字面量，`&'a str` 是生命周期，区别只在名字后面有没有闭合引号）。判错的代价是整行变色——`/ab"c/` 里的引号会被当成字符串开头，把后半行染成一片——所以规则是「拿不准就不染色」：找不到闭合的 `/` 或 `'` 时退回标点。

**扩展它是一次改数据**：C 系语法只是 `LANGUAGES` 里的一个表项（后缀、关键字、注释符、引号），不是 C 系的（Markdown、HTML/XML）各有一个扁平行扫描器。分词器是纯函数、不认识 React，这层与已落地的 CodeMirror 6 引擎无关：它是无引擎兜底时的高亮路径，解析器切换不影响保存与冲突逻辑。

### 交互细节

- `Tab` 插入两个空格（引擎里由 `indentWithTab` 做，兜底里走 `document.execCommand('insertText')`——后者直接改 `value` 会清空浏览器的撤销栈，按一次 `Ctrl+Z` 就丢掉整段编辑）。`Shift+Tab` 反缩进。
- `Ctrl/Cmd+S` 保存并 `preventDefault`（否则会弹出浏览器的「保存网页」）。`Esc` 关闭，但**只在没有未保存内容时直接关**，有内容时先问一句。这个 `Esc` 挂在面板自己的 `keydown` 上，不是 `document` 的捕获阶段——就地编辑器不该截走输入框和叠在上面那层对话框的 `Esc`。
- 保存期间敲的字不会被吞：成功回包只把「已保存的基线」推进到刚发出去的那份文本，**不覆盖正文**。用户在第 3 行还在打字时点了保存，回包之后那几笔输入仍然在。
- 正文 `textarea` 是编辑器里**唯一**的滚动容器，行号栏跟着它的 `scrollTop` 走。两个独立滚动条会在滚轮落到错误的那一个时立刻错位，而行号错位比没有行号更糟。面板自己 `overflow: hidden` + `box-sizing: border-box`：盒子是量出来的视口像素，边框和内边距再加进去就会溢出到面板之外。
- 自动换行是个开关（`localStorage` 记住），默认关——代码按行读，硬换行会把一行折成好几行，行号就对不上了。

## 右侧「文件」树的多选

多选做在**宿主自己的「文件」标签页里**，不需要打开任何插件标签页或对话框。那棵树的 store 没有选择模型（既没有 `selected`，也没有修饰键处理），插件也不拥有它的行节点，所以插件不改它的 JSX，只做四件事：

1. 给行加 `.sshwsp-tree-row-selected` / `.sshwsp-tree-row-cursor` 两个**自有类**——不碰宿主类名，宿主改样式不会让高亮消失；
2. 给行写 `aria-selected`，给行内按钮写 roving `tabindex`；容器写 `aria-multiselectable`；
3. 用 document 捕获监听读取 `data-files-entry` / `data-files-path`，把手势喂给**同一个** `selectReduce`；
4. 宿主重渲染后由 `MutationObserver` 重新同步；宿主移除行或换根时，选择按「只能声明看得见的行」修剪；宿主把非活动标签的 body 整个卸载时，选择还要**跨重挂载**存活（见下）。

**关键在冲突**：普通单击目录照常交给宿主展开；Ctrl/Shift 命中目录时 `selectReduce` 返回 `navigate: null`，桥就据此刻在捕获阶段吞掉这次点击。于是「选择优先、导航让路」只有一处判定，不在两个 handler 里各写一遍。

**普通单击文件仍要打开它**。多选是叠加在原习惯上的，不是替换：单击文件返回 `navigate: index`，既选中该行（成为后续 Shift 的 anchor），也把这次点击放行给宿主去打开预览。只有带修饰键的单击才吃掉导航——否则「看一个文件」会从一次点击变成两次。

**选择要跨标签页重挂载存活**。打开文件会切到预览标签，宿主随即把 Files 标签的 body **整个卸载**（`keepMounted` 是 opt-in，Files 类型没有声明），`[data-files-body]` 容器换成一个新的——如果选择只挂在容器上，用户「打开一个文件再回来按 Shift」就只剩单行。所以选择按「会话 + 工作区根」记进 `treeSelectionScopes`，且**锚点存路径而不是下标**：新容器挂载时先恢复 ids 与 anchorPath，根列表晚一帧到达也能在下一次同步里把锚点解析回来。切根时旧根与新根的记忆都清掉；空列表（还在加载）不按「看不见的行」修剪，否则恢复出来的选择会在加载完成的瞬间被清空。

| 手势 | 结果 |
| --- | --- |
| 单击目录 | 宿主照常展开 / 进入；选择清空、anchor 重置 |
| 单击文件 | **既选中它，也照常打开**（导航放行）。「查看文件」选为「会话中查看」时，普通单击改为在会话窗显示（见下节）；`Ctrl/Cmd+click` 仍开右侧预览 |
| Ctrl/Cmd+单击 | 切换该行；**命中目录只选中、不进入**（这一次点击被吞掉） |
| Shift+单击 | 从 anchor 到该行的连续区间；**命中目录只选中、不进入**；anchor **不**更新 |
| Ctrl/Cmd+Shift+单击 | 把该区间追加进现有选择 |
| 右键（选择之外） | 选择**收拢到该行**再出菜单；不打开、不导航 |
| 右键（选择之内） | 保留整批选择再出菜单；菜单文案不变，**目标**是整批 |
| Ctrl/Cmd+右键 | 切换该行后出菜单 |
| Shift+右键 | 从 anchor 扩区间后出菜单 |
| 单击空白 / Esc | 清空选择（Esc 保留键盘光标） |
| Ctrl/Cmd+A | 全选（含目录） |
| ↑/↓、Home/End | 移动光标并选中；Shift 扩展区间；Ctrl+↑/↓ 只移光标 |
| Enter | 打开光标所在目录 / 文件 |
| F2 / Delete | 重命名 / 删除光标所在行（与行菜单同一组动作） |

- **右键先归位，再弹菜单**：`point` 动作在 `openTaskMenu` **之前**执行（守卫 `if (container !== null)`），所以菜单渲染时读到的已经是这次右键该有的选择——菜单不该读到上一次点击留下的集合。
- **锚点属于工作区，不属于这一次 DOM**：打开文件、切去预览标签再切回 Files，容器已被宿主重建，但 Shift 仍从原锚点扩区间；锚点是路径，根列表重新异步加载也不影响。
- **视觉**：选中行背景高亮，光标行描边；**任何行都不渲染复选框，也没有“选择模式”开关**，树的下方**不浮出批量条**。
- **一个动作只有一个文案**：菜单里删除永远是「删除」、下载永远是「下载到本机」，**不随选择数变化**，也**不带数字**。以前这里有两套：只作用于右键那一行的删除，和作用于选择的「下载所选（N 项）」。两套文案就是两条代码路径，数字还算自**另一个**数组——菜单能承诺三行、却只删掉一行。现在两者都只有一个动词。
- **目标是算出来的，不是猜出来的**：`resolveTargets(clickedRow, selection)` 是唯一判决点——选中集包含该行且不止一项时，目标是整批；否则**先把选择收敛为该行**再返回。收敛发生在菜单弹出**之前**，所以「屏幕上高亮的那几行」永远是「接下来会被操作的那几行」。
- **数量搬到确认框与目标对话框**：菜单不说数字，破坏性动作在动手前说清楚。删除确认框按目标数换标题（一个文件 / 一个目录及其下 N 项 / 空目录 / N 项），正文给出目录与文件的**分项计数**（选中目录会递归数到 `DELETE_COUNT_LIMIT = 200` 项为止，触顶标 `200+`；本地目录不冒充远端、标「未知」；列目录失败仍允许确认，只是没有数字）。**确认框先出现、数字后到**：数一棵目录要一串 `/ls` 往返（真机上 27 个目录的一棵树要四十多秒），等数完再弹框就是一个看起来死掉的按钮。所以标题先用**选择本身**能回答的话（一个文件 / N 项）开框，单目录先开成「删除该目录及其下的全部内容？」，正文那一行写「正在统计目录内容…」，数完就地把同一批节点改写成分项计数，单目录的标题再精确成「…及其下 N 个文件？」——只开一个框，从不再开第二个。下载没有破坏性确认，因此数量写在两处：目标目录对话框副标题「将下载 N 项到本机」，以及入队后提示「已加入队列 N 项」。
- **批量下载只问一次位置**：目标超过一项时先确认并选**一个目标目录**，再整批入队。取目录按可用性回落，四种结局各有去向：

  | `pickDirTarget` 结局 | 怎么来的 | 队列怎么落盘 |
  | --- | --- | --- |
  | `handle` | 浏览器 `showDirectoryPicker()` 给了可写目录句柄 | 客户端流式写入该句柄 |
  | `path` | 选到了路径：桌面壳优先走 preload 桥 `__DSH_DIRECTORY_PICKER__.pick()`，页面选择器缺席或被拒时才问 `uiWorkspace.pickDirectory()` | `POST /transfer` 的 `recursive` 下载，服务端直接写到该路径 |
  | `canceled` | 用户关掉选择器（异常文案匹配 `/cancel\|abort\|dismiss/iu`） | 整批取消，**不**退化成逐个弹窗；并发一条中性提示（见下） |
  | `unsupported` | 两种选择器都没有 | 逐项回落到单文件保存对话框（旧行为） |

  `showDirectoryPicker` 存在但**被拒绝**（非 `AbortError`，如跨域 iframe 的权限策略）时也回落到宿主选择器，而不是当作取消。
- **先问桌面壳，再问页面**：`window.showDirectoryPicker()` 是 Chromium 的接口，在 Electron 壳里窗口刚打开时，第一次调用出现过「对话框已弹出、文件夹已选中、仍回 `AbortError`」——这一条 abort 被当成取消，整批静默返回，正是本轮修掉的真实故障。顺序因此是：桌面壳 preload 桥 → 页面 `showDirectoryPicker()` → `uiWorkspace.pickDirectory()`。桥拒绝（非取消）不算取消，继续往下试。
- **取消不再静默**：批量入口走到 `canceled` 时发一条**中性** toast（第三态 `muted`：不染成功绿、不染失败红、`role="status"`、不抢焦点、仍 7 秒消失），文案 `transfer.pickCanceled`。此前这是整条路径上唯一「什么都不发生」的分支，看起来像按钮坏了。错误态则按「顶部提示（toast）」表：带诊断码与原始错误、可展开 / 复制，只有可安全重放的动作才出现「重试」。
- **取消是真的取消**：`localDir` 那条路要等整个目录写完才返回，所以取消是**轮询**（150ms）`ctx.isCancelled()` 后 `controller.abort()`，中止请求即让服务端停止遍历；`finally` 里清掉定时器。等服务返回再检查等于「点了取消也拦不住」。
- **降级**：宿主换了行属性名（`data-files-entry` / `data-files-path`）时，桥找不到可选中行，表现为「点击没有选中效果」，不会报错、不会破坏宿主。

## 会话窗里的文件预览

「查看文件」有两个落点，二段式切换在插件面板「设置」→「文件查看」里；默认「右侧文件树」，就是宿主原来的行为，升级不改变一次点击的去向。

- **接管是谁做的**：还是多选那条捕获桥。归约器判定这次单击会导航（`navigate` 非空）之后，桥才读偏好；`conversation` 且目标是文本类文件、没有 Ctrl/Cmd/Shift/Alt 时，它在捕获阶段 `preventDefault` + `stopPropagation`，宿主的 React 处理器根本收不到这次点击。`Enter` 在 `activateTreeRow` 之前走同一判定，否则那条路径会绕过桥直接开右侧预览。
- **哪些文件不接管**：只有「已知二进制」（`viewerOf` 返回 `binary`）留给宿主，例如 zip、Office、字体。图片、音视频、PDF 由查看器表接管，未知后缀先接管再读 4 KiB 判定（见「认不出的后缀」）。判定必须发生在读盘之前——接管了却读不出来，等于把一次点击变成一句道歉。`.md` / `.markdown`（以及无扩展名的 `README` / `CHANGELOG`）**在接管之列**，并且打开时就是**排版预览**（见下一条）；`.mdx` 仍按源码打开，因为它带 JSX，而预览器不执行文件里的标记。修饰键点击一律归宿主，`Ctrl/Cmd+click` 因此仍是「这次就开右侧预览」的逃生口。
- **落点**：**每点开一个文本文件，会话顶部标签条（「对话 / 轨迹 / Git 图谱 / billion 上下文」后面）多一个**同名标签**，标签名就是文件名（保留大小写，去掉查询串与尾部斜杠）：`app.ts` 的标签就叫 `app.ts`。**名字撞车时在右侧补一段暗色目录尾巴**——`__init__.py` 与另一份同名文件并排时，两颗标签分别显示成 `__init__.py  …\api`、`__init__.py  …\core`：名字保持原位（宿主渲染的文本始终是裸文件名），尾巴是插件追加的一个 `span[data-sshwsp-tab-dir]`，取「刚好够区分的最短父目录」，分隔符跟随路径本身（远端 `/`、本地 `\`），并用 `direction: rtl` 让省略号吃掉**左端**——要区分的是尾巴的末段。目录名也撞、就再往上一层（`…\a\x` / `…\b\x`）；其中一颗关掉后，另一颗的尾巴自动消失。**判定读的是按钮的正文而不是 `textContent`**：尾巴与 `×` 都是插件追加的兄弟节点，`textContent` 会把它们粘在名字后面（`index.ts…/src×`），于是「哪个文件」当场对不上——这正是尾巴在同胞被关掉后赖着不走的根因。名单是每次渲染现读的，所以标签名始终是「当前开着什么」的函数。**悬停给出完整路径（自绘提示条）**：标签固定 **132px**，长名字按省略号截断；标签上不设 `title`（浏览器原生提示在深色主题下是一个系统黑框，样式改不了），悬停 320ms 后由插件自己画一条提示：圆角与 0.5px 描边跟面板一致，文字是 `displayPathOf` 统一拼法后的完整路径（`ssh://` 前缀与远端路径用 `/`，本地路径用 `\`），提示的**上沿固定在标签底边 + 8px**，**左沿落在指针右侧 14px**（视线已经在指针上，居中会盖住正在读的名字），向右放不下时夹到视口内；只有标签贴近窗口底部、下方放不下时才翻到上方；滚动或缩放即消失。宿主自己的标签提示在这里被**拦掉**：宿主的 `ViewTabLabel` 只要标签文字超过 88px 就会挂上它自己的 Tooltip，文件标签几乎必然超，于是两条提示会叠在一起；插件在 capture 阶段吃掉 `pointerover`（React 的 `pointerenter` 就是从它合成的），点击切换标签不受影响；另加一道门——悬停文件标签期间给 `body` 打 `data-sshwsp-tab-hover`，样式里据此隐藏宿主的 `[role="tooltip"][data-side]` 气泡（React 也会从「离开别的元素」的 `pointerout` 合成 enter，那条事件不归我们拦）。多个文件可以同时开着、互相切换，每个标签各自的滚动位置、草稿与未保存状态互不影响。标签是**懒注册**的：第一次点开某个文件才注册，关掉它之后注销，所以从没开过文件的会话不会多一个空标签，也不会留下一个名字已经不代表内容的标签。同一个文件再点一次不会注册第二个，只是切回它已经开着的那个标签。
- **位置**：文件标签注册时带 `order: 100`，宿主的 `viewTabs()` 按这个数排（「对话」0、「轨迹」10、「Lineage / Stats」40），所以文件标签**总是排在所有内置视图之后**；`conversation.view` 的条目没有 `order` 时会被当成 0，紧跟在「对话」后面——那正是这一版之前的错误位置。
- **激活**：注册完立刻**点一次那颗标签**（`[role="tab"]` 里文字等于文件名的那个按钮）。宿主的标签 DOM 没有 data-id，所以插件先用自己打的 `data-sshwsp-tab-path` 认，第一次还没有时按「同名标签里的第 n 个」认——n 等于注册顺序，同名但不同目录的两个文件因此不会互相串台（最多重试约 1.2s 等注册后的首次渲染）。宿主标签的 `onClick` 才是受支持的切换路径——它同时激活该视图的装配目标并写入会话的 `view`，只调其中一个都不会让内容出现。标签条按宽度决定多少标签留在行内，窗口很窄时它会被收进「更多」菜单，那时由插件打开菜单再点同名项。
- **关闭**：宿主的标签没有关闭按钮，所以插件用 MutationObserver 给每颗文件标签尾部注入一个 `×`（`span[data-sshwsp-tab-close]`），点它就是关这个文件；`Esc` 等价。两者都会先询问未保存改动。`×` 是**绝对定位在标签右侧**的（`right: 4px; top: 50%`），文件标签也统一取**固定宽度**（132px，其中 22px 留给 `×`）：宿主的标签是按名字自适应的，手加的 `×` 会让行高多出一行，名字长短不一时整条标签行还会跟着抖。关掉一个文件只收掉它自己的标签并把会话落到仍开着的那个文件上；关掉最后一个文件标签时才切回「对话」，不留一个空视图。切回「右侧文件树」偏好时会一次性收起所有文件标签。
- **右键只关文件标签**：文件标签上右键给出三项——`关闭`、`关闭其他文件标签`、`关闭右侧文件标签`。宿主没有给会话标签做菜单（它唯一那套「关闭其他 / 关闭右侧」属于**右侧栏**，语义是「所有其他右栏标签」，照搬会把别的插件的视图一起关掉），所以这套菜单由插件自绘：同一个 `renderMenuDom`，和文件树的行菜单同一副长相、同一套键盘规则。「其他」与「右侧」的名单取自**插件自己的会话名单**（`sessionOpenFiles`，按打开顺序），不是标签条——被宿主折进「更多视图」的文件标签在 DOM 里只是 `menuitem`、盖不了章，问 DOM 就会把它们漏掉。「对话」、轨迹、其他插件注册的视图从未进这份名单，因此既不出现也永远不会被关。「右侧」读的是标签条自己的顺序——宿主按注册顺序渲染，那就是视觉顺序，插件不再维护第二份排序。批量关闭只问一次未保存（一个对话框写明几个文件），拒绝即整批取消。
- **标签的身份是插件盖的章**：宿主的 `conversation.view` 按钮上没有 view id，只有 `role="tab"` 和文本，所以插件在装饰那一趟把自己写的 `data-sshwsp-tab-path` 打到按钮上，之后一切都按这个属性认（右键、`×`、激活）。第一帧还没盖章时按「同名标签里的第 n 个」兜一次（n 等于注册顺序），且**只对名字唯一的情况**作答——两个 `index.ts` 时宁可不弹菜单，也不猜着关错文件。
- **面板**：文件标签的内容**就是编辑器本身，而不是浮在会话上的一层**——同一个 `FileEditorPanel` 以 inline 模式渲染：不量矩形、不 `position: fixed`、不进 `modalLayer` portal，`flex: 1 1 auto` 直接铺满宿主的 `.viewArea`，背景透明、无边框、无圆角、无阴影，看起来和「对话」视图一样是原生的一屏。文件名已经在标签上，所以面板里不再重复一遍标头与路径，也没有「取消」按钮；正文仍是 CodeMirror 6 + 语法高亮，可编辑、按 `version` + `revision` 双令牌走 `write-text` 保存，别人改过会给出冲突条（重载优先、覆盖要二次确认）；右侧与会话两个面板按 `session × surface` 分开持有，同时打开不互相关闭，草稿共享。未保存状态按「会话 + 文件」分开记：有改动时面板顶上才出现一行「未保存」（干净时连这一行都没有，标签内容就是编辑器本身），此时关这个标签会先确认。焦点在编辑器里时 `Esc` 交给编辑器自己处理（先关查找条），模态对话框打开时也让给它。视图拿到的 props 带 `sessionId`（注册时注入），缺省时依次取 `session.id`、宿主地标 `[data-conversation-session]`。
- **Markdown 默认按排版预览**：文档类文件（`md` / `markdown` / `mdown` / `mkd` 与无扩展名的 `README` / `CHANGELOG`）打开时，面板**右上角**多一颗胶囊形「预览 / 源码」二段切换（极小的眼睛与 `</>` 图形 + 文字，选中一段用强调色底），默认落在**预览**；它在正文之上的薄行里右对齐，不悬在文字上，所以既不挡阅读也不压代码。正文按排版渲染成阅读列（最宽 860px——一行太长会让人找不到下一行的开头），标题分级、代码块、引用、列表（含嵌套与 `- [ ]` 任务框）、表格（按分隔行取每列对齐）、分隔线、行内代码 / 强调 / 删除线都在。`data-sshwsp-mode` 落在面板根上，方便用样式或脚本判断当前模式。**源码模式仍是原来那个可编辑的 CodeMirror 面板**，一切照旧（双令牌保存、冲突条、未保存提示）。两种模式读的是**同一条 `read-text` 路由**，所以预览与源码不会各说各话。**有未保存改动时不允许切到预览**：预览读的是磁盘上的文件，切过去就会显示与标签不一致的内容——点「预览」不生效，胶囊左侧给出原因；先保存或撤销再切。
- **切换沙箱要重载**：iframe 的 sandbox 在导航时定死，改属性不会影响已加载的文档；所以「允许脚本」用 `key` 强制重建帧。沙箱里**没有** `allow-same-origin`（有它 + `allow-scripts` 就等于把宿主页面交出去），因此依赖 localStorage/cookie 的页面在解锁后仍会失败，这是有意的取舍。

**认不出的后缀先读 4 KiB**：后缀只用于快速路径；不在文本表也不在二进制表里的文件（`cts`、`bat`、无扩展名的脚本）先被接管，再按字节判定——是文本就进编辑器，是二进制就给一张说明卡（文件名 + 「在右侧面板打开」的提示），不会因为名字陌生被扔回宿主。

**HTML 页面与媒体不是源码**：一份页面在会话里以 iframe 打开（脚本默认禁用，条上写着「脚本已禁用」，按钮可以临时允许并变成一句警告）；样式与图片是服务端把相对引用改写成字节路由 URL 之后的自然结果，不跑脚本也有样式。图片、音视频、PDF 走同一条字节路由的 `inline=1`：它返回真实 media type 并支持 `Range`，视频因此可以拖动、PDF 可以内嵌；这些类型没有「源码」模式——把 PNG 的字节当文本看不是任何人要的。
- **源码与预览同一栏宽**：预览是「22px 侧距 + 1240px 阅读列」，而内联编辑器默认铺满整个会话宽——同一份文件在两种模式间切换会像换了个应用。现在内联编辑器也收进同一条列（含侧距共 1284px、居中、底部 28px）；「代码 / 预览」两个按钮不再贴着面板右缘，而是同一条列的右缘——按钮右边与正文右边在同一条竖线上，行号栏仍在列内；窄窗口下先压缩自己、不横向溢出。
- **令牌作用域**：会话里的文件面板**不在** `.sshwsp` 面板根之下，所以它一开始拿不到任何 `--sshwsp-*` 令牌——`var()` 解析失败会让整条声明作废，表现就是「文字是默认色、代码块没有底色、表格和引用没有线」。令牌块（深色与 `body:not([data-ds-dark-theme])` 浅色两处）现在都带上 `.sshwsp-filepane`，自定义属性沿 DOM 继承到 `.sshwsp-md`，面板本身也取同一套字体与文字色。`file-preview-smoke` 钉住这两个选择器，防止再有人把面板挪出作用域。
- **预览器的取舍**：渲染由插件自己的 chunk 完成（`lib/client/client.markdown.js`），**不借宿主的 `MarkdownText`**——那个组件的外观来自宿主自己 `import` 的 CSS module（哈希类名在宿主 bundle 里），插件 chunk 拿不到，直接渲染出来是一段无样式的裸 HTML（会话里曾经正是这个样子）。既然样式只能自己写，就照宿主的字阶抄：正文 14px/1.72、标题 32/16 的上下间距、无边框的代码卡、行内代码胶囊、引用竖条、表格只留横线、阅读列宽 1240px，全部走 `--sshwsp-font-*` 令牌。范围按「README 里真的会出现的东西」划：原始 HTML **当文本**（文件来自远端主机，预览不是执行它内容的地方）、相对链接与 `javascript:` 链接**只留文字**（文件在另一台机器上，点了也到不了）、frontmatter 原样框在正文之上（那是 YAML，按 Markdown 渲染只会变成一堆标题）。**图片**会真的显示：`imgSrc` 把 `./img/a.png` 按文档所在目录解析成远端绝对路径，再拼成 `download?alias&path`（那条路由本来就流式、可取消、有体积上限）；别名未知（会话还没出现在 `/status` 里）时退回带 alt 的占位块，而不是一个 `src=""` 的坏图。超过 400 KiB 只渲染开头，并在正文上方说明「完整内容在源码里」——把 2 MiB 一次性解析在主线程上是肉眼可见的卡顿。
- **高度按滚动区算，底栏不跟着滚**：宿主在会话活跃时给 `.viewArea` 写的是 `flex: 1 0 auto`——视图会被自己的内容撑高，整列跟着 `.scrollBody`（`[data-conversation-scroll]`）一起滚，编辑器底部那条「行数 / 自动 (LF) / 自动换行 / 保存」就会被滚出视野。所以这个视图**不按内容定高**：挂载时量滚动容器，高度取到**输入框那条带子的上沿**为止——先认宿主的座位 `[data-composer-seat]`，认不到再退回输入卡 `[data-composer-card]`，两者都不可见（被「隐藏输入框」收起时）才用滚动容器的整个 `clientHeight`。这样输入框**显示**时文件视图正好停在它上面、不会钻到卡片底下去，输入框**收起**时文件占满整列。正文字典自己内部滚动，底栏因此永远停在面板底部。`ResizeObserver` 盯滚动容器与那条带子、`window.resize` 兜底，隐藏 / 显示输入框（不改变滚动容器尺寸）由 `applyComposerHiding` 直接回调一次重测；重算走 `requestAnimationFrame` 合帧，低于 180px 时按下限兜底、高于滚动容器时按上限夹住。
- **输入框可以收起来**：输入框**不属于任何视图**——它是视图区下方的一条 sticky 座位，所以文件标签打开时它仍然挂在最底部。设置「文件查看」里因此有一个「文件标签页里隐藏输入框」（默认**开**）：打开时整条输入区（卡片 + 渐隐遮罩 + 内边距）收起，文件占满整列；关掉就保留输入框，可以一边看文件一边接着对话。隐藏是 DOM 级的：从 `[data-composer-card]` 往上找宿主的座位——优先认宿主自己的标记 `[data-composer-seat]`，没有这个标记时才退回「最近的 `position: sticky|fixed` 祖先」——给它打 `data-sshwsp-composer-off`，由样式表 `[data-sshwsp-composer-off] { display: none !important }` 收起——按行为而不是按宿主的 CSS module 类名认，宿主改名也还成立。视图挂载 / 卸载与这次设置变化都会重新判定一次，关掉文件（或切回「对话」）时立刻恢复。
- **状态不持久**：每个会话一份内存记录，刷新即消失；不写 session event。偏好本身写入 `dsh-ssh.json` 的 `preferences` 节（与 `forwards` / `passthrough` 同一种 store 通道），由面板 `POST /preferences` 写、`/status` 下发，坏值在读入时落回默认。
- **标签跟着会话走**：宿主的 `conversation.view` 是一份**插件级**注册表，名字上却按会话渲染——不额外处理的话，在 A 会话打开的文件会出现在 B 会话的标签条上。所以插件维护一份 `sessionOpenFiles`（会话 → 打开过的文件，关掉才移除），而 `openFileTabs` 里**只放当前会话的注册**：会话地标 `[data-conversation-session]` 一变就切名单——把上一个会话的注册全部 dispose（**只是注销，不是关闭**，路径仍留在名单里），再把新会话开过的文件按原顺序注册回来。标签 id 由路径算出（FNV-1a），所以切回来注册的还是同一个 id，宿主自己记的 `view`（按会话存在 localStorage 里）又能解析到它，切回来直接就是原来那个文件。
- **换工作区会把会话壳整个换掉**：那时地标是随着一棵**新子树**一次性插入的，只听属性变化的观察器永远收不到。所以 `MutationObserver` 同时盯属性和子树重建；子树那条按 `requestAnimationFrame` 合帧，名单为空时 `syncSessionTabs` 直接返回，安静时没有开销；地标元素缓存起来（`isConnected` 就复用），正常一次判定只是一次属性读取。
- **座位被重新声明时只丢句柄、不丢名单**：宿主一旦重新声明 `conversation.view`，注册在里面的条目会被它全部 dispose。`deregisterFileTabs()` 因此只清 `openFileTabs`、把 `registeredSessionId` 归零，`sessionOpenFiles` / 每个会话「最后看的是哪个文件」/ 未保存标记都留着，等新座位（或下次回到这个会话）再注册回来；只有切回「右侧文件树」偏好或插件卸载才整份清空（`closeEveryFileTab`）。
- **同一组设置里的第三个开关**：「同时列出目录里的文件」不改变点击去向，只改变两个目录 picker 的列表内容（见「浏览目录对话框」一节）。它和上面两项共用一条 `POST /preferences`，所以面板上一次保存、点击桥与 picker 下一次读取看到的是同一个值。

## 行菜单、重命名与删除

行菜单先是一份**描述数组**，再是像素。`rowMenuModel` / `blankMenuModel` 产出 `{ id, label, glyph, disabled, reason, danger, separatorBefore, run }`，`openTreeMenu` 把它交给 `renderMenuDom` 画成插件自己的浮动菜单。**只有一个渲染器**：这里曾经把同一份模型交给宿主的 `ctx.contextMenus` 画，结果是同一次右键——本地工作区里的文件、远端工作区里的文件——长出两种长相：前者是宿主的菜单壳，后者是插件的。菜单属于插件，所以现在一律自绘，宿主侧不注册任何 provider（宿主给别的 target 画的菜单不受影响）。加一项仍然只加一条 descriptor。

只读策略**不阻塞打开**：菜单先画出来（全部可用），`policyOf(claim)` 的答案回来后才把四个写动作就地 `disabled` 并把理由写进 `title`；查询失败不降级成拒绝，服务端仍是最终边界。答案按「会话 + 根」缓存 30 秒，连点两次只发一个请求。

菜单**按宿主自己的行菜单度量**，而不是一套更紧凑的尺寸：宽度随内容取，下限 144px、上限 360px（宿主同样以这两档夹住），外边距 4px、**行高最小 34px**、内边距 6px 8px、标题字号 13px / 行高 20px、项圆角 12px、整张浮层圆角 16px（`--sshwsp-radius-lg`）、分隔线 0.5px 且左右各缩进 8px、图标 14px 且取宿主的菜单图标色（`--dsw-alias-menu-icon`）、禁用项不透明度 0.4。理由不是照抄：同一个手势在两侧文件树里都存在，菜单应该读起来像同一个产品的一部分，贴近宿主的度量是唯一能让「右键」不换来两张脸的办法。宽度随内容后，定位不能再按固定 220px 夹右边界，`openMenuAt` 会先挂载再量 `getBoundingClientRect().width` 再夹（常量只留作尚未布局时的兜底）。
单行布局、**去描述行**、**最多 8 项**、**最多三组分隔线**（「下载到本机」、远端目录的「新建文件 / 新建文件夹」与「重命名 / 删除」各占一组）这些没变。少掉的第二行原本放完整路径与「同名覆盖」说明：行本身已经写着文件名，那段文字在重复行而不是解释动作；覆盖策略改由 `title` 提示。**图标随动作区分**：添加到任务、复制路径、新建文件、新建文件夹、重命名、删除各用独立线条图形，下载 / 上传仍共用托盘箭头；图标列不再把四个动作都画成一个文件 / 文件夹，动作不必先读标题才能分辨。图形取的是**一张合并表**：`menuGlyphTable()` 把 kernel chunk 里的动词图形（`MENU_GLYPH_PATHS`）与 icons chunk 里的托盘箭头（`TRAY_ARROW_PATHS`）按「后者优先」合并，菜单按名字取图，取不到就回落到文件图形——看起来正常，所以「模型点了名、表里漏了」只能靠测试拦住（`tree-menu-model-smoke` 从模型反推名字集合与这张表比对）。**「新建工作区」选择菜单是唯一保留两行的菜单**（描述正是它存在的理由），宽度 250px、标题保持 13px 且加粗，通过 `.sshwsp-flowmenu-roomy` 修饰；它同时放宽了「内容定宽」与「单行省略」，否则描述行会被 `text-overflow` 吃掉。

行菜单里的「重命名」「删除」对远端行与本地行都出现，走同一组 `POST /rename` 与 `POST /delete`。**「新建文件」与「新建文件夹」都只对远端目录出现**，与它们同一组，分别走 `POST /create-file` 与 `POST /mkdir`，请求父目录路径 + 名称：名称必须是单个路径段，目标已存在答复 409，越界 / 只读 / 停用均在写盘前拒绝；成功后重新列目录并选中新行。新建文件建出的是 0 字节文件，不自动打开（内容交给编辑器）。本地目录行没有这两项——本地新建的唯一入口是空白处菜单（两项都在），两条入口不重复。路由本身有本地分支（`path` 的拼写决定分支，边界只取自会话的工作区根，客户端的 `root` 只用于识别会话，且 `realpath` 父目录防符号链接逃逸），由空白处菜单驱动。`create-file` 的远端分支用 `'wx'` 独占创建、本地分支用 `open(..., 'wx')`：先查后写只是把「已存在」变成 409 而不是 500。菜单本身支持方向键 / Home / End / Enter / Escape，新项不额外做鼠标专用入口。

- **重命名在行上做**（参考 Better Sidebar）：F2 或行菜单「重命名」把文件名**原位**变成输入框，不弹模态框。输入框 portal 到 `document.body`（`.sshwsp-inline-rename`，`position: fixed`，z-index 1400），按名字 span 的 `getBoundingClientRect()` 定位；名字 span 取 `button` 内**最后一个有文字的 `<span>`**，不依赖宿主 class。
  - 提交语义三态由 `inlineRenameDecision(original, typed)` 判定：trim 后为空或等于原名 → `cancel`（不发请求）；`localNameRefusal` 拒绝（含 `/` `\`、`.`、`..`）→ `refuse`；否则 → `commit`。
  - Enter 提交；**被拒绝时输入框保持打开**并设 `aria-invalid="true"`（边框转红），而不是关掉让人重来一遍；Escape 取消；失焦且内容有改动时提交。
  - `settled` 标志保证一次编辑只提交一次（Enter 后紧跟 blur 不会发两个请求）。失败走 `notifyUser(toastError(describeRenameFailure(err), err, 'SSHWSP-E-RENAME'))`：带原始错误，可展开详情 / 复制，**不提供重试**（改名可能已经部分完成，重放不是幂等）；成功后 `refreshFilesPanel()` 并提示。
  - 只改名不换目录；目标已存在直接拒绝（提示「目标已存在」）；不内联改写宿主树的行——改完仍由刷新重读。
  - 分发器是 `requestRowRename`：`if (row instanceof Element && document.contains(row))` 才走行内，否则回落到原来的模态框（行已被宿主重渲染掉时的兜底）。
- **删除**：确认浮层写明数量、前几个名称与「不可恢复」，目录注明含子目录；确认后逐项执行，单项失败不隐藏其余结果；汇总「已删除 N 项 / M 项失败」。Delete 键与 F2 触发同一动作。
- **只读与无法定界时直接禁用**：菜单打开时向 `GET /mutation-policy` 询问该行的会话模式；`read-only` 下四项置灰并提示「只读会话」，本地路径若服务端识别不出所属会话工作区也置灰（不是点了再拒绝）；策略答案按「会话 + 根」缓存 30 秒，菜单打开时读缓存，未命中就先画全可用、后台再问——宿主渲染的 `resolve` 只有一秒预算，等一次往返就来不及了。`Delete` / `F2` 走同一判定。
- **不乐观更新**：接口返回前不改列表；失败保持原样并给出原因。
- **刷新**：改完由我们发出 `refreshFilesPanel()`；宿主文件树**不自动刷新时**，插件只点它公开的 `[data-files-reload]` 控件（不是私有 API）来重读，不向宿主 DOM 注入节点。目录浏览对话框自己重读当前目录，是可信的回退。

## 表现层：一套令牌契约

样式表开头是一块 `--sshwsp-*` 定义，其余规则只读这套名字。**规则体里不出现裸色值，也不直接读
`--dsw-*`**，只有高亮调色板是例外（见下）。这不只是为了整齐：`var(--dsw-x, #4a9eff)` 里的 fallback
从来不是设计，是当初某个 token 没解析出来时随手写的值，于是同一块面板在应用里和别处颜色不同，
而且**静默**——未定义的自定义属性回落到 `initial`，不是回落到旁边那个字面量。

### 三组令牌

- **跟随宿主**（23 个）：`--sshwsp-bg` / `surface` / `text` / `muted` / `accent` / `danger` / `shadow` / `font` …
  每个都是 `var(--dsw-…, <深色 fallback>)`。fallback 是**唯一**允许写字面量的地方，用途是宿主一个都
  没发布时面板仍然可读。
- **派生**（7 个）：`sunken` / `border-subtle` / `accent-soft` / `danger-soft` / `warn-soft` / `track` /
  `selection`，全部 `color-mix` 出来，不引入新色相。
- **自有刻度**：`radius-*`（映射宿主的 `--dsw-radius-*`）、`focus-width`（映射
  `--dsw-focus-ring-width`）、`font-*`（映射宿主的字号）、`space-1…6`、`z-*`。

### 八个根，而不是一份运行时样式

参照对象 dsh-opencode-go 用 `themeStyle(tokens)` 在每个根上挂 `style`，靠 WeakMap 缓存，再加一个
MutationObserver 跟主题变化。我们没有照抄：根分散在 6 个文件、其中 5 类是 portal，所以改成**一个
选择器列表**（`.sshwsp` / `-backdrop` / `-editor-panel` / `-flowmenu` / `-inline-rename` /
`-popbackdrop` / `-queuepanel` / `-toast`）。属性选择器天然随 `body[data-ds-dark-theme]` 重算，
比参照对象少三个活动部件。

**新增 portal 根必须加进这个列表**。漏了不是语法错误，是那个面板静默丢掉全部令牌——
`presentation-tokens-smoke` 会从源码把根反推出来逐个比对，专门拦这一种。

### 浅色层只覆盖六个令牌

`body:not([data-ds-dark-theme])` 下只重声明 `text` / `muted` / `faint` / `border` / `border-strong` /
`shadow`。其余全部继续跟随宿主——宿主自己会换，我们要修的是**原本就假的 token**，不是长出第二个
主题（`docs/ui.md` 早就承诺过不新增第二份主题）。判定认 `data-ds-dark-theme`，不认
`prefers-color-scheme`：宿主已经替我们判过一次，第二份判定迟早和它分叉。

### 有意的例外：高亮调色板

`--sshwsp-hl-*` 保持 6 位 hex。理由不是审美：`file-editor-smoke` 用正则把这些声明抽出来算 WCAG
对比度，换成 `color-mix` 会让抽取返回空数组、循环 0 次、**断言假绿**。

### 反向验证

守卫测试只对着正确的代码跑过，等于什么都没证明。`scripts/reverse-verify-presentation.mjs` 逐个施加
「把这次做的事删掉」的变异，要求套件变红；留在绿上的变异就是漏洞。它已经抓到过三个：第一版交互态
断言问的是「样式表里有没有焦点环」（一条环就满足所有元素），第一版死规则检查在包含样式表的源码里
搜索类名（命中了规则自己），以及第三个——它没有抓到东西，而是**证明自己缺了一整层**（见下）。它
**不进 CI**，因为会改写源文件再还原。

### 样式表在模板字面量里，所以它必须被真的执行

整个 sheet 是 `tag.textContent = \`…\`` 里的文本，这条路上有一个只改一个字符、症状却指向别处的故障：
注释里一个**未转义的反引号**会提前结束模板，剩下的部分变成**标签模板**：

```text
/* The container is `.sshwsp` itself, so nothing here may style `.sshwsp`:
```

解析成 `` `…`.sshwsp`…` `` —— 合法 JavaScript。于是 `node --check` 通过，`indexOf`/`lastIndexOf`
照样切出完整样式表，所有文本级断言全绿，而 `injectStyles()` 一执行就抛
`TypeError: "…".sshwsp is not a function`；模块系统把它报成 chunk 加载失败，`apply` 没注册面板，
侧栏一片空白。这个 bug 真的发布过一次（`acc6872` 修的）。

**为什么所有 83 个套件都没抓到**：没有任何一个套件**执行**过那段模板。`injectStyles()` 第一行是
`if (typeof document === 'undefined') return`，而 `client-chunk-smoke` 的 chunk 上下文是**故意**不提供
`document` 的（让 apply 期的安装器走 headless 分支）。语法合法但语义错误的模板，没有任何途径变红。

所以 `presentation-tokens-smoke` 现在把真 chunk 放进 `vm`，用桩 `document` 跑它的 factory、调
`injectStyles()`，并要求**它写出来的文本等于断言读的那份 sheet**（差异只有模板用的那一种转义）。
另两条断言直接点名这个错误：sheet 里不得出现裸反引号；转义序列只许有这一种。
