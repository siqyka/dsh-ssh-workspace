# 界面指南

> 定位：插件在 DSH 界面中的全部出入口与交互。

## 「远程工作区」面板

侧边栏面板，注册在 `sidebar.panellist` 插槽，入口图标为服务器图标（`ServerIcon`），标题「远程工作区」。

主机卡片逐条展示存储与 `~/.ssh/config` 回退的全部主机，字段为别名、`user@host:port`、认证方式、来源（store / ssh-config），以及「密钥未就绪」提示（key 认证且 `keyPath` 在本机不存在时）。每张卡片提供：

- **测试连接**：调用 `POST /api/dsh-ssh-workspace/test` 实连一次，**然后释放这条连接**——「测试」回答的是「这台主机是否可达」，不是「替我连上」。结果以页面顶部 toast 呈现（成功附往返毫秒数），成功后数秒（约 3.5 s）自动消失，点击可提前关闭；失败消息同样处理。连接指示点因此不会被一次探测点亮：刷新读的是实际剩下的连接，而不是假定测试留下了一条。
- **断开**：仅在该主机存在池化 SSH 连接时显示（连接状态指示绿点内联在主机名之后）。点击调用 `POST /api/dsh-ssh-workspace/hosts/disconnect` 关闭该主机的池化连接，**并连带拆除该主机上的全部端口转发**（响应里的 `closedForwards` 报告拆了几条，toast 据此改写为「已断开连接，同时关闭 N 条端口转发」）。拆除的结果与在端口转发行上点「断开」**完全一致**：映射保留、意图置为断开、不记任何失败原因——主动断开不是故障，面板不该对它亮红字或提示「下次启动会自动开启」。连接上有操作进行中（进行中数量大于 0）时按钮禁用并给出提示。断开无需确认——下一次操作会按需重连。
- **立即重连**：仅在该主机处于后台重连状态时出现（等待中或已停止）。等待中的下一次尝试可能还有几十秒，`POST /api/dsh-ssh-workspace/hosts/reconnect` 跳过退避立刻试一次；成功显示「已恢复连接」，失败把真实错误放进 toast。主机卡片上的状态文字是「重连中（第 N 次，M 秒后）」/「重连中（第 N 次）」/「重连已停止」，并用黄点与「已连接」的绿点区分——重连中既不是连接正常，也不是刚刚断开。只要列表里还有在重连的主机，面板每 5 秒自动刷新一次，否则倒计时会停在原地（刷新只在浏览器可见时进行，无重连任务时完全停止）。
- **忘记主机密钥**：调用 `POST /api/dsh-ssh-workspace/hosts/forget-key` 清掉该别名的 TOFU 主机密钥记录（需就地确认），用于主机确实重装系统或更换密钥之后——见 [hosts.md](./hosts.md) 的「主机密钥校验」。
- **浏览目录**：打开该主机的目录浏览器（见下节）。它与「新建远程工作区」里的目录选择是**两个不同的组件**（这里是 `DirectoryBrowser`，那里是 `RemoteWorkspaceDialog`）：后者只列目录、只为选路径，前者还带上传与逐行下载。共同点是挂载入口在两边都有——毕竟从主机卡片点进来，多半就是为了挂载。
- **编辑 / 删除**：编辑打开主机表单；删除为就地确认，删除只影响存储条目，不会自动卸载已挂载的工作区。

表单要点：密码与密钥口令**从不回传浏览器**，编辑时留空表示保留原值（见 [hosts.md](./hosts.md) 的「认证与凭据」）；切换认证方式时必须重新填写新凭据。

## 添加工作区双入口

插件占用两个 directoryFlow 插槽：侧边栏的 `sidebar.workspaces.directoryFlow` 与会话页的 `conversation.hero.workspace.directoryFlow`，以负优先级（`-100`）遮蔽部署自带的本地选择器——插槽核心渲染优先级**最低**的占用者，负优先级因此胜出，且不卸载内建实现。

触发后弹出锚定菜单（宽约 300px），包含两行：

- **本地**（FolderIcon）：转交 DSH 原生目录选择器——桌面端走 preload 桥 `__DSH_DIRECTORY_PICKER__`，否则走 `uiWorkspace.pickDirectory()`。
- **远程**（远程标记图标）：打开「新建远程工作区」对话框。

锚定机制：触发按钮不传给插槽占用者，因此插件在捕获阶段监听 `mousedown` 记住最近一次按钮位置（3 秒内有效，避免键盘快捷键打开时菜单"瞬移"），弹出层定位在按钮右侧 8px 处，并钳制在视口内；窗口 resize 时重新定位。点击菜单外部或按 Esc 关闭。

## 浏览目录对话框

点主机卡片的「浏览目录」打开 `DirectoryBrowser`（`lib/client.js`）。它与「新建远程工作区」里的目录选择**不是同一个组件**（后者是 `RemoteWorkspaceDialog`，只列目录、只为选路径），因此两者能力不同：

- 顶部：返回上级、当前绝对路径、**上传文件**（`POST /upload`，原始字节流）；
- 列表：目录在前、按名排序；文件行显示大小并带 **下载到本机**（`GET /download`，流式返回原始字节），目录行没有下载按钮——整个目录不能作为一个文件拉下来；
- 底部：「挂载此目录」——按当前路径创建远程工作区，成功后附**能力提示**（`capabilityNotes`：`rg` / `git` / `inotifywait` 的缺失项，只报探测出的确定缺失）。

首帧路径为 `null`，首次 `GET /ls`（不带 `path`）返回 SSH 登录目录后回填，所以「挂载此目录」永远指向一个真实绝对路径。加载中 / 空目录 / 无法加载是三种独立状态。

上传与下载各有自己的忙碌标记：一次只跑一个传输，第二个点击会被忽略，且**上传失败不会清掉下载的错误**，反之亦然。失败信息常驻对话框内而不是走 toast——对话框开着时用户不会去看页面角落。

## 三个对话框的遮罩关闭（`backdropDismiss`）

`HostEditor`、`DirectoryBrowser`、`RemoteWorkspaceDialog` 三处共用 `backdropDismiss(close)`：判据是**按下与松开都落在遮罩上**，而不是「click 落在遮罩上」。

差别不是学究式的。`click` 的事件目标取**按下点与松开点的最近公共祖先**——在输入框里拖选一段文字、把鼠标拖到对话框外再松开，按下在对话框内、松开在遮罩上，浏览器仍会把 click 派发到遮罩，于是 `onClick: onClose` 会在用户选字的半途把整个流程关掉。按下点才是可靠信号。

四条附带规则，每条都对应一种会回退的行为：

- **只认主键**（`event.button === 0` 才置位）。`click` 从不为副键派发，若不加这道门，「右键按在遮罩上松开」会凭空多出一个关闭动作，而右键本该只弹上下文菜单。**松开侧刻意不设这道门**：touch / pen 的 `pointerup` 在部分引擎里报 `button: -1`，门住它会让触屏点空白再也关不掉。
- **状态写在元素上，且每次 `pointerdown` 无条件覆写**。按下后把鼠标拖出窗口再松手，多数平台根本不派发 `pointerup`；若靠「松手时清理」，残留的「已按下」会漏到下一次手势里，反而在用户从对话框内按下时误关。因为遮罩是祖先节点，来自对话框内部的按下会冒泡到它并把标志覆写为 false。
- **忙碌时关闭被拒**：编辑对话框存盘中、目录浏览器传输中、创建工作区接纳中都不可用遮罩关闭（各自的门禁写在组件的 `dismissBackdrop` 里），否则会把仍在进行的请求连同它唯一的反馈一起丢掉。
- **对话框本身没有 Escape 关闭**。三个组件都没绑键盘关闭，遮罩收紧后唯一的出口是各自可见的「取消 / 关闭」按钮与标题栏的 ×。这是现状而非遗漏：加 Escape 必须处理「下拉框或文件选择器正吞这个键」的先后，需要真机浏览器验证，不在 0.2.5 范围内。

## 新建远程工作区对话框

一次完成"选主机 → 选目录 → 命名 → 挂载"：

1. 拉取主机列表，默认选中第一台；主机列表为空或出错时给出对应空态。
2. 目录浏览：`GET /api/dsh-ssh-workspace/ls?alias=…&path=…` 逐级浏览远端目录，只列目录、按名称排序；提供「返回上级」、加载中 / 空目录 / 无法加载三种状态。
3. **可写探测**：`/ls` 同时回报 `writable`。目录不可写时显示红色警告（"当前 SSH 账号对这个目录没有写入权限……"）并禁止创建——写入能力是 Agent 工作的前提。
4. 创建：`POST /api/dsh-ssh-workspace/mount`，携带 `{alias, remotePath, title, register: true}`。**先注册、后接纳**：挂载路由在宿主接纳该路径之前就按所填名称登记工作区，宿主随后解析到既有记录，避免以派生标题重复建条目。成功后刷新标记数据源，把路径交还吸附链路；对话框在接纳期间保持禁用，背景点击可取消（创建中除外）。

## 远程工作区标记

远程工作区不以文件夹图标示人，而是显示 SSH 标记。DSH 的行图标没有插件插槽，实现为 **DOM 装饰**（`lib/client.js` 的 "Remote-workspace marks" 段），三条原则：

- **React 安全**：从不删除或搬迁 React 拥有的节点——仅通过内联 `style` 隐藏文件夹字形（React 不会重写这些节点的 `style`），在旁插入自带 `data-sshwsp-mark` 的 svg。
- **自愈**：`MutationObserver` 监听 `document.body`，React 重建行节点后自动重新施加替换；工作区不再远程时同样自动还原。
- **身份匹配**：从 live `workspaces` store 的 `getSnapshot()` 取 id / title 集合（服务不可达时退回 `/status` 的 `workspaces` 数组）。侧栏行按工作区 **id** 匹配；选择器菜单行与会话页 hero 工作区按钮只有标题，按 **title** 匹配，hero 在会话刚建立时可能显示路径 basename，故 basename 也计入标题集合。

装饰同时覆盖三处展示：侧栏工作区行、侧栏选择器菜单行、会话页 hero 工作区按钮。

### 停用工作区的置灰

已停用（`detach` 过）的工作区，侧栏那一行会被打上 `data-sshwsp-disabled="1"`，
由 CSS 降到 50% 不透明度并在行尾加一枚 `⏻` 标记，**同时把这一行里的按钮变成不可点**：

```css
[data-sshwsp-disabled="1"] button,
[data-sshwsp-disabled="1"] [role="button"] { pointer-events: none; opacity: 0.4; }
```

置灰只是装饰，真正拒绝点击的是这条规则。一个看灰了却仍能触发「新建会话」「重命名」
「删除」的行是在谎报，用户只有点下去、拿到错误之后才会发现。用 CSS 而不是拦 DSH 的
点击处理器，是因为后者属于和宿主抢控制权，宿主一改版就会崩；选择器写成通用的 `button`
而不是本插件自己的类，是因为那些按钮是 DSH 画的。

**工作区标题那一行本身仍然可点击**：展开分组是看清「停用保留了哪些会话」的唯一途径。
所以规则只落在 `button` / `[role="button"]` 上，不落在标题行上。

**它下面的会话行则整行不可点**——这里的情况相反：会话行本身就是「打开会话」那个控件，
只把它的按钮置灰会把唯一要紧的动作留着。这类行按行键单独作用域：

```css
[data-row-key^="session:"][data-sshwsp-disabled="1"] { pointer-events: none; cursor: not-allowed; }
```

`pointer-events` 只挡鼠标，键盘路径由脚本补 `inert` + `tabindex="-1"`（见
[unmount-modes.md](./unmount-modes.md) 的「置灰」一节）。会话行是 `session:<id>`，
**不携带任何工作区信息**，所以成员关系由 `/status` 的 `workspaces[].sessionIds` 下发。

真正的恢复入口是面板里的「启用」按钮。

身份匹配需要 id 与标题两套集合。这里有个容易踩的坑：`readLiveWorkspaces()` 会从
DSH 自己的 store 重新收集身份，而那个 store **不知道**本插件的停用清单，所以停用
路径单独保存在 `knownDisabledPaths` 里并在每次重新收集时传回去——否则置灰会在
下一次 MutationObserver 回调时消失。

## 面板：已挂载与已停用

「远程工作区」面板把工作区分成两段，互斥：

| 分区 | 内容 | 每行操作 |
| --- | --- | --- |
| 已挂载的工作区 | `/status` 的 `mounted[]` | 「卸载」→ 就地展开确认行 |
| 已停用的工作区 | `/status` 的 `disabled[]` | 「启用」 |

**卸载是两步的**：第一次点击只展开确认行（附带「同时删除工作区记录」复选框），
第二次点击「确认卸载」才真正执行。这个动作会影响到该工作区登记的全部会话，一次点击
就执行不合适。

两种模式的后果**只写在「卸载」按钮的悬停提示里**（`mounted.detachHint`，展开确认行后
由「确认卸载」沿用同一个 `title`）：未勾选则工作区记录与会话都保留、左侧那一行仍在
（置灰）、随时可重新启用；勾选则工作区记录被删除、会话归档。不再在确认行里另起一行
常驻文字——那行说明会随复选框变化而要重写一遍，而提示只需要说清两种模式的区别。

两个模式分别对应什么，是这一段的验收口径：

| 复选框 | 模式 | 侧栏那一行 | 面板这一行 | 会话 |
| --- | --- | --- | --- | --- |
| 不勾（默认） | `detach` | **保留**，置灰且按钮不可点 | 移到「已停用」分区，可「启用」 | **保留，不归档** |
| 勾选 | `deregister` | **删除** | **删除** | 归档，不删除 |

「保留记录却不保留会话」是自相矛盾的：`detach` 留住侧栏那个分组，就是为了让用户还能
点开它；把会话归档等于把分组内容清空——行还在，点开却是空的，比删掉更让人困惑。所以
归档跟随「删除记录」这个勾选，而不是独立开关。

勾选时的「两边都删除」是**必须同时成立**的：删掉工作区记录已经让侧栏那一行消失，
而面板的「已停用」分区由持久化的停用标记驱动——如果只删记录、不清标记，面板会继续
为一条在任何地方都不存在的记录提供「启用」按钮，而运行时围栏又拒绝这个已经无法
再启用的路径。所以 `deregister` 会同时清掉**持久清单**与**运行时围栏**两处标记。

「已停用分区始终渲染」只针对 `detach`：这是用户得知「卸载之后还留了个东西可以
启用」以及「它去哪了」的唯一途径——如果只在有内容时才渲染，第一次卸载的用户会
以为工作区被永久删除了。

已停用行的样式是 `opacity: .62` 加一个「已停用」小标签，**不使用
`pointer-events: none`**：这一行存在的意义就是它的「启用」按钮。

## 面板：主机与端口转发

主机区每行一个 alias，右侧是「断开」；端口转发区列出**已存映射**与临时隧道，
顶部有「启动时自动开启隧道」总开关。

### 两条「断开」路径必须在面板上不可区分

面板读的只有三个字段：`live`（是否真有 listener）、`enabled`（用户的意图）、
`error`（是否需要解释）。两个入口都指向同一个关闭方法，所以三者逐字段相同：

| 入口 | 走的路径 | `live` | `enabled` | `error` | 面板那一行 |
| --- | --- | --- | --- | --- | --- |
| 主机行的「断开」 | `savedForwards.closeAlias(alias)` → 逐条 `closeById` | `false` | `false` | 无 | 已断开 + 开启，**无红字** |
| 端口行的「断开」 | `closeById(id)` | `false` | `false` | 无 | 同上 |
| 连接意外掉线 | `ForwardManager.closeForAlias()` → `onClosed` | `false` | `true` | `"SSH connection closed"` | 已断开 + 开启 **+ 红字「连接已断开」** |

第三行才是故障：连接断得不是时候，所以要保留意图（下次可一键恢复）并留下原因向用户
解释。前两行是用户主动完成的动作，留下原因等于把成功的操作报成故障，后面还会跟着
「启动时自动开启隧道」的暗示——而用户刚刚明确关掉了它。`forwards.lost`
（「连接已断开」）只在 `error` 里含 `connection` 时渲染，因此主动断开后不会出现。

主机行「断开」的 toast 在拆掉了隧道时报数：`hosts.disconnectOkForwards`
（「已断开连接，同时关闭 {n} 条端口转发」），`n` 来自响应的 `closedForwards`；
没有隧道时用 `hosts.disconnectOk`。

### 面板：持久远端会话

`status.shells` 非空时才出现「持久远端会话」一区，每行 `alias [session]` + 状态
（`存活` / `已结束`）。它是一个**只读**列表——这一区不提供开关或关闭按钮，
因为会话的生命周期归 agent 的 `ssh_workspace_shell` 管（同一 `alias` 可并存多个
命名会话）。空列表**整区不渲染**，避免暗示面板拥有一个它并不拥有的控制项。

## 面板：诊断报告

面板底部的「诊断报告」一节是插件唯一**预期被贴到公开场合**的产物：一段纯文本，
把版本、补丁判定、主机配置（含 `~/.ssh/config` 审计）、工作区、连接代次、端口转发、
每主机自检、最近命令与事件组装在一起，供用户贴进 issue。

三个入口共用同一个 `buildSupportBundle`，措辞与脱敏规则不会分叉：

| 入口 | 形态 |
| --- | --- |
| 面板「打开诊断报告」 | 取 `GET /api/dsh-ssh-workspace/support-bundle` 的文本，渲染为面板内的对话框 |
| 报告窗口内的「复制」 | 把**屏幕上这一份**文本写剪贴板；没有剪贴板权限时选中全文，让用户手动 Ctrl/Cmd+C |
| `ssh_workspace_status` 的 `supportBundle` | 字符串，agent 可直接取用 |

### 状态灯：报告本身不给结论，所以结论由判定模块给

诊断报告是**事实汇总**，不是体检报告——九个章节全是原始事实，没有一行说"这算不算问题"。
这对粘贴是对的（它不能与面板矛盾），对面板是错的：用户不该需要知道阈值才能判断
`probe: 'fixed'` 意味着"该删了"、或者主机没出现在列表里意味着它的配置被拒绝了。

所以判定被拆成独立模块 `lib/diagnosis.js`，并在报告标题后画一个圆点：

| 状态 | 颜色 | 含义 |
| --- | --- | --- |
| `ok` | 绿 | 没有需要处理的事项 |
| `warn` | 红 | 有 N 项需要处理（标题 `title` 与读屏标签给出条数） |
| `unknown` | 琥珀 | 有 N 项无法判断 |

**三态不折叠成两色。** `unknown` 既不是绿也不是红：探测不到的主机不能报成"缺了它所有的
工具"，也不能报成"一切正常"。聚合时**确定的坏压过不确定**——一个红点说"另外我还判断不了
一件事"仍然是红点，可行动的那条事实更重要。

判定只读报告**已经在打印的字段**，不探测、不连接、不读文件。它在**服务端**计算
（`/status` 的 `diagnosis` 字段），浏览器只负责渲染——两处各自推导同一套规则，是"圆点与
报告说法不一致"的开始。

**圆点必须在面板里可行动**：findings 直接列在标题下方（最多 8 条，其余显示总数）。
一个只说"有问题"却不说是什么的圆点是个谜题，不是报告。

### 报告里补上了三处它原本漏掉的事实

判定要诚实，报告就得先带上这些事实（都来自已有数据，没有新增采集）：

- **`## host keys`**：被接受但没能固定的主机密钥。这是"报告什么都没说"与"报告说一切正常"
  曾是同一个画面的地方，也是安全上唯一真正要紧的一条；
- **被跳过的主机**：`~/.ssh/config` 里存在但无法使用（如 `ProxyJump`）的条目以前**根本不出现**
  在报告里，于是"我明明配了却用不了"没有任何线索。现在带原因列出，别名照样打码；
- **连接代次**：`generation` 大于 1 时说明"重连前启动的远端进程可能仍在运行"。
  "偶发断线"与"从没连上"以前在报告里长得一样。

另外，空补丁列表的措辞不再合并两种情况：`none installed (or the projection seam was
unavailable)` 把"补丁不需要装"和"我不知道补丁装没装"写成了一句，现在只说后者。

「复制」不在面板工具栏上，而在报告窗口里。复制只在**已经有一份报告**时才有意义，而且
工具栏上的「复制」在无剪贴板权限时会悄悄改成弹出一个窗口——按钮的标签承诺了另一件事。

### 报告窗口：自动换行、打开不选中

文本用 `wrap="soft"` + `white-space: pre-wrap` **自动换行**。它曾经是 `wrap="off"` 加横向
滚动，为的是让一条被脱敏的长路径留在一行；但报告是逐行读的，横向滚动逼读者一边读一边拖，
而换不换行对内容没有区别——等宽字体下对齐照旧。

打开时**不自动全选**。`area.select()` 挂在挂载时看着贴心，实际是：整份报告在用户还在读的
时候闪成高亮，之后任何一次按键都把选区换掉，浏览器没拿到焦点时还会留下一个没人要的选区。
复制改为窗口底部的按钮，键盘用户也够得着。只有在**复制失败**（没有剪贴板权限）时，
才退而选中全文——那是用户按了「复制」之后的补救，不是打开时的惊喜。

`client-shape-smoke` 对 `ReportDialog` 内部**计数** `.select(` 的出现次数（恰好 1，且必须
在 `handleCopy` 之后），而不是断言「挂载时没有 `area.select()`」——后者会被
`areaRef.current?.select()` 这种写法绕过，反向验证时确实绕过过一次。

### 「打开」为什么不能是新窗口

「打开诊断报告」曾经是一个 `<a href="…" target="_blank">`。**在桌面端它点了没反应**，
而路由本身返回 200——失败的是新窗口这条路径，有两层原因：

1. 桌面端的文档来源是 `dsh-app://app/`，相对 `href` 于是解析到 `dsh-app://` 协议。
   主窗口的 `setWindowOpenHandler` 只放行 `http:` / `https:`，其余一律 `deny`，
   点击被静默吞掉。
2. 即便协议被放行，`shell.openExternal` 会交给系统浏览器，而那个浏览器没有 Host 的
   鉴权 cookie，只会拿到 `401 dsh web authentication required`。

所以入口改为**在面板内取同一份字节**：`fetchReportText()` 是唯一的取数点，「打开」把它
渲染进一个只读、可选中、等宽的 `ReportDialog`，复制在该窗口内完成。`client-shape-smoke` 用
「这一节里不得出现 `window.open` / `target: '_blank'`」来钉住它——断言的是**形状**
而不是「有个按钮」，因为前者才是两个壳子里都会坏的那一半。

### 标题叫「诊断报告」，标识符仍是 `support-bundle`

标题改过一次：原先叫「支持包」，那是从 Docker / Kubernetes 借来的术语，而本插件
没有支持台、产物不是归档、且**不上传任何地方**——"支持"二字暗示了一个并不存在的
接收方。新标题用「诊断报告 / Diagnostic report」。

**标识符一律不动**：路由 `/support-bundle`、工具字段 `supportBundle`、模块
`lib/support-bundle.js`、套件 `support-bundle-smoke` 都是契约面，改名没有功能收益。
这与仓库既有习惯一致——面板叫「远程环境自检」而路由叫 `/self-check`，面板叫
「最近的远端命令」而模块叫 `audit.js`。

避免用「插件诊断」：`ssh_workspace_status` 里已有 `diagnosticsText`（只有 20 条事件环），
两个"诊断"并存会让读者分不清该贴哪一个。「报告」二字守住了区别——这是**一份可读
文本**，不是要上传的归档。

### 脱敏是设计约束，不是选项

- 家目录段打码，保留首段与扩展名（仍能分辨 `src/index.ts` 与 `dist/app.js`）；
- alias 短写且**跨行一致**（同一主机的多条事件仍可关联）；三个字符以内整体打码；
- 登录用户打码而地址与端口保留（`<user>@10.0.0.1:22`）；
- 命令行经 `audit.js` **在写入时**脱敏，不在导出时补第二次；
- 凭据从不进入报告：存储里的 secrets 是加密的，报告读的是面板那份无密行。

**没有"原始模式"开关**——有 raw 开关的报告，一定会有人用 raw 模式贴出去。

报告末尾固定一句：`Paths, usernames and credentials are masked. Nothing was uploaded: you decide where this goes.`

这句话**只留在报告里**。面板工具栏下面那行提示原先也带着"不会上传到任何地方"，两处同时
声明让一句陈述读起来像免责声明；提示现在只说**报告包含什么、已经脱敏**，"不上传"由报告
自己的收尾句负责——那是唯一真正需要读者知道这件事的地方（他正要把它贴出去）。

## 路径的展示拼写

两处纯展示的替换，把 `ssh://alias/path` 显示为 `ssh://alias@/path`（读起来像 SSH 地址）：

- 工作区悬停卡片（hover card）中的路径；
- DSH `PathLabel` 单元格：文件面板头部、文档预览标题、交付物列表。

只改渲染文本，复制行为与所有功能消费方保持真实拼写。规则细节见 [protocol.md](./protocol.md) 的「显示规则」。

## 文件进任务：拖拽与右键

侧边栏文件树的文件与文件夹（`li[data-files-entry="file"|"directory"]`）有两种手势把路径加入当前会话的任务：

- **左键拖到输入框**：拖动经过输入卡（`[data-composer-card]`）时卡片显示虚线高亮（内联 `outline`，拖拽结束/离开即清除），松开即插入引用 chip；
- **右键 → 菜单**：行上弹出锚定菜单（复用 `.sshwsp-flowmenu` 样式，视口内钳制）。菜单内容取决于该行是否落在远端工作区：

  | 菜单项 | 出现条件 | 说明 |
  | --- | --- | --- |
  | 「添加到任务」 | 总是 | 菜单项副标题直接显示将要插入的 `@` 拼写，点击插入 |
  | 「下载到本机」 | 仅远端行 | 目录行**禁用**并说明「暂不支持下载整个目录」（整棵树请用 `recursive` 上传反向、或远端打包） |
  | 「上传文件到此目录」 | 仅远端行 | 文件行传到它的父目录，目录行传到它自己 |

  本地工作区的行只有「添加到任务」——`GET /download` 与 `POST /upload` 对本地路径没有任何可对话的对象，摆出这两项等于承诺一个该行并不具备的能力。

插入与「`@` 补全里选中候选」走同一条管线：取主会话 composer 的 `captureInsertion()` 跨度，经会话作用域的 `slash/input-insert-reference` 事件交给编辑器——chip 节点、序列化与失效判定因此与补全完全一致（插入后可继续输入、照常提交）。会话监听不声称该事件时降级为纯文本插入；输入框不可用或路径不可表示时给出 toast。

拼写规则与 `@` 补全一致：树根即会话 cwd 时用**工作区相对路径**（`/` 分隔），否则保留绝对拼写；含空格按引号语法（目录保留开引号）。带控制字符或双引号的路径拒绝插入。

实现要点（`lib/client.js` 的 "Composer file bridge" 段）：行的 `draggable` 标记并入 DOM 装饰的同一趟 pass（`MutationObserver` 触发、rAF 合并）；拖拽只写入自定义 MIME、**不写 `text/plain`**，因此不触发输入框的文本粘贴，也不会与 DSH 的「拖入文件」浮层冲突；文档级 capture 监听 `dragover`/`drop` 判定输入卡并转发手势；右键菜单在滚动 / resize / 失焦 / Esc / 点击外部时关闭。手势面向**主会话**的输入框（文件树跟随主会话，二者工作区根一致时用相对拼写）。

## 文件面板与文档预览

「工作区文件」侧边栏与文档预览无需插件改动——它们经 `ctx.fs` 读取，远程工作区下自然由 SFTP 提供（列目录、读文本、写回均同本地工具一致），大文件预览按块流式读取。

插件往这个面板加了**一个**按钮：`sidebar.right.tab.files.actions` 插槽里的「上传文件到此目录」。它读槽位给的 `absolutePath`（面板正在显示的目录），所以上传落在用户眼前那个目录，而不是猜一个根。目录不能作为一个文件下载，因此头部**没有**下载按钮——下载在上面的行菜单里，那里目标明确。

非远端的工作区列表不渲染这个按钮：同一个面板也会显示本地目录，摆出一个只能对远端工作的控件会谎报能力。

已知差异：远端的变更监视**优先走 `inotifywait` 推送**（远端装了该工具时即时上报，不受元数据精度限制）；没有该工具时回退到**轮询式**快照比对——基础约 2 秒一次，空闲目录自适应退避到 5–10 秒、变更后立即回到 2 秒，文件树 / 预览会自动刷新。轮询路径下 SFTP 元数据无亚秒时间戳，同一秒内等长的连续改写可能不触发刷新（增、删、改名总能感知），此时重新打开或重新读取即可看到最新内容。
