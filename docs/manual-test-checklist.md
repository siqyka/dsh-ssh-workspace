# 手动验收清单（整个插件）

> 用途：只列**自动化测不到、必须真人在 GUI 里做**的部分。自动化已经覆盖的不放进这里，
> 避免重复劳动——每条都注明「为什么必须手测」。
> 配套：`node tests/run.mjs`（83 套件）、`scripts/reverse-verify-*.mjs`；表现层专项走查见本文第 12 组。
>
> 优先级：**P0** 功能不通就是回归，必须测；**P1** 边界与体验；**P2** 视觉细节。
> 建议按组连续测——同一组能在一次会话里走完。结果按文末格式回报。

## 0. 前置环境与记录

- [ ] 一台可 SSH 的测试主机（Linux 最佳：`rg` / `git` 已装，`inotifywait` 可选），和一个空目录用于挂载。
- [ ] 一个**本地工作区**用于对照（本地行为不该被插件改变）。
- [ ] 记录本次版本：插件版本、DSH 版本、宿主主题、时区。
- [ ] 每次改客户端代码后：**完全退出 DSH**（托盘也退）再启动，并 `Ctrl+Shift+R` 硬重载页面——浏览器半边没有构建管线，但页面有缓存。
- [ ] 准备一个「仅可查看」会话和一个「workspace-write」会话用于围栏对照。

## 1. 主机管理（P0，真实 SSH + GUI）

| # | 场景 | 操作 | 预期 / 判定要点 | 为何手测 |
|---|---|---|---|---|
| 1.1 | 添加 / 编辑 / 删除主机 | 面板里走一遍增改删，删除后看 `dsh-ssh.json` | 写回原子、保留文件里插件不认识的字段；删除主机**不会**自动卸载已挂载工作区（那些工作区随后不可访问，属预期） | GUI 表单 + 真实写盘 |
| 1.1a | 与 `~/.ssh/config` 同名的主机 | 让一台存储主机的别名与 `~/.ssh/config` 的某个 `Host` 相同（配置块先有，或在面板里保存同别名） | 卡片上**没有**「编辑」「删除」，并多一行说明去 `~/.ssh/config` 改；直接 `POST /hosts/delete` 该别名答 409 且 `dsh-ssh.json` 里的记录仍在；把记录改名到空闲别名可以保存，原别名不残留 | 需要真实 `~/.ssh/config` 与面板 |
| 1.1b | 表单里测试未保存的主机 | 「添加 SSH 主机」填一个真实主机，点底栏「测试」；再故意改错端口/密码点一次；最后改回正确值 | 第一次显示绿色「可连通（N ms）」且**没有**新增主机记录（`dsh-ssh.json` 不变）、主机列表不出现「已连接」；第二次显示服务端原始错误；改了任一字段后旧结果立刻消失（不会留着上一个地址的绿灯）；保存与测试对同一份表单给出同样的必填/端口判断 | 需要真实 SSH 主机 + 面板 |
| 1.2 | 测试连接 | 点「测试」，成功与失败各一次 | toast 显示往返毫秒；**7 s 后自动消失**，指针悬停暂停、移开重计满；可点 / Esc 提前关；失败可展开诊断码 + 原始错误、可复制、可「重试」 | toast 计时与焦点是 DOM 行为 |
| 1.3 | 凭据加密与回显 | 用 password / 带口令的 key 添加主机，重开编辑框 | 编辑时密码框留空 = 保留原值；`dsh-ssh.json` 的 `secrets` 段是密文；凭据**从不**出现在浏览器网络响应里 | 加密与回显只在前台可验 |
| 1.4 | 主机密钥 TOFU | 首连接受指纹 → 服务端指纹变更后再连 | 第二次**拒绝连接**并同时显示新旧指纹；面板「忘记主机密钥」后重新信任才恢复 | 需要真实 host key 变更 |
| 1.5 | `~/.ssh/config` 回退 | 不写 store，只在 `~/.ssh/config` 放一个 Host 块 | 主机出现在列表、可挂载；面板**不改写**该文件；同名时 store 优先 | 真实 config 解析 |
| 1.6 | ProxyCommand 拒绝 | 配一个带 `ProxyCommand` 的 Host | 解析时明确拒绝并说明原因（不悄悄按直连试）；`ProxyJump` 正常 | 真实配置行为 |
| 1.7 | 断开 / 立即重连 | 健康时「断开」；断网后看「立即重连」 | 「断开」只在 `connected` 时出现，`broken`/重连中不出现；主动断开无红字，连接掉线有红字 + 保留意图 | GUI 状态机 |
| 1.7a | 开机自动连接只标记 | 连着一台主机（未勾选）→ 勾选；再取消勾选；另找一台没连的主机勾上 | 勾选**不拨号**、取消**不断开**（当前会话仍在，绿点不变）；勾选态只反映意图——连着但没勾过的主机显示未勾选；toast 写「当前连接未改动」；`dsh-ssh.json` 顶层 `autoConnect` 跟着变 | 需要真实连接观察 |
| 1.7b | 主机硬停用（电源开关） | 一台连着、有持久 shell 的主机：拨开关 → 看确认框 → 确认；再拨回开 | 确认框列出实时计数（连接 / 命令 / shell / 转发 / 反向 / 监视 / 终端，只列非零项）并写明会话保留；确认后开关变关、该主机下的工作区与会话行变灰；此刻对这台主机发命令 / 挂载 / 测试 / 重连都失败并**说明是开关**（不是超时）；`dsh-ssh.json` 里该条目 `enabled:false`；拨回开后这些行恢复，**不会**自动拨号 | 真实资源拆除 + 置灰 |
| 1.7c | `~/.ssh/config` 主机没有开关 | 看一张来自 config 的卡片 | 左侧**没有**开关；直接 `POST /hosts/toggle` 答 409 并点名 `~/.ssh/config` | 需要真实 config 主机 |
| 1.8 | 后台重连 | 断开 SSH 服务再恢复 | 面板显示「重连中（第 N 次，M 秒后）」；恢复后自动重连；`status` 的 `generation` 从 2 起带说明 | 需要真实断网 |

## 2. 工作区生命周期（P0）

| # | 场景 | 操作 | 预期 / 判定要点 | 为何手测 |
|---|---|---|---|---|
| 2.1 | 新建远程工作区 | 「添加工作区 → 新建远程工作区」走 选主机 → 浏览目录 → 命名 → 挂载 | 目录**单击选中**（高亮，并成为创建目标）、**双击**进入；选中后「将创建：」一行显示选中路径，创建即建在该目录；路径栏尾斜杠表示"在目录里"；输入框前缀只本地收窄、不自动进入；挂载后可写 | 对话框交互 + 真实目录浏览 |
| 2.2 | 可写探测 | 对一个只读目录打开新建工作区对话框 | 红色警告 + **禁止创建** | GUI 门禁 |
| 2.3 | 目录浏览对话框 | 主机卡片「浏览目录」 | 只列目录；**双击**进入；上传/下载/队列**不在**这里；大目录用 `ls` 快路径，形状不符会自动回退 SFTP | 真实大目录表现 |
| 2.4 | 折叠单链目录 | 打开一条 `a/b/c` 单链目录 | 折成一行，点进去才展开；**软链不折叠**；层数上限 16 | 纯视觉/交互 |
| 2.5 | 重启自动重挂 | 挂载后完全重启 DSH | 工作区自动恢复挂载、侧栏分组恢复 | 跨进程 |
| 2.6 | 卸载两步确认 | 点「卸载」 | 第一次只展开确认行（**没有复选框**，只有「确认卸载 / 取消」），第二次才执行 | GUI 交互 |
| 2.7 | detach（卸载的唯一行为） | 卸载后看三处 | 工作区记录保留、侧栏那行**只置灰（仍可点）**、会话**保留不归档**、面板移到「已停用」可「启用」 | 视觉 + 真实会话状态 |
| 2.8 | 删除（两个都勾） | 已挂载或已停用行点「删除」，两个勾选框都留着，再点「确认删除」 | 第一次只展开两个勾选框 + 「确认删除 / 取消」；确认后侧栏行消失、面板行消失、会话**归档不删除**（文件仍在 `sessions/` 下）；提示写明归档数 | 真实 registry 状态 |
| 2.8b | 删除（只勾「删除工作区」） | 取消「删除会话」后确认 | 记录消失、会话**仍在侧栏**、提示是「已删除工作区，会话保留」（不得报归档数） | 真实 registry 状态 |
| 2.8c | 删除（只勾「删除会话」） | 取消「删除工作区」后确认 | 工作区转到「已停用」（可再启用）、会话归档、提示是「工作区已停用，N 个会话已归档」 | 真实 registry 状态 |
| 2.8d | 删除（两个都不勾） | 取消两个勾选 | 「确认删除」**禁用**，点击无请求发出 | GUI 门禁 |
| 2.9 | 停用即全局停机 | detach 后在会话里：读文件、列目录、执行命令、开终端、glob/grep、传输 | 全部被拒且错误点名 "detached"；**但 SSH 连接本身可用**（主机面板、不带 cwd 的 exec、端口转发照常） | 跨多个工具联动 |
| 2.8a | 删除主机后的工作区标红 | 删掉某台主机（它名下至少有一个已挂载、一个已停用工作区） | 两段列表里这些行的行首出现红色感叹号，悬停说明是哪个主机不见了；重新添加同 alias 的主机后（点一次刷新）标记消失；**拉取 /hosts 失败时不得给所有行标红** | 真实主机删除 + 视觉 |
| 2.9a | 嵌套停用不吃掉父目录 | 父目录已挂载，再挂它的子目录后只停用子目录，然后在父目录的文件树里点开该子目录 | 能正常列目录/读文件（父根仍在服务这条路径）；停用行本身仍是灰的。反向：停用父目录、子目录已挂载时子目录照常可用，父目录下其他路径仍被拒 | 真实嵌套挂载 |
| 2.10 | 停用置灰 | 看侧栏与会话行，再点一下 | 停用工作区的**会话行**也置灰，但**点击照常**：点开会话、展开分组、行内按钮都能用 | 视觉 + 交互 |
| 2.11 | 重新启用 | 在「已停用」行点「启用」，远端目录还在 | 恢复正常、会话回到可见；**不必再重启一次**就见到会话分组与行 | 真实会话补偿 |
| 2.11a | 从「已停用」删除 | 在停用行点「删除」，两个勾选框都留着，再点「确认删除」 | 第一次只把「启用」换成两个勾选框 + 「确认删除 / 取消」；确认后侧栏与面板两行都消失、`dsh-ssh.json` 的 `workspaces.disabled` 移除该路径、会话**归档不删除**（文件仍在 `sessions/` 下）；提示写明归档数 | 真实 registry + 磁盘状态 |
| 2.12 | 启用失败（远端目录已删） | 删掉远端目录后点「启用」 | 明确报"目录不存在"，不得得到"看着在服务、实际 ENOENT"的工作区 | 真实 SFTP stat |
| 2.13 | 会话归属补偿 | 「禁用 → 重启 → 启用」 | 会话自动认领回工作区；`status` 的 `ownership` 快照给出 `pending` / `skipped` / `failures` | 跨重启 + 宿主索引 |
| 2.14 | 同名工作区 | 本地与远程用同一个标题 | 两边都**不**误标、不误置灰；只有一方独占该标题时才打标记 | 纯 GUI 身份判定 |

## 3. 文件读写与围栏（P0，真实 SFTP + GUI）

| # | 场景 | 操作 | 预期 / 判定要点 | 为何手测 |
|---|---|---|---|---|
| 3.1 | 远端读写编辑 | 在 `ssh://` 会话里 `read` / `write` / `edit` | 全程走 SFTP；本地工作区一切照旧 | 真实 SFTP |
| 3.2 | 原子写入 | 编辑时观察目标文件 | 先写同目录暂存再改名；不支持 `posix-rename` 的服务器退化为先删后改名 | 需特定服务器 |
| 3.3 | 换行符 / BOM 保真 | 编辑 CRLF 与带 BOM 的文件并保存 | 不被改成 LF / 丢 BOM | 字节级结果 |
| 3.4 | 编码识别 | 打开 UTF-16LE/BE、GB18030、含中文的文件 | 能正确显示；GB18030 **能看不能改**（铅笔按钮不出现/带原因） | 真实编码文件 |
| 3.5 | 大文件 | 预览 / `read` 一个 > 256 KiB 的文件 | 分块流式；超出 `maxBytes` 报 `FS_TOO_LARGE`；内存不暴涨 | 真实大文件 |
| 3.6 | 写入围栏越界 | 在挂载根外写、通过符号链接逃逸写 | 一律 `FS_OUTSIDE_WORKSPACE`；读取**不受**此限制 | 真实 symlink |
| 3.7 | 只读会话围栏 | 在「仅可查看」会话写远端 | 被拒（`FS_SANDBOX_DENIED`）；读取正常 | 真实 mode |
| 3.8 | 变更自动刷新 | 远端用 shell 改文件，看文件树 / 预览 | 装了 `inotifywait` 即时刷新；否则轮询基础 2 s、空闲退避到 10 s、一有变更立刻回 2 s；**同一秒内等长改写可能不刷新**（已知盲区） | 真实 watcher |
| 3.9 | 变更追踪 | 远端 shell 改文件，看「变更」面板 | 用**远端 git** 出回合快照与 diff（+N/−N、可点开看）；未装 git 时降级关闭并提示；**逐文件 before/after 文本对比对远端不可用**（已知盲区） | 真实 git 仓库 |
| 3.10 | `rg` / `glob` / `grep` | 在远端工作区搜索 | 调用远端 `rg`；没装时退出码 127 + 安装提示 | 真实工具 |

## 6. 传输与队列（P1，浏览器 + 真实 SSH）

## 报告格式

按组回报，每条一行：

```
[组号.条目号] 期望 → 实际 → PASS / FAIL
```

- FAIL 必须附：插件版本 + DSH 版本 + 主题 + 复现步骤 + 截图（视觉问题必附）。
- 每组开头写一句结论（全过 / N 条 FAIL）。
- 最后单列：**哪些组没测**（及原因，如"没有带 TOFU 变更的服务端"）。
- 视觉问题不写"看起来不对"，写"哪个位置、期望 vs 实际"。
