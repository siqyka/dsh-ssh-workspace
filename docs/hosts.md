# 主机配置与认证

> 定位：主机从哪里来、如何存储、如何在面板中管理。

## 来源与优先级

两类来源，按优先级：

| 来源 | 位置 | 可编辑 |
| --- | --- | --- |
| 主机存储（优先） | `$DSH_HOME/dsh-ssh-workspace/dsh-ssh.json` | 是（面板增删改；**别名同时出现在 `~/.ssh/config` 时除外**） |
| OpenSSH 配置（回退） | `~/.ssh/config` | 否（只读） |

> 主机存储从 `$DSH_HOME/dsh-ssh.json` 迁到了上面的插件私有子目录。旧位置仍可读取：首次写盘时文档被迁到新路径；加密密钥同理（旧 `$DSH_HOME/dsh-ssh.key` 继续可用，新密钥写到 `dsh-ssh-workspace/dsh-ssh.key`）。迁移不丢主机，也不需要手工搬文件。

与存储同名的主机以存储为准，列表里也只出现一次（呈现为存储条目），但那条记录
**不能再被删除或编辑**：列表带 `configAlias: true`，面板不给这两个按钮，
`POST /hosts/delete` 与 `POST /hosts/save` 都答 409。理由是两种改法都会骗人——
删掉存储条目只是露出原来的 `Host` 块（主机「自己回来」），而改它会遮蔽那个块，
让本机其它 ssh 客户端解析到的东西悄悄变样。要改就去 `~/.ssh/config` 里改，
或者把记录改名到空闲别名（保存仍放行）。
存储文件读不懂时按空列表降级（不阻塞 `~/.ssh/config` 的主机），但**编辑**
时会明确报错，避免把读不懂的内容覆盖掉。

## 存储格式

`dsh-ssh.json` 是共享格式（`{ "version": 1, "hosts": [...] }`），DSH 的 SSH
工具链共用这一份主机列表。插件写入时保留顶层与条目里**不认识的字段**；
写入是原子的（暂存文件 + rename），文件权限收紧为 `0600`（目录 `0700`）。
除 `hosts` 外，文件另有 `knownHosts` 段记录主机密钥指纹（见「主机密钥校验」）、
`secrets` 段保存加密后的凭据（见「认证与凭据」），以及顶层 `autoConnect`
别名数组（见「自动连接意图」）。

条目字段：

| 字段 | 含义 |
| --- | --- |
| `alias` | 别名（用于 `ssh://` 与工具参数） |
| `host` / `port` / `user` | 连接目标；默认端口 22 |
| `auth` | `{ kind: "key" \| "password" \| "agent", keyPath?, passphrase?, password?, agentPath? }` |
| `description` / `tags` | 备注与标签（`ssh_workspace_hosts` 可搜索） |
| `agentForward` | 布尔。在远端**命令通道**（exec / shell / 终端 / 持久 shell）上转发本机 ssh-agent，使远端命令（如远端 `git push`）能用本机密钥认证，私钥不落到远端；SFTP（浏览 / 传输）不受影响，认证方式也不因此改变 |
| `compress` | 布尔。传输压缩，以 CPU 换带宽，慢链路（跨国 / 移动网络）下明显更快 |
| `proxyJump` | 跳板机链，字符串（`a,b`）或数组。按 `ssh -J` 的形状**逐跳建独立连接**，最多 8 跳；`none` 表示强制直连（见下） |
| `enabled` | 布尔，**opt-out**：缺省为开，只有显式 `false` 才表示「被电源开关停用」。开启时该键会被**删除**，所以启用的条目与引入这个开关之前字节级一致；写到 `~/.ssh/config` 主机上无效（那些主机没有这个键，也没有开关） |
| `createdAt` / `updatedAt` | 时间戳 |

`agentForward` / `compress` 都是**可选布尔**：缺省等于 ssh2 默认（关闭），
所以老版本写入的条目与新版本字节级兼容。面板的主机编辑器里以复选框呈现，
勾掉即从文件中删除该字段，不会残留 `false`。

`agentForward` 是**逐通道**生效的：ssh2 的转发请求只能挂在 exec / shell 通道上，
连接级同名字段会把整条连接（含只读 SFTP）都卷进来，本插件不使用它。转发的
前提是连接上挂着一个可解析的本机 ssh-agent（`SSH_AUTH_SOCK` / pageant，或
agent 认证自带的 `agentPath`）：key / password 认证的主机勾选后若本机有 agent
会自动挂上（配置的密钥 / 密码仍是第一认证方式），本机没有 agent 时转发空转、
连接照常；agent 认证却找不到 ssh-agent 仍会在连接时报错。

## ~/.ssh/config 回退

只解析**具体的 `Host` 块**（含通配符的块忽略），读取 `hostname` / `port` /
`user` / `identityfile`（`%d` 展开为家目录）/ `password` / `identityagent` /
`forwardagent` / `compression`，同键按 OpenSSH 的 first-wins 规则。
`ForwardAgent` / `Compression` 按 OpenSSH 的 yes/no 语义归一为布尔（只有显式
`yes` 才算开启，其余一律关闭）。`Include` 会被**跟随**（`lib/hosts/hosts.js` 的 `readConfigWithIncludes`，相对
`~/.ssh` 解析、支持 `*` / `?` / `[...]` 通配，并防环），`Match` 会被**求值**
（`lib/hosts/ssh-config.js` 底部的 `matchSelects`，支持 `host` / `originalhost` / `all`）。
仍被跳过的是**通配符 `Host` 块**——它只用于代理扫描，不贡献身份字段；目标是
「够用的回退」，不是完整解析器。

## 认证与凭据

- 密码与私钥口令**加密后**保存在 `dsh-ssh.json` 的 `secrets` 段，按别名存放：
  `{ "<alias>": { "password": "enc:v1:…", "passphrase": "enc:v1:…" } }`；
- 算法 AES-256-GCM，密钥是 `$DSH_HOME/dsh-ssh-workspace/dsh-ssh.key`（`0600`）里的 32 字节随机值，
  首次保存凭据时生成（旧 `$DSH_HOME/dsh-ssh.key` 仍被读取以解密迁移过来的密文）。密钥与存储**分文件**：只拿到 `dsh-ssh.json` 解不开内容；
  密钥文件丢失或被更换后，已有凭据无法解密，连接时会明确报错，在面板重新保存
  该主机即可恢复；
- 老版本写入的明文凭据由插件在**启动时自动加密回写**（每次启动检查一次，
  无明文则不动文件）；`~/.ssh/config` 的 `password` 关键字是只读回退，不会被改写；
- **不会回传到浏览器**——面板编辑时密码/口令字段永远为空，留空表示保持原值；
- 切换认证方式（key ↔ password ↔ agent）时无法把旧凭据带过去，必须当场填新凭据；
- key 认证在主机的 keyPath 不存在时，主机列表会给出 `keyReady: false`
  提示（`check-key`）。

> 密文不写进 `auth` 字段，是为了不破坏共享格式：DSH 其它 SSH 工具会把
> `auth.password` 当明文密码直接用。它们读不到本插件保存的密码，但同一主机
> 仍可用密钥 / agent / `~/.ssh/config` 连接。

## 主机密钥校验（TOFU）

每次连接都校验服务器出示的主机密钥（即 ssh 的 known_hosts 行为）：

- **首次连接**：把密钥的类型与 SHA256 指纹（连同当时的 host/port、时间）
  记入 `dsh-ssh.json` 的 `knownHosts` 段并按别名保存，放行——首次使用即信任；
- **指纹一致**：放行；
- **指纹不一致**：**拒绝连接**，错误信息同时给出已记录与本次出示的两个
  指纹（含记录时间），并提示下一步怎么办；
- 面板每张主机卡片都有「**忘记主机密钥**」次级操作（需就地确认）：仅在该
  主机确实重装系统或合法更换密钥后使用。忘记后，下次连接会重新信任并记录
  对方出示的密钥（重新 TOFU），同时丢弃该别名的既有连接。

记录按**别名**归属，存储主机与 `~/.ssh/config` 回退主机一视同仁。升级后的
首次连接会静默记录、无交互确认弹窗——这是有意取舍（在面板流程里插入确认
对话框成本高），因此：**若不确定某次指纹变化是否可信，先按 [troubleshooting.md](./troubleshooting.md)
的「主机密钥不匹配」条目与管理员核对，再决定是否忘记。**

## 面板管理

「远程工作区」面板可添加 / 编辑 / 删除主机（写回 `dsh-ssh.json`）。
改动立即生效：对应别名的旧连接会被丢弃，下一次操作按新配置重连。
删除主机**不会**自动卸载已挂载的远端工作区，但那些工作区会因主机不存在
而无法访问。每张卡片另有「忘记主机密钥」（见上节），只清主机密钥记录，
不动主机条目。

### 自动连接意图

每张卡片有一个「开机自动连接」勾选框：**它只标记存储的意图，不操作连接**——
勾选把别名写入 `dsh-ssh.json` 顶层 `autoConnect` 数组，取消勾选把它移除；两者
都**不拨号、也不拆连接**：勾上一台正在用的主机不会因此重连，取消勾选也不会断开
当前会话（要断开会用同一行的「断开」，要立刻重连用「立即重连」）。勾选态只读
意图，不读 socket：一台连着、但用户从未勾过的主机显示未勾选。写盘失败则请求
失败，勾选态回到服务端的真实值。主机改名时意图跟着搬，删除主机一并清除。

意图存在**顶层数组**而不是条目字段，因为 `~/.ssh/config` 主机没有可编辑的
条目，却同样能开关。DSH 下次启动时在稍后的 tick 上**串行**连回这些主机：
单个失败记一条诊断事件、不中断其余；用的是引擎的 `acquire`，**不是**
`retryNow`——后者会顺带打开已存端口转发，绕过「启动时自动开启隧道」总开关。

同一意图登记为引擎的两个谓词：掉线后后台循环把该主机当作「还有人要」继续
重拨；空闲回收（默认 30 分钟）**豁免**这些主机，否则自动连回的连接会在安静
半小时后被回收，重启恢复等于白做。引擎记住每个别名**最后一次连接失败**
（成功连接或主动断开时清除）：fatal 失败（如拒绝的主机密钥）不武装后台重连，
此时卡片显示红点 +「连接失败」并在行下列出原因——这是这种失败唯一的用户
可见通道。`/status` 与 `ssh_workspace_status` 都下发 `autoConnect` /
`connecting` / `failures` 三项，面板与机器工具据此渲染，不会互相矛盾。

### 硬停用（电源开关）

卡片左侧的开关不是「隐藏这一行」，而是**让这台主机现在什么都不做**：
`POST /hosts/toggle` 带 `{alias, enabled}`，服务端先写 `enabled:false`（写失败即整体
失败），再关引擎闸门（`disabledHosts`，`acquire` / `probeDescriptor` / `exec` /
`openChannel` 一律拒绝并回 `HOST_DISABLED`），然后拆掉在途命令、池化连接、持久
shell、正/反向转发、变更监视与远端终端。开关打开只写回并开闸，**不拨号**。

- 只有存储主机有开关：`~/.ssh/config` 主机没有可写记录，路由对它们回 409 并说明
  「给它一个存储条目才能停用」。
- 停用期间 `/hosts/test`、`/hosts/reconnect` 与所有会拨号的路径都回 409（不是静默失败，
  也不是「假成功」）。
- 会话与工作区属于宿主，插件不关它们：`/status.disabledHosts` 让客户端把该主机下的行
  置灰，真去用时由路由报出原因。这是有意留下的边界，而不是遗漏。
- `/hosts` 的每一行带 `resources`（连接 / 在途命令 / shell / 转发 / 已存转发 / 反向 /
  监视 / 终端），确认框显示的就是这次读取的实时数字。

## 连接方式支持面

| 方式 | 状态 |
| --- | --- |
| 直连 | 支持 |
| `ProxyJump`（存储字段或 `~/.ssh/config` 的 `ProxyJump`） | **支持**：字符串与数组都接受，`a,b` 多跳按顺序逐跳建独立连接（最多 8 跳），`[::1]:22` 方括号 IPv6、`user@host:port`、`none`（任意大小写）表示强制直连；每跳各自认证并固定自己的主机密钥，目标只看到直接邻居。自引用与重复跳在解析时拒绝 |
| `ProxyCommand` | **拒绝**：它是任意本地命令执行，而配置文件是数据，不能变成「读配置 = 执行程序」。带 `ProxyCommand` 的主机会在解析时**明确拒绝**并说明原因，而不是静默按直连去试 |
