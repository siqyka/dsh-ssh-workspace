# 功能说明

> 定位：把插件提供的**全部功能**按能力域列成一张可核对的清单——每项写清「做什么、
> 怎么用、依赖什么、缺依赖时退化成什么样」。想快速了解看[根 README](../README.md)，
> 想知道某项具体参数看对应专题页。

## 概述

插件把一台 SSH 主机上的目录变成 DSH 工作区，使 DSH 原有的文件、搜索、命令、变更
追踪、终端与界面能力**原样作用于远端**，再补上远端特有的主机管理、端口转发与文件
传输。

规模：

| 项 | 数值 |
| --- | --- |
| Agent 工具 | 11 个 `ssh_workspace_*` |
| 浏览器 HTTP 路由 | 42 条（前缀 `/api/dsh-ssh-workspace/`，仅回环 + Host 头校验） |
| 接管的服务 seam | 7 个 `installSeam()`（`lib/index.js`）：`PATCH-fs` → `ctx.fs`、`PATCH-sandbox` → `ctx.sandbox.confine`、`PATCH-shell` → `ctx.shell`、`PATCH-subprocess` → `ctx.subprocess.spawn`、`PATCH-ptc` → `ctx.ptcRuntime.resolve`、`PATCH-terminal` → `spawnTerminal`、`PATCH-shell-discovery` → `ctx.terminalController.shells`（远端 shell 发现，实现在 `lib/surface/shell.js`）。另有 `ctx.slots` 上的一组 UI 槽位（面板 `sidebar.panellist`、侧栏文件树与预览的动作条、`conversation.input.dock`、新增工作区的 `directoryFlow`、宿主的 `sidebar.right.pane.tab`）与 `projection` schema 放宽，它们不经 `installSeam`——前者是客户端注册、后者走 `upstreamWorkarounds` 通道 |
| 桥接的宿主内建模块 | 2 个：`node:fs/promises`、`node:path` |
| 冒烟测试套件 | 87 个（多数可在裸检出上直跑；少数需要真实主机、完整 DSH 树或 POSIX `sh`，以 SKIP / partial 计）。套件数以 [development.md](./development.md) 的套件表为准，断言数看各自的收尾行（该页有一次 2026-11-24 的完整采样说明） |

设计前提：**不注册第二个 fs 服务**。远端方法装在部署已挂载的那一个 `ctx.fs` 实例上，
`ssh://` 路径走 SFTP，其余路径原样转发给原后端——因此本地工作区的一切行为不受影响。

## 一、工作区

| 功能 | 说明 |
| --- | --- |
| 挂载远端目录 | 把一个远端绝对目录登记为 DSH 工作区，返回 `ssh://<别名>/<路径>` 供会话使用；挂载前 `stat` 验证目录真实存在且是目录 |
| 持久登记 | 登记进 DSH 工作区 registry，出现在侧栏工作区列表；登记失败仍保留进程内挂载并回报原因 |
| 重启自动重挂 | 已登记的 `ssh://` 工作区在下次启动时从持久化 registry 恢复挂载 |
| 停用（可逆） | 默认 `detach`：保留工作区记录（侧栏那一行仍在、置灰），**会话也不归档**——保留分组却归档内容等于留一个点开是空的标题 |
| 注销 | `deregister`：删除工作区记录并归档会话；归档走 DSH 原生 `archiveSession`，会话文件与记账槽位都不动，可 `unarchiveSession` 放回 |
| 从面板删除 | 已挂载与已停用两段列表的每一行都有「删除」：两步确认，确认行里两个勾选框分别决定「删除工作区」（`deregister`，不勾则只 `detach`）与「删除会话」（归档，不删文件）；两个都不勾时确认按钮禁用。删记录会同时清持久清单与运行时围栏；提示里写明「启用救不回来」 |
| 主机缺失标记 | 主机被删除后，它名下的工作区（已挂载与已停用两段都算）在面板行首显示红色感叹号，悬停说明是哪个主机不见了、该怎么修；**只在 `/hosts` 完整读过之后仍找不到该 alias 时**出现——拉取失败、store 报错、config 有跳过条目时一律不标，避免「没看到」被当成「它没了」 |
| 重新启用 | 再挂载并取消归档；启用前用**原始连接**（绕开围栏）`stat` 验证远端目录仍存在，避免得到一个「看着在服务、实际 ENOENT」的工作区。启用**不会**顺手新建工作区记录——「启用」回答的是「再服务这个路径」，侧栏那一行由显式挂载或真正在那跑起一个会话时创建；宿主记录已不存在时照常解除围栏并开始服务，`registered: false` 由状态答复如实说明，归档会话也因为没有记录可归位而不动 |
| 停用即全局停机 | 停用后该工作区**除 SSH 连接外的一切操作**都被拒绝：读写、列目录、变更监视、执行命令、开终端、glob / grep / git、文件传输。**判据是「没有别的根还在服务这条路径」**（`isDetachedTarget`）：父目录已挂载、子目录曾被单独挂载又停用时，父目录的树照常可读——那条路径仍由父根服务；反之停用的父目录下、已挂载的子目录也照常可用。围栏挂在 `engine.disabledWorkspaces`，在 `ctx.fs`、内建 fs 桥、`ctx.shell`、`ctx.subprocess`、终端接管层与四条传输路由（`transfer` / `download` / `download-tree` / `upload`）里同时生效，且都在**建立连接之前**拒绝 |
| 刻意保留的例外 | 内建桥的 `stat` / `lstat` / `realpath` 不挡——DSH 的 registry 用它们做会话身份探针，在那里制造失败会让它把会话从工作区记账里剪掉 |
| 会话归属自动补偿 | 插件**每次激活**、在远端根挂好**之后**，把上一次启动漏挂的 `ssh://` 会话重新认领回工作区。会话文件从未丢失，丢的是宿主按 `realpath` 建的那份归属记账（插件缺席时 `ssh://` 的 `realpath` 必然失败，宿主随即把会话从记录里筛掉并写盘）。只在**规范化后完全相等**的路径上认领（子目录、另一台主机的同一路径都不算——宿主的判据就是字符串相等），逐个 `attachSession` 后**回读 `sessionIds` 验证**，失败只算一条 `pending` 而不中断其余；detach 的工作区计入 `skipped`、不计失败。仍不可恢复的三类情形：工作区被停用（根刻意没挂）、远端目录已删除（`realpath` 仍失败）、会话清单不可读——后两者留在 `ssh_workspace_status` 的 `ownership` 快照里（`failures` 带路径与理由、`degraded` 说明为何没查），`pending > 0` 时诊断给出 `workspace-ownership` 的 warn；每次激活都**无条件重建一次**宿主会话索引（`listStoredHeaders()` → `replaceHeaderIndex()` → `indexLiveSessions()`；在真实部署上约 340 ms / 60 个会话），再据此读记账、只 attach 记录里真的没有的 id——因此「禁用 → 重启 → 启用」之后**不必再重启一次**才见到会话；重建成功后还会按宿主的 `domain/changed`形状把每个工作区的**筛选后**视图重新广播一次，已经在看页面的客户端因此也不用刷新（广播数记在`published`，失败原因记在 `publishError`，广播不可用只降级、不中断补偿）。广播只补上**分组**这一层，分组**里的行**来自页面连上时的那一次 `session.list`，而冷会话没有可推事件——所以浏览器那一半还会在补偿跑完后**再要一次会话基线**（`sessions.refresh()`，即重连时走的那条路，自带 single-flight与按序合并）：只在 `stage === 'done'` 且这次确实动过东西时触发，缺行就重试最多 3 次（首看 400 ms、退避 ×1.6 封顶 2 s、整趟 150 s 封顶），一个页面实例只跑一趟，宿主缺服务或抛错时静默跳过。之所以不再「先量症状」，是因为实体的 `sessionIds` 是**已筛选**视图、原始记录又不在公开面上，「健康」与「索引陈旧」读出同一个零。`replaceHeaderIndex` 不是公开 API，缺失即降级为 `unsupported`（结果写在快照的 `indexRebuilt` 字段），快照同时由状态工具、诊断报告与面板 `/status` 三处提供 |

## 二、文件读写

会话工作区是 `ssh://` 时，`read` / `write` / `edit` 经 SFTP 直接读写远端文件。

| 功能 | 说明 |
| --- | --- |
| 完整错误语义 | 与本地同一套 `FS_*` 码，另加一个远端专用的 `FS_OUTSIDE_WORKSPACE`（详见下文与 [troubleshooting.md](./troubleshooting.md)） |
| 原子写入 | 先落**同目录**暂存文件再 `rename` 发布；优先 `posix-rename@openssh.com`，服务器不支持时退化为「先删后改名」（此时不再原子） |
| 符号链接裁决 | 写入围栏在词法前缀之外补一次**父目录 `realpath`** 裁决，堵住「中间目录或末级是 symlink 指向围栏外」的绕过；读取不加此限制 |
| 换行符保真 | 编辑 CRLF 文件不会把它改写成 LF |
| 文本编码识别 | 采样前 8 KiB 按 **BOM → NUL 只是提示 → 严格 UTF-8 → 严格 GB18030** 判定：带 BOM 的 UTF-16（两字节序）、不提 BOM 但 16 位读法像文本的 UTF-16、含中文的 GB18030 都能读；GB18030 还要求真解出中日韩字符，否则 Latin-1 文件会当乱码打开。都不成立才 `FS_NOT_TEXT` |
| 编码原样写回 | 保存按读到的编码写回（UTF-8 / UTF-16LE / UTF-16BE），`#publish` 收**字节**而不是字符串，所以一次编辑不会把 UTF-16 文件整份转成 UTF-8；GB18030 能看不能改（Node 无编码器），`probe` 直接给 `not-encodable`、按钮不出现 |
| 字节原样读写 | `readBytes` 不做文本判定，原样返回字节 |
| 大文件流式读取 | 预览与 `read` 按 **256 KiB** 分块流式读取，不再整文件进内存；超出调用方 `maxBytes` 时报 `FS_TOO_LARGE` |
| 变更自动刷新 | 优先走远端 `inotifywait` 推送事件（即时、不受 mtime 精度限制）；未安装时回退轮询 |
| 轮询自适应退避 | 基础 **2 s**；连续 **15** 轮无变更退至 **5 s**，**30** 轮退至 **10 s** 封顶；任一变更立即回到 2 s |
| 元数据缓存 | 读路径元数据缓存 TTL **1.5 s**、上限 **1024** 条（刻意低于轮询间隔，避免把缓存快照当成新快照） |
| 轮询的已知盲区 | SFTP 元数据无亚秒时间戳，同一秒内**等长**的连续改写可能不触发刷新；增、删、改名总能感知 |
| 在浏览器里编辑 | 文档预览头部的铅笔按钮把编辑器**盖在预览正文那一块上**（不是弹窗），**远端 `ssh://` 与本地绝对路径走同一组路由**（`read-text` / `write-text` / `edit-text`），只有最内层的读写与围栏分两支；上限 **2 MiB**（超出改为只读分页，128 KiB 一页）；不能编辑时铅笔按钮**保留**，图标角上戴红点，悬停显示原因（编码限制 / 只读会话 / 二进制 / 超出上限 / 工作区外）。**≤64 KiB 的文件由 probe 连正文一起回传**，点开编辑直接用它起稿（令牌一同带回，保存仍会发现这期间被改过的文件），编辑器打开不再额外发一次读 |
| 文件内查找 | `Ctrl/Cmd+F` 打开查找条，`Enter` / `Shift+Enter` 前后跳并在首尾回绕，`Aa` 切大小写，`Esc` **先关查找条再关编辑器**。匹配是字面量扫描（不编译正则），最多收集 **1000** 条、超出显示 `1000+`。选中即高亮——引擎路径由 CodeMirror 6 原生画选区与高亮；无引擎兜底的 `textarea` 画不了区间，用覆盖层逐像素对齐（不再考虑 `contenteditable` 重写选区与撤销） |
| 编辑器内核 | 文件读出后 `require.async` 取 **CodeMirror 6**（独立 744 KiB chunk，`npm run build:editor` 生成，`check:editor` 防漂移）；chunk 未到或加载失败就继续用 `textarea`，失败被记住、不在每次 render 重试。语法高亮由解析器驱动：JavaScript / TypeScript / JSX、JSON、CSS、HTML/XML、Markdown、Python、Shell、YAML、SQL、Go、Rust、C 系、TOML/INI、Dockerfile、Makefile |
| 多标签 | 同一会话打开过的文件进一条标签带，切换时**先认未保存草稿再看磁盘**；脏标签带圆点、关闭前询问、关闭当前标签取右邻（末尾取左邻、全关收起面板）；保存不再关闭面板 |
| 语法高亮回退 | 引擎不可用时退回 `textarea` + **窗口化**颜色覆盖层：只画视口附近的行并按 `scrollTop` translate，缓存每行进入时的扫描状态；**换行模式、输入法组合期间、超过 512 KiB** 时不染色。颜色全走 CSS 变量，浅色主题有独立调色板 |
| 保存的双令牌 | 回传 `version`（`ino:size:mtime`，便宜）与 `revision`（内容 sha256，贵），先比 version 再比 revision：常见改动一次元数据往返就 409，而「同一秒、同样大小」的改写只有哈希能发现。任一不符回 **409** 并带当前令牌 |
| 冲突默认不覆盖 | 409 的默认动作是「重新加载」；「覆盖」排在后面且要二次确认，且**重新读一次拿新令牌再写**而不是跳过校验。**没有 `force` 参数** |
| 行尾与 BOM 保真 | 读时把 `eol`（`LF`/`CRLF`）与 `bom` 与 `text` 分开报告（`text` 已归一化为 LF 且不含 BOM），写时原样装回；`eol: 'auto'` 用磁盘当前风格。底部行尾下拉就是保存策略选择器：`自动（LF/CRLF）` / `LF` / `CRLF`，选中的一种在下一次保存时生效，服务端回传实际写入的行尾；只改行尾也算未保存改动。编解码与 `editText` 工具共用同一份实现 |
| 截断即不可写 | 超限读只回头部且 `revision: null`——截断内容算出的哈希是假证据，而写路由要求 revision 是字符串，所以截断的文件在协议层面无法保存 |
| 分页读（只读） | 超过 **2 MiB** 的文件不是死路：probe 回 `paged: true`，读路由接受 `offset`，每次一页 **128 KiB**，`nextOffset` 说明下一页从哪开始（页按固定字节数切开，最后一个字符可能被切断，切下的字节留在下一页，不丢也不补）。编码与行尾**只在第一页决定**，之后由客户端回传——中间页按自己的字节重新嗅探会把同一个文件解成两种文字（GB18030 的一页很可能恰好也是合法 UTF-8）。分页一律只读：`revision: null`，没有保存路径，预览里那一个「太大不能编辑」的拒绝会变成可点的「只读分页查看（大小）」，点开是**只读面板**（`FilePagerPanel`）：按 `offset` 取页、`nextOffset` 前进，没有任何保存入口 |

详见 [architecture.md](./architecture.md) 的「接管 ctx.fs」。

### 本机路径直通（localPassthrough）

**问题**：`ssh://` 会话的绝对路径默认落到远端主机根。聊天框上传的非图片附件却存在运行 DSH
的本机，模型拿到的句柄是 `$DSH_HOME/attachments/v1/files/<digest>/<name>`；不直通时它会被
解释成 `ssh://<alias>/<本机绝对路径>`，`read` / `read_image` / `node:fs` 都得到 ENOENT。

**规则**（`lib/fs/passthrough.js` 是唯一实现）：

| 输入 | 结果 |
| --- | --- |
| 本机绝对路径，命中配置前缀（默认 `$DSH_HOME/attachments`、`$DSH_HOME/plugins`） | 本机后端；读由宿主本地策略决定 |
| 本机绝对路径，未命中前缀（例如 `/Users/me/notes`、`C:\work\x`） | 仍是远端，与未开直通时一致 |
| 前缀下用 `..` 逃出去的路径（`attachments/../dsh-ssh.json`） | `normalize` 后不命中 → 远端 |
| `ssh://` 拼写 | 永远远端；配置里出现会告警并忽略 |
| 相对路径 | 跟随 cwd，不变 |
| 命中前缀的写入 | 走本机后端，**仍受本机沙箱与可写根围栏**；不把前缀加入任何 writableRoot |
| 整个 `$DSH_HOME` | 不支持，配置会被拒绝（会暴露 `dsh-ssh.json`、`dsh-ssh.key` 与会话库） |
| 用户在消息里 `@` 点名的 Windows 盘符 / UNC 路径（`@F:\\123.txt`） | 本机；由消息文本恢复意图，不靠拼写猜 |
| 显式 scheme 点名（`local:/Volumes/SSD/a.md`、`local:F:\\123.txt`） | 本机，路径是剥掉前缀后的绝对路径；`local` 是默认前缀名，可在面板「文件引用设置」→「显式文件引用 scheme」里改 |
| 未启用的 scheme 拼写（例如把前缀改名为 `host:` 后仍写 `local:/x`） | `FS_PERMISSION_DENIED` 响亮拒绝；不转远端、也不交给本机后端 |
| scheme 点名之后同名的裸拼写（`local:F:\\123.txt` 之后的 `F:\\123.txt`） | 仍是远端；点名只解锁它自己那个拼写 |
| `@` 点名以外的一切 Windows 盘符 / UNC 路径 | 仍是远端（`node:fs` 的盘符拼写本来也不会出现在远端） |
| `@src/a.js`、`@/tmp/x` | 工作区 / 远端，与宿主 `@` 语法一致 |
| 非 Windows 平台上的 `@f:\x` 一类盘符拼写 | 不登记，仍是远端 / 工作区 |
| `@` 点名的 POSIX 绝对路径（`@/Volumes/SSD/PARAMS.md`）+ 回退开关打开 | 先远端；远端**确实报不存在**时试一次本机同名文件，内容末尾附 `[ssh-workspace]` 来源说明 |
| 同上，回退开关关闭 | 纯远端，与未开直通一致 |
| 回退开关打开但没被 `@` 点名、也不命中前缀的 POSIX 路径 | 纯远端；回退只服务用户点过名的拼写 |
| 回退涉及的写 / `glob` / `grep` / 目录列表 | 一律不回退；只有读（`read` / `read_image` / `streamText` / `lstat`）回退 |

默认值来自 `$DSH_HOME`（未设置时 `~/.dsh`）；`localPassthrough: false` 或 `[]` 关闭。
匹配是**词法**的：不 `stat`、不检查存在性、不 `realpath`。因此本机恰好有一个未命中前缀的
同名文件也不会改变判定；这是为了不让“这一刻有没有这个文件”改变路径属于哪个世界。符号链接
逃逸是已知残余风险：直通只解决“路径属于哪个世界”，不扩大本机读权限，也不假装 `realpath`。
远端主机上存在同名前缀时按本机前缀优先，这是显式取舍。

**为什么 `file:` 不能当本机前缀**：`formatRemoteFileUrl`（`lib/core/protocol.js`）为**远端**路径写出
`file:///srv/x` 这类 URI。若把 `file` 配成本机前缀，同一串拼写在目录树里指向远端、在读取时
指向本机——它不是「多了一个便利前缀」，而是把一个拼写的含义在两台机器之间交换。`sftp` 同理
（`sftp://host/path` 是用户对远端最自然的写法，剥掉后 `host` 会变成路径首段、静默命中一个
看起来合理的本机目录）。因此保留名是一张冻结的、逐条带理由的表（`SCHEMES_IN_USE`），理由会
原样出现在拒绝文案里；没有「仍要使用」的逃生门。

**macOS 上的大小写假阴性是已决定不修的取舍**：APFS 默认大小写不敏感，`@/Volumes/SSD/x.md`
被点名过、模型却写 `/volumes/ssd/x.md` 时，回退闸门 `isNamed` 判 false，本机回退不会发生——
文件其实存在，本机后端也读得到。不在 darwin 折叠是**方向性选择**：折叠会同时让
`/Volumes/SSD` 的授权放开 `/Volumes/ssd`，在大小写敏感的 APFS 卷（可格式化时选择）上就是
误放行；而这里失败的方向是 fail closed（不读，且报错文案提示用 `local:` 显式拼写，当场可自救）。
真要修，必须先真的探测卷的大小写敏感性，而不是按平台名猜。

**`@` 引用这条路为什么必须看消息**：宿主的 `dsh-file-reference` 把选中的文件拼成普通提示词
文本（`@path` / `@"path with spaces"`），除文本外没有任何元数据；`dsh-file-reference-local`
的 `list()` 也只扫工作区 cwd。所以“这个路径来自用户点名”只存在于消息里：插件监听
`session/created`（重启后重扫历史，`session.deriveMessages()`）与 `session/event` 的
`user/message`，用 `hostReferencePathsInText` 抽出拼写，再交给 `addHostReference`。
判据只有一条：**Windows 盘符或 UNC**。POSIX 远端主机没有盘符，这个拼写因此无歧义地指向本机；
`/tmp/x` 两边都合法，只能由显式前缀决定，绝不因为 `@` 就改判。提取尊重引号形式，未加引号的
写法在空白或全角标点处结束（中文正文常不写空格），末尾的 ASCII 标点会被剥掉。引用表上限
256 条（先进先出），整个 `$DSH_HOME` 即使被点名也拒绝——那里有私钥与宿主凭据，而 `@` 很容易
从不可信文本里粘贴进来。

**显式 scheme 与「远端优先、miss 回退」是两道独立的门**：

- scheme（默认 `local:`）是**意图声明**。语法是 `<scheme>:` 后接 0–3 个 `/`，剥完后必须仍是
  绝对路径（POSIX `/x`、盘符 `F:\x`、UNC `\\srv\x`；不做 percent-decoding）。前缀名大小写不敏感，
  只允许小写字母、数字与 `+ - .`，`ssh` 是保留名。名字只有一份：存在 (`dsh-ssh.json` 的
  `passthrough.scheme`)，在面板「文件引用设置」一区的「显式文件引用 scheme」里改它即写穿到
  live matcher，三条消费缝（`ctx.fs.resolve` / `lstat`、`node:path` 桥接、宿主读动词）读的都是
  同一个值，不需要重启。未启用的前缀被明确拒绝
  （`FS_PERMISSION_DENIED`）——**交给本机后端是不行的**：那会让 `local:/etc/passwd` 在本机真的
  读出来，等于让模型给自己授权；静默转远端又会让用户以为前缀没生效。所以只能响。
- 回退是**存在性**判定，因此它是全仓库唯一一处 `stat` 启发式，且被三道闸门拦住：只有当 (1) 有
  本机后端、(2) 开关打开、(3) 该拼写被 `@` 点名或命中前缀时才试一次；试的方向永远是「远端先」。
  它只挂在读动词上，写、`glob`、`grep`、目录列表一律不回退——否则「远端没有」会被静默解释成
  「用户想读本机」，写和搜索会跟着串味。命中时返回的文本追加一行 `[ssh-workspace]` 说明来源，
  二进制载荷（`read_image` 的字节）不追加，避免破坏魔数嗅探。
  回退是否可试**还取决于平台**：`@` 引用表按主机平台收拼写（Windows 收盘符与 UNC，POSIX 收
  POSIX 绝对路径），所以 Windows 主机上的 `@/home/me/x.md` 从未进表、回退对它不生效。两个方向的
  miss 文案因此不同：回退试过也落空时说「两边都没有」，回退没资格试时说「这条路径按远端读的」并
  给出 scheme 写法——Windows 上还会省掉那句「去勾回退开关」，因为勾了也救不了它。

**直通的边界就是 `ctx.fs`。** 直通的判定点在 `ctx.fs.resolve` / `lstat` 与 `node:path` 的桥接里，
所以只有**经过 `ctx.fs`** 的文件系统调用会命中它（宿主 `read` / `write` / `edit` / `read_image`、
插件自己的工具、`node:fs`）。绕开 `ctx.fs` 的读取仍然碰不到本机后端：

| 入口 | 是否走 `ctx.fs` | `ssh://` 会话里读本机路径 |
| --- | --- | --- |
| 宿主 `read` / `write` / `edit` / `read_image` | 是 | 直通生效 |
| `node:fs`（经插件桥接） | 是 | 直通生效 |
| `dsh-tool-fs-search` 的 `glob` / `grep`（直接 spawn `rg`） | 否 | 仍按远端执行（远端路径正确；本机路径读不到） |
| dsh-ops 的 `inspect_local_file` / `read_files` / `glob` / `grep` | 否 | `EXECUTOR_UNAVAILABLE` |
| `ops_bash`（带 `workdir`） | 否 | `invalid workdir` |

dsh-ops 把**会话 cwd 原样**交给本机的 `dsh-ops-worker.exe`；`ssh://` cwd 在
`lib/patch/patch-subprocess.js` 的远端桥上只放行 `git` 与 `rg`，worker 因此被拒。worker 是本地
Windows 可执行文件，它的 `is_absolute` + `canonicalize` 也消化不了 `ssh://` 拼写——这是
「本地进程 + 远端根」的结构性错配，不是拼写问题，也不是授权拒绝；**重试与换本机 shell 都无用**。
替代入口：读远端用 `ssh_workspace_exec` / `ssh_workspace_shell`，读本机文件用
`ssh_workspace_transfer` 上传到该主机 `/tmp` 再读。

### 写入的两道围栏是两件事

| 围栏 | 回答的问题 | 拒绝时的码 |
| --- | --- | --- |
| 沙箱模式 | 「这个会话允许写吗」——`read-only` / `workspace-write` / `danger-full-access` | `FS_SANDBOX_DENIED`（宿主会改写成 `[sandbox: …]` 标记 + 升权提示） |
| 挂载根 | 「这个目录被服务吗」——目标是否在某个已挂载 `ssh://` 根之下 | `FS_OUTSIDE_WORKSPACE`（原文直达模型） |

**为什么要在远端重做模式判定**：本机沙箱的实现是 `SandboxedFileSystem.checkedTarget`，一个原型方法；
插件用同名自有属性接管了 `writeText` / `editText`，远端分支根本不调用它。所以不加这一步，`read-only`
会话照样能改远端文件，且全程无任何提示——模型的系统提示还明确要求它「不要仅凭策略就拒绝，先试」，
于是它试成功了，从模型视角看完全合规。

**工作区内的修改算不算数？** 算。`workspace-write` 要求目标落在**会话自己的**工作区之内，
与本地同一条规则（本地是 `writableRoots(policy)`，第一项为 `policy.workspaceRoot`）。
这个 root 不是「本机上的路径」——实测 `SandboxPolicyService.resolve({ session })` 返回的是
`session.header.cwd` 原样，远端会话拿到的就是 `ssh://dev/home/dev/proj` 这种拼写，可以直接
比较。此前文档说「不比较，因为那是本机路径」，是**错的**；不比较的后果是一个会话能写同一
主机上的兄弟根、甚至另一台主机上的已挂载根，而本地会话做不到这些。

| 目标 | `workspace-write` 的结果 |
| --- | --- |
| 会话工作区内 | 允许 |
| **该主机的 `/tmp`**（会话工作区外） | **允许**——与本地一致，见下 |
| 同一主机的兄弟目录（即使已挂载） | 拒绝，`FS_SANDBOX_DENIED`，文案点名会话工作区 |
| 另一台主机的已挂载根 | 拒绝，文案点名两个主机 |
| 未挂载路径（`/tmp` 之外） | 拒绝，`FS_OUTSIDE_WORKSPACE`（挂载围栏，另一道） |

**为什么远端也允许 `/tmp`**：本地的 `writableRoots(policy)` 除 `workspaceRoot` 外还列了常量
`/tmp` 与 `os.tmpdir()`（`dsh-sandbox/lib/index.js`，注释明写「漏掉它就会拒绝这个模式本来承诺
允许的写入」）。远端此前把 `/tmp` 判成「工作区外」而拒绝，于是**远端构建全部写不了暂存文件，而本地
同一份构建正常**——这正是本地注释里点名的那种偏差。现在 `/tmp` 与它的子目录算作可达，判定仍是
词法的（不探测 `$TMPDIR`），且**只对已经有挂载根的主机生效**：只知别名、什么都没挂载的主机仍然
不可达，「先挂载」这条没有变松。`danger-full-access` 同样受益——否则会出现「更宽的模式反而更窄」
的非单调结果。

**模式读不懂时按最严格处理**：`read-only` / `workspace-write` / `danger-full-access` 之外的任何
字符串（未来新增的模式名、fold 损坏出的值）现在**拒绝**，写入与命令都是。本地后端对同样的输入走的
是 containment 分支且 `writableRoots` 返回 `[]`，即一律拒绝；远端此前会同时跳过模式围栏与范围围栏，
只剩挂载根——同一个输入「本地收紧、远端放开」。拒绝文案**不会**谎称这是你选的「仅可查看」：切换模式
修不好一个读不懂的字符串，文案会列出被认可的三个模式。策略服务**完全缺席**仍是「不受限」而非拒绝，
这条没有变。

**命令则不然**：`workspace-write` 下远端命令仍以远端登录用户权限运行，无法收窄到工作区——
限制**进程**需要内核边界，而它跨不过 SSH。文件写入被收窄，命令没有被收窄，这个差别是
如实的，不是遗漏。

**一条隐含依赖，必须知道**：上面说的「会话 root 可以直接比较」依赖 `fs-shim.js` 对
`node:path.isAbsolute` 的补丁（让 `ssh://…` 读作绝对路径）。`SandboxPolicyService.resolve`
会对 `session.header.cwd` 调用它，缺了这个补丁就会抛
`workspace root must be an absolute execution-world path`，于是**每个远端会话**的策略解析
都失败。插件对这种失败的做法是 fail-closed（拒绝），但拒绝文案会明确说这是**接线问题**、
切换模式无用，并引述底层错误——不会谎称你选了「仅可查看」。这条依赖的脆弱性已实测确认：
裸 `node:path` 下 `isAbsolute('ssh://dev/home/dev/test')` 为 `false`，打上补丁后为 `true`。

`node:fs` 桥接（`fs-shim.js`）**不看模式**，这是刻意的：它服务的是宿主自己的记账调用
（新建会话 cwd 的 `mkdir`、注册表的 `stat`/`realpath`、变更追踪的快照拷贝），本地同一批调用同样不受
`ctx.fs` 沙箱约束。而且它只看得到部署默认模式、看不到会话级覆盖，按它判定会得出错误结论。
模型面向的写路径走 `ctx.fs` 与插件自己的工具，那条路上模式是生效的。插件自己的工具不经 `ctx.fs`，
所以它们**各自解析** `ctx.sandboxPolicy.resolve({ session })`：`ssh_workspace_transfer` 的上传
（写入远端）与下载（**写入本机**，走 `node:fs`，宿主 sandbox 看不到）都在 `read-only` 下被拒。下载
在 `workspace-write` 下只允许本机临时目录或会话自己的本地工作区根（远端会话没有本地根，因此只允许临时
目录），`danger-full-access` 才放开到任意路径；策略解析失败同样 fail closed。上传现在**四条围栏全部与
`write` / `edit` 一致**——模式（`writeModeRefusal`）、工作区范围（`workspaceWriteScopeRefusal`）、
挂载根（`assertWithinRemoteRoots`）、符号链接真实落点（`assertFencedRealpath`），所以两条写路径不会分叉：
一个 `write` 会拒绝的落点，上传同样拒绝，且**在写入任何字节之前**拒绝。此前上传缺后两条围栏，实测能
把字节落到未挂载的 `/etc/cron.d/…`（而 `write` 到同一拼写报 `FS_OUTSIDE_WORKSPACE`）——那正是
「两条写路径不会分叉」这句话当时的反例，现已由 `transfer-smoke` 的失败反证钉死。策略服务
缺席＝不受限，但**策略解析失败按拒绝处理**——拒绝一次可重试的上传，好过在「仅可查看」会话里静默写入；
文案会区分这两种情况。浏览器面板的上传/下载走 HTTP 路由，是**用户自己的动作**，只受挂载根与停用围栏
约束，**不受会话模式约束**（与本地文件面板同理：模式管的是 agent，不是用户）。


### 命令执行是另一条独立的写路径

只堵文件写入是不够的。插件有**六条**改远端的路，它们不共享调用链：

| 表面 | 到达远端的方式 | 模式的判定位置 |
| --- | --- | --- |
| `write` / `edit` | `ctx.fs` 路由 | `remote-fs.js`（每次调用带 policy） |
| `ssh_workspace_transfer` | SFTP 暂存 + 原子改名 | 工具自己解析 policy |
| `ssh_workspace_exec` | `engine.exec` | `mode-gate.js` |
| `ssh_workspace_shell` | PTY 通道 | `mode-gate.js` |
| `bash` / `pwsh`（workdir 为 `ssh://`） | `ctx.shell` → `patch-shell.js` | 读 spec 上的 `sandboxPolicy` |
| `terminal_open` / `terminal_send`（cwd 为 `ssh://`） | `ctx.subprocess.spawnTerminal` | `patch-terminal.js`：开 PTY 时拒绝，且**每次写入**重新判定 |

这六条读的是**同一个** `sandboxPolicy.mode`，而且模式判定本身**共用同一份代码**：`write` / `edit`
与 `ssh_workspace_transfer` 的上传都调用 `mode-gate.js` 的 `writeModeRefusal`，四条命令表面共用同一模块
的 `assertRemoteCommandAllowed`。分歧的风险因此只剩下「模式取自哪里」——六条的主判据都是会话级策略
（`write` / `edit` 用宿主传入的第五个参数 `sandboxPolicy`，其余五条自己 `resolve({ session })`）；
只有 `write` / `edit` 在策略缺席时回落到部署默认，那是无 agent 的调用，本地后端对同样的调用也用部署默认。
（`FS_SANDBOX_DENIED` 由宿主改写成 `[sandbox: …]`，与本地一致。）

**还有一层在它们之前**：宿主的每条命令通路都先跑 `ctx.sandbox.confine(argv, policy, signal)`，之后才到
`ctx.shell` / `ctx.subprocess`。它拿到的 `workspaceRoot` 同样是那个 `ssh://` 拼写，而 Windows ACL 提供方
按**主机路径**解析它——`realpath` 抛 `ENOENT` 后 fail-closed，命令一条都不起来（文案是
`windows-acl workspace and temp directory resolution failed`）。`lib/patch/patch-sandbox.js` 因此先接管
`ctx.sandbox.confine`：只把 policy 里的远端根换成本机真实存在的替身目录，`mode` 与 `sessionId` 原样带过，
**不动 `sandboxPolicy.resolve`**——上表中「会话工作区」那一列的收窄正是拿那个拼写做比较的。

这不是预防性设计：曾有一个 `read-only` 会话执行
`ssh_workspace_exec { command: "rm /home/dev/test/test.py" }` 并拿到 `[exit code: 0]`，而同会话的
`write` 是会被拒的。

**为什么是「拒绝」而不是「过滤」**：本机沙箱回答「这条命令能不能写」的方式，是把**进程**用内核边界
（bwrap / seatbelt / 受限 ACL 令牌）限制在工作区根内。这些机制一个也跨不过 SSH——远端命令以远端登录
用户的完整权限运行。没有哪个 seam 能接收一个 `workspaceRoot`，而用文本匹配去猜一条命令是否会写也不是
边界：`sh -c 'rm -rf ~'`、`find -delete`、`python -c ...` 读起来都像纯文本。

所以只有两个选项：允许任意远端命令、让模式成为一句空话；或者拒绝、让模式说真话。插件选后者，并在
拒绝文案里写明原因与出路（切到 `workspace-write` / `danger-full-access`），因为一条模型没预料到的拒绝
会被当成 bug 反复重试。

**读不受影响**：`read` / `glob` / `grep` / `ops_*` 走 SFTP，不需要执行命令。代价是失去任意命令执行
（远端 `git status`、构建），这需要用户显式切换模式来解锁。

**终端为什么有两道判定**：`ctx.subprocess.spawnTerminal` 的 spec 里没有 owner（只有 `cwd` / `argv` /
`env`），所以门禁不能装在那里；而它也不是单一入口——宿主有**两条**路会走到它：

| 路径 | 经过 |
| --- | --- |
| `terminal_open` / `terminal_send` | `ctx.terminals.spawn` → `dsh-terminal-bash` → `spawnTerminal` |
| 侧边栏的内建终端（`dsh-api-terminal-controller`） | **直接**调用 `spawnTerminal`，完全不经过 `ctx.terminals` |

因此把门禁装在 `ctx.terminals` 上会漏掉第二条——而只测工具路径的用例仍会通过。门禁装在
`patch-terminal.js` 的路由里（两条路唯一的汇合点），会话身份取自 `spec.env.DSH_SESSION_ID`
（两个调用方都会写它），再用 `ctx.get('agents').get(id)` 换成 session。

判定分**两半**，因为只拒「打开」只能保护本来就处于 `read-only` 的会话：

- 开 PTY 时拒绝，且**没有任何通道被打开**；
- handle 的每次 `write` 重新读一次模式——在 `workspace-write` 下开的 shell 被切成 `read-only` 后
  立刻停止接受命令。这是实际更常见的顺序：先开终端干活，再收窄模式。

控制字节是例外：SIGINT（`\x03`）与关闭路径必须继续可用，否则「仅可查看」会变成「连你已经启动的
命令都停不掉」。

`node:fs` 桥接（`fs-shim.js`）同样**不看模式**，原因见上：它服务宿主自己的记账调用，本地同一批调用也不受
`ctx.fs` 沙箱约束，而且它看不到会话级覆盖。

## 三、远端执行

| 功能 | 说明 |
| --- | --- |
| `pwsh` / `bash` 远端化 | 会话工作区是 `ssh://` 时，这两个工具的命令**在远端以 POSIX shell 语义执行**；一次性命令、后台任务、超时与中止都按 DSH 的进程契约工作；本地 `workdir` 的命令仍在本机沙箱内 |
| 无沙箱约束 | 远端命令以远端登录用户的**完整权限**运行，不受本机文件沙箱限制——正因如此，`read-only` 会话的命令执行由插件**直接拒绝**（见上节「命令执行是另一条独立的写路径」），而不是尝试围栏 |
| `ssh_workspace_exec` | 不依赖挂载即可在远端跑命令（主机巡检、挂载根之外的路径、装机脚本），支持 `run_in_background` 与 `timeoutMs` |
| `ssh_workspace_shell` | **持久**远端 shell：`cd`、导出的变量、后台任务跨调用保留，像一直开着的一个终端；可按名字并存多个会话；PTY 通道，退出码由命令行末尾的标记行取回 |
| glob / grep 远端化 | 调用**远端主机上的 ripgrep**，返回真实远端路径；`rg` 缺失时以退出码 **127** + 安装提示失败 |
| 命令白名单 | `cwd` 为 `ssh://` 的子进程只放行 `git` 与 `rg`（全 asar 扫描确认只有搜索工具与变更追踪两个消费方）；其余本机可执行文件**同步抛**错，不上传二进制 |
| 变更追踪远端化 | 「变更」面板用**远端 git** 做回合快照与 diff，远端 shell 改的文件也会出现在列表（+N/−N、可看 diff）；未装 git 时按「无仓库」降级，每回合一条 warn，不阻断会话 |
| 逐文件文本对比是远端盲区 | 宿主的整文件捕获（`@deepseek-ai/dsh-workspace-changes` 的 `captureFile()`）用 `node:fs` 打开 `ctx.fs.processPath(target)`；远端目标拿到的是**远端路径**，两次捕获都 `ENOENT` → `{kind:'absent'}`，`sameCapture()` 判等后**整条记录被丢弃**。捕获不经过 `ctx.fs`，插件无法替换读取，只能**不让它静默**：首次远端写入时往诊断环记一条 `degraded`（status 工具与面板状态路由都可读）。变更列表仍由 git 提供，缺的只是逐文件 before/after 文本 |
| 快照目录镜像 | 本机 `mkdtemp` 的 git 快照目录（`GIT_OBJECT_DIRECTORY` / `GIT_INDEX_FILE`）改写成远端 `/tmp` 下同后缀并 `mkdir -p`——远端 git 看不到本机路径 |
| 持久终端 | 接管 `ctx.subprocess.spawnTerminal`：`cwd` 为 `ssh://` 时开 SSH PTY 通道而非本地进程，handle 满足宿主的 `output` / `write` / `resize` / `done` / `inspectForeground` / `signalForeground` / `terminate` 契约；默认 **80×24**，按 spec 调整。**启动哪支 shell 由远端探测决定**（见下一行） |
| shell 菜单与启动一致 | 菜单项由**远端主机**回答：接管 `ctx.terminalController.shells()`，对 `ssh://` 会话一次往返跑 `command -v` 探出这台主机真有哪几支（`$SHELL` 那支排第一，按家族去重），本机会话原样交给原方法。启动侧只采用**探测到过**的路径（`argv[0]` 命中该主机已发现集合 → 按发现到的绝对路径 + `-l` 启动），其余仍沿用按家族 `command -v` 兜底、最后回落 `sh -l`；**宿主 argv 里的 `-i` / `-NoProfile` 一律丢弃**（那是本机方言的产物）。探测不到就**报错**、菜单显示 failed 并可重试，绝不改名成一份本机 shell 列表；缓存按「主机 + 连接代次」，**只在重连时重探**（无 TTL、无手动刷新）。查表按**家族**匹配（`basename` 去 `.exe` 小写），所以本机默认 shell 是 bash 时「不选直接开」也会落到远端那支 bash；只有该主机没有这个家族时才回落 `sh -l`（安全降级）。副作用是它不会认「远端的默认登录 shell」本身——那要替换 `resolveShell` 的语义，属宿主内部函数，留作独立议题 |
| `inspectForeground` 的取舍 | 本地 handle 靠本机进程表回答，单条 SSH 通道无法廉价等价；宁可回答「未知」也不猜（错误答案会让宿主以为还有前台进程、白等整个超时） |
| UTF-8 跨块正确性 | 输出用 `StringDecoder` 拼接，多字节字符跨 chunk 边界不再变成两个替换符；截断按**字节**记账并回退到完整字符边界 |
| 命令审计（四个通道都在） | 每条远端命令都进一个有界环（默认 200 条，`seq` 单调、淘汰后不回退）：`exec`（工具与路由）、`background`（后台任务）、`shell`（持久 shell，由 `ShellManager.run` 自己记，因为 PTY 不经过 `engine.exec`）、`terminal`（**击键捕获**，见下两行）。命令在**写入时**脱敏并截断（400 字符），错误 200 字符，stdout/stderr **从不记录**；拒绝（模式闸门、确认框取消）与「结果未知」各记一条，因为它们回答的正是「到底跑没跑」 |
| 终端击键捕获（近似） | 终端里敲的命令也进审计：`RemoteTerminalHandle.write()` 在字节**被通道接受之后**喂给一个按字节处理的小状态机——可打印字符累积、退格与 Ctrl-U 删、Ctrl-C 丢弃该行、回车成条、方向键/功能键的 CSI/SS3 序列与 OSC 串整体跳过。它**不模拟行编辑器**：Tab 补全、历史展开、多行 here-doc 的还原都只是近似，所以 UI 与文档都把它标成近似而非真相；记录里 `exitCode` 为 null（击键没有状态） |
| 审计落盘 | 环同时写到 `$DSH_HOME/dsh-ssh-workspace/dsh-ssh-commands.json`（`{version:1, entries:[…]}`）：变更后 500 ms 防抖、暂存文件 + rename 原子替换、0600、目录 0700、内容未变不重写；重启时读回并按容量裁剪，读回的行走与实时行**同一个清洗器**（脱敏与字段上界一致）。四条上界：条数（保留条数设置）、字段、无输出、**文件 512 KB**——超了丢最旧的行，而不是改形状 |
| 保留条数与审计 tab | 面板第四个 tab「审计」按时间倒序列出全部保留命令（时间、主机、通道、状态、命令、错误），可按工作区过滤（用 `/status` 已下发的 `sessionIds` 做本地投影，不多发请求），并有「刷新」。保留条数 1–2000（默认 200）在同一个 tab 里改：`POST /audit/settings` 先落 store 再改环，改小立刻裁剪；坏值落回默认而不是报错。行数据来自独立的 `GET /audit`（不挤进每两秒一次的 `/status`） |

详见 [architecture.md](./architecture.md) 与 [tools.md](./tools.md)。

## 四、本机 ↔ 远端传输与文件树操作

传输本体（工具、队列、归档、重试）之外，文件树一侧的批量动作（多选、拖入任务、批量下载、
重命名 / 删除、新建文件 / 文件夹、空白处菜单、打开方式）也在这里，因为它们回答的都是
「这个文件从哪来、到哪去」。

| 功能 | 说明 |
| --- | --- |
| `ssh_workspace_transfer` | 经 SFTP 双向拷贝，字节**不经过对话内容**；适合推构建产物、拉日志 |
| 目录树传输 | `recursive: true`，**两个方向都支持**；下载时树内的 symlink 只列出不跟随（跟一个指向 `/` 的链接会把"下载这个目录"变成无界遍历）。冲突策略按**每个文件**判定，不是整棵树 |
| 树传输的排除规则 | `exclude: string[]`，**两个方向共用同一份匹配**（`lib/transfer/transfer-rules.js` 的 `treeFilter`）；两侧各自解释一遍规则必然漂移——上传跳过 `node_modules` 而下载保留它，这种不对称在有人对比两棵树之前看不见。语法刻意不是 `.gitignore`：按路径段（`node_modules`）、通配（`*.log`）、从根锚定（`build/output`）、目录限定（`tmp/`）、`!` 反选，**最后匹配的一条说了算**。被排除的目录**不创建**，`refuse` 的预检也跳过它们 |
| 上传原子发布 | 先写同级暂存名再 `rename`；目标在被替换前读到的始终是旧内容或完整新内容，不会是半截文件；失败清暂存并保留原内容 |
| 下载读至 EOF | 不依赖 stat 时的长度，因此传输期间变长的文件会被完整取回 |
| 分块流式 | 每块 **256 KiB**，大文件只占有限内存 |
| 单文件上限 | **1 GiB**（超出直接拒绝，不静默截断）。工具与浏览器两条路由是**同一个常量**（`transfer.js` 导出、`routes/transfers.js` 引用），超限回答 413 |
| 浏览器内上传 / 下载 | 唯一的浏览器上传入口是文件树行右键菜单（**文件面板头部按钮与目录浏览对话框都不提供上传**：前者只留进度入口，后者已收窄为只浏览/挂载）。上传走**同一个传输队列**：一次可选多个文件、逐项入队、串行执行。上传统一走 `POST /upload-chunk`（JSON + base64 分片）——它是唯一同时能给出**逐块进度**与**块间取消**的通道，桌面壳的 `dsh-app://` 也承载不了 `File` 请求体；`POST /upload` 的原始字节路由仍留在服务端（有独立围栏与测试），只是浏览器不再使用。下载走 `GET /download` / `GET /download-tree` 把字节直接写进响应；单文件有 `content-length` 才画百分比，目录归档没有总量，只报已传字节 |
| 从系统拖入文件 | 远程工作区的「文件」树可直接接收系统文件拖入并上传：落点决定目标目录——目录行自身、文件 / `other` 行父目录、展开目录内的嵌套空白归该目录、树体空白与树头 / 路径标签归根；不自动展开目录，只接收文件。拖入文件夹整批拒绝（不递归）：与文件混合时跳过说明搭在同一条批次提示上，只有文件夹时才单独提示；本地工作区明确拒绝且不交给 composer；树内拦截宿主附件，树外保持 DSH 原有附件行为。上传复用同一个队列与同一个超限提示。目标规则与退化矩阵见 [ui.md](./ui.md#从系统拖入文件上传)。 |
| 传输队列 / 进度浮层 | 队列是浏览器侧**唯一**的传输状态：同一主机同时 1 个、跨主机上限 2；入队前按服务端同一个 1 GiB 上限预检，超限文件**一次列全**而不是排队后再失败。浮层入口是文件面板头部的一个**图标**（托盘箭头，和行内的下载记号同一组几何），**只在面板显示 `ssh://` 远程工作区时渲染**（本地目录沿用宿主自己的头部，队列属于远端；本地视图里开始的远端传输由完成提示继续报告）。在远端列表里它**常驻**——空队列也不隐藏：空闲时是中性色的裸图标，有排队或运行中的项时整枚变蓝并套上聚合进度环（方向取自行中的传输方向，进度按字节加权合并，任一运行中的目录归档没有总量时改为旋转弧而不是编造百分比），数量改由无障碍名称「查看传输进度（N 项）」给出；此前它会随队列清空而消失，被读成控件坏了，浮层空态因此要有内容。逐项显示方向、名称、百分比或字节、速度与浅蓝色进度条，可单独取消与「清除已完成」；列表的**绘制顺序**是排队/运行中在上（按到达顺序）、已结算在下且**最新在前**——store 仍按到达顺序调度；此前一律按到达顺序绘制，下载几次之后最新一行落在 320px 可视区外，打开浮层看到的是最老的行，容易被读成「这次下载没有记录」。目录浏览对话框不内联队列，只浏览与挂载。速度由状态机按动作时钟采样（不足 250 ms 不更新、停顿超过 5 s 归零重测）；进度条只在知道总量时按百分比填充，目录归档用扫描动画。每行只有三个动作：**暂停 / 恢复**、**取消**、失败项的**重试**。暂停会**中断在途分片**（不是只拦住排队项），已写入的暂存与 sidecar 保留；确认停下后该行变为暂停并**让出主机 / 全局槽位**，恢复按原到达顺序重新入位，从断点继续。失败项重试会**重新判定冲突**，上传先探测暂存前缀、只补缺失分片；重试成功走双侧 SHA-256 校验并在结果行写出「已校验 / 未校验及原因」。源文件在两次尝试之间改变时服务器拒绝续传，客户端从 0 重传并说明原因。取消上传会发 `abort` 清掉暂存，暂停中被取消同样清理，远端不残留 `.dsh-up-*`。同名文件策略是**覆盖**，选择入口与右键菜单都写明 |
| 传输重试与校验 | 失败项的重试不复用第一次的判定：上传每次发布前重新走 `decideConflict`，暂存前缀用 sidecar 里的源身份（大小 + mtime）校验，只补缺失分片；下载重试把 `resume` / `verify` / `onConflict` 交给 `POST /transfer`，服务端从本地 staging 的 sidecar 续写。重试的上传在末片带上源端 SHA-256 与 `verify: true`，下载要求服务端在发布后比对双侧摘要；结论写进队列行的 note（`已校验` 或 `未校验：原因`），缺 hasher 时同样明说，不把「没校验」报成成功 |
| 下载图标的空闲 / 运行态 | 下载控件不再用 `↓` 字符：`DownloadIcon`（托盘 + 下箭头）与镜像的 `UploadIcon` 是两处入口共用的同一组 svg（队列行、右键菜单）；某个路径的下载在队列里运行时，该行换成 `TransferProgressIcon`——灰轨道 + 蓝色弧线，环内仍是同一箭头（命令词 + 刻度）。文件面板头部的进度入口也用它；环的读数来自 `transferQueueProgress`，按字节加权并跟随队列的方向。已知总量按比例填充并封顶 99.5%（满圈时圆头会叠出接缝），未知总量（目录归档）转固定 30% 弧而不停 0%，排队中只有空环。队列行运行中变蓝；行内下载在下载期间禁用，避免同一路径重复入队。匹配按 `alias` + `remotePath`（`downloadQueueItemFor`），重试取最后一条；环的旋转在 `prefers-reduced-motion` 下停止 |
| 浏览器下载目录 | 文件树行菜单提供「下载目录」，走 `GET /download-tree`，默认答复 **zip**（`?format=tar` 仍可用）。浏览器拿不到一个目录，归档是一个文件——一条下载流。字节随读随发，不落盘暂存，所以大树的峰值内存有界。树内的 symlink **跳过并在归档内的 `SKIPPED.txt` 里逐条列出**；被排除规则跳过的路径数也写在那里 |
| 下载失败带真实状态码 | 响应头未发出时按 `FsError` 码答复（`FS_NOT_FOUND` → 404、权限类 → 403、类型不符 → 400、其余 → 500）；**不能答 200**——浏览器只认状态码，2xx 的 JSON 错误体会被存成文件 |
| 右侧文件树多选 | 直接做在宿主「文件」标签里，不需要插件标签页或对话框：单击目录照常进入、**单击文件既选中也照常打开**（多选叠加在原习惯上，只有带修饰键的单击才吃掉导航）；Ctrl/Cmd 命中目录只选中不进入，Shift 按 anchor 选区间且不移动 anchor（选择按「会话 + 工作区根」跨标签页重挂载存活，锚点存路径）；**第一次 Shift 会直接播种锚点，因此连续两次 Shift+click 就能连选，不需要先普通点击——普通点击文件会打开预览**；Ctrl+Shift 追加；**右键同样守多选语义**（选择之外收拢到该行、选择之内保留整批、Ctrl 切换、Shift 扩区间，一律不打开）；空白 / Esc 清空，Ctrl+A 含目录；方向键 / Home / End / Ctrl+方向键 / Shift+方向键同一套规则，Enter 打开、F2 / Delete 改名删除。**不渲染复选框、没有选择模式开关、树下不浮出批量条**。菜单文案**固定不随选择数变化**：「删除」「下载到本机」各只有一项；作用范围由 `resolveTargets(clickedRow, selection)` 唯一决定——选中集包含该行且不止一项时为整批，否则先把选择收敛为该行。数量不在菜单里，而在删除确认框与下载目标对话框。面板「设置」里「查看文件」选为**会话中查看**时，**普通单击不再打开右侧预览**，改在输入框上方显示（见下一行）；`Ctrl/Cmd+click` 仍按宿主的右侧预览打开，多选的其余语义不变 |
| 展示文件 | 两个目录对话框（「浏览目录」与「新建远程工作区」）默认**只列目录**；面板「设置」→「文件查看」勾「同时列出目录里的文件」后，`/ls` 不再带 `dirs=1`，改走同一套**一次往返的全量列目录**（目录优先、同一套截断规则，`total` / `truncated` 仍统计全部条目）。文件行是**纯展示行**：不可点、不可双击、不参与「选中的目录」，只回答「这个目录里有什么」；目录行的单击/双击/键盘语义一概不变。关闭开关即回到只列目录 |
| 会话窗查看文件 | 右侧文件树的文本类文件可以显示在**会话窗里**，不新增任何按钮：面板「设置」→「文件查看」二段式切换选「会话中查看」后，普通单击文件（或 Enter）在会话顶部标签条里开一个**同名标签**（与「对话 / 轨迹 / Git 图谱 / billion 上下文」同排）——`app.ts` 的标签就叫 `app.ts`，**每文件一个、可同时开多个**，点标签在它们之间切换，各自的滚动位置 / 草稿 / 未保存状态互不影响；内容**就是编辑器本身而不是浮层**：同一个 `FileEditorPanel` 以 inline 模式铺满宿主 `.viewArea`，不 `position: fixed`、不进 portal、无边框 / 圆角 / 阴影 / 重复标头，正文**复用右侧预览的编辑器**（CodeMirror 6 + 语法高亮、行尾/BOM 保真），可编辑并按 `version` + `revision` 双令牌经 `write-text` 就地保存，冲突时给出重载 / 二次确认覆盖；`×` 绝对定位在标签右侧、文件标签统一固定宽度（132px / 22px 留给 `×`），`Esc` 等价，有未保存改动先确认；关掉一个只收掉它自己的标签，关掉最后一个时会话回到「对话」（懒注册，没开过文件的会话不会多出空标签），切回「右侧文件树」偏好时一次性收起全部。**默认「右侧文件树」= 现行为**，升级零变化。`.md` / `.markdown` / `README` / `CHANGELOG` **也在接管之列**，且打开时默认是**排版预览**（顶部一条细栏切「预览 / 源码」；预览渲染标题、代码块、引用、列表与任务框、表格、行内样式，相对链接与 `javascript:` 只留文字、原始 HTML 当文本、图片是带 alt 的占位、frontmatter 原样框在上方、超过 400 KiB 只渲染开头并提示；有未保存改动时不切，先保存或撤销）。`mdx` 与其它文本按源码打开；图片、PDF、二进制与其它未知后缀**不接管**，仍走右侧预览；`Ctrl/Cmd`、`Shift`、`Alt` + 单击也仍归宿主（多选与右侧预览的逃生口）。**输入框不属于任何视图**——它是视图区下方的 sticky 座位，文件标签打开时仍在最底部，所以「文件查看」里另有一个「文件标签页里隐藏输入框」（`preferences.hideComposer`，默认开）：打开时整条输入区收起、文件占满整列，关掉就保留输入框边看边聊。读取经编辑器同一条 `read-text`（远端与本地同一条路），超出 2 MiB 走只读分页；**标签属于打开它的会话**——切到别的会话（工作区）就看不到它们，切回来还是原来那几个标签、原来那个文件（插件按会话记账，离开只注销注册、不关闭文件；地标 `[data-conversation-session]` 一变就换名单）；面板**按滚动区定高**（`clientHeight` 减去输入框座位高度），正文自己内部滚，底部那条「行数 / 自动 (LF) / 自动换行 / 保存」不随会话滚动条移动；状态 per-session、不写 session event、刷新即消失 |
| 多选整批拖入 | 把整批选中项一次拖进输入卡：`dragstart` 用 `resolveTargets` + `treeSelectedItems` 取目标集合（点在选中之外时先按 `point` 手势收拢），载荷写成版本化 JSON `{v:1, items, root}`，只进自定义 MIME；`drop` 只调一次 `addPathsToTask`，逐条插入、重复路径只插一次、末尾**只聚焦一次**且聚焦的是接住投放的那张卡；行菜单「添加到任务」用同一个目标集合与同一个助手。拖动结束清掉树行里残留的文本选区，光标落在 chip 之后。拖放落点会传给插入助手：指针在输入框内时第一个 chip 插在指针处，后续 chip 跟随；多张可见输入卡、卡片内边距、浏览器不给 caret 或映射失败时回退追加到选区/末尾 |
| 批量下载只问一次位置 | 目标超过一项时，点「下载到本机」先弹出确认（副标题写明「将下载 N 项到本机」，混选时说明跳过多少本地行）再选**一个目标目录**，随后整批入队；不再每个文件弹一次保存框。四种结局各有去向：浏览器 `showDirectoryPicker` 的目录句柄 → 客户端流式落盘；宿主目录选择器（`__DSH_DIRECTORY_PICKER__` / `uiWorkspace.pickDirectory`）返回路径 → `POST /transfer` 的 `recursive` 下载由服务端直接写该路径；用户取消（异常文案匹配 `/cancel\|abort\|dismiss/iu`）→ 整批取消，**不**退化成逐个弹窗；两种选择器都没有 → 逐项回落到单文件保存框。`showDirectoryPicker` 存在但被拒（非 `AbortError`）时回落到宿主选择器而非当作取消。`localDir` 路径要等整棵树写完才返回，所以取消是**轮询**（150ms）`ctx.isCancelled()` 后 `abort()`，中止请求即让服务端停止遍历，`finally` 清定时器 |
| 重命名 / 删除（远端与本地） | 宿主树行菜单使用 `POST /rename`、`POST /delete`。远端围栏：挂载根、停用、只读会话；本地边界只取自服务端会话/策略——请求里的 `root` 只是选取会话的线索，没有会话拥有它即拒绝。**重命名在行上做**：文件名原位变输入框（portal 到 `body`、按名字 span 的 `getBoundingClientRect()` 定位、不依赖宿主 class），Enter 提交 / Esc 取消 / 失焦且有改动提交；三态判定 `inlineRenameDecision`——空或原名 → 取消，非法名 → 拒绝（**保持打开**并标 `aria-invalid`），其余提交；`settled` 防重复提交，模态框仅作行已失效时的兜底。只改名不换目录、目标已存在拒绝；删除目录递归且先确认（数量 + 名称 + 含子目录 + 不可恢复）；跨设备不退化 copy+delete；软链只删链接本体 |
| 新建文件 | **远端目录行**右键菜单与远端**空白处**菜单新增「新建文件」，排在「新建文件夹」之前；本地工作区从**空白处菜单**进入（本地行不提供，宿主树拥有本地创建）。走独立的 `POST /create-file`：请求父目录路径 + 单个路径段名，与 `mkdir` 同形状。建出来是 0 字节文件，内容交给编辑器（空文本可预览、铅笔可编辑、可保存）。已存在 409、越界 403、只读 403、停用 403、父目录缺失 404、父目录是文件 400、名字带分隔符 400 均在写盘前拒绝；点开头的名字（`.gitignore`）放行。成功后刷新树、选中并聚焦新行，**不自动打开**。远端用 `'wx'`（`O_CREAT|O_EXCL`）独占创建，先查后写只是把「已存在」变成 409 而不是 500；本地用 `open(..., 'wx')` |
| 新建文件夹 | 宿主文件树的**远端目录行**右键菜单新增「新建文件夹」，与重命名 / 删除同一组；本地行不提供（本地新建走空白处菜单）。走 `POST /mkdir`，请求父目录路径与名称。围栏与改名同一套：挂载根内、工作区已启用、会话可写，名称必须是单个路径段；目标已存在答复 409，越界 403，非法名 400，父目录不存在 404。成功后重新列目录并选中新行。路由按 `path` 拼写分支，本地分支（由空白处菜单驱动）的边界只取自会话/策略，`realpath` 父目录防符号链接逃逸 |
| 本地空白处菜单 | 本地工作区「文件」树的空白处右键恰好三项：「新建文件」「新建文件夹」「复制路径」。目标目录是空白处所属的那一个——落在某个已展开目录的嵌套列表里就是那个目录，否则是树根；两者都必须在该树根之内。两个新建分别走 `POST /create-file` 与 `POST /mkdir` 的本地分支并选中新行；「复制路径」始终可用，只读会话只禁用两个新建。远端工作区保留原有空白处菜单。**菜单只在文件面板内部弹出**：作用域是 `[data-files-page]` 而不是 document，会话窗口与其它页面区域的右键交还浏览器原生菜单 |
| 空白处菜单只在文件面板内部 | 插件右键菜单的合法位置只有两处：文件树的行上，以及**本文件面板内部**（`[data-files-page]` 里的头部、树体、行下方空白）。面板以外——会话正文、消息、侧栏其它标签、对话框外——一律不弹，交还浏览器原生菜单；本地与远端两个面板并排时也不会互相借按钮，按钮与树必须同属这一页 |
| 行菜单收窄 | 单行、去描述行、**按宿主菜单的度量**（内容定宽 144–360px、行高 34px、内边距 6px 8px、标题 13px、项圆角 12px、浮层圆角 16px、分隔线 0.5px、图标 14px 取宿主菜单图标色）、最多 8 项、最多三组分隔线（下载到本机、新建文件 / 新建文件夹 / 重命名 / 删除各占一组）；菜单**只有自绘一条**（同一个右键在本地与远端工作区读起来一样），度量取自宿主行菜单；「新建工作区」选择菜单保留两行（标题 13px）并收敛到 250px。图标按动作区分：添加到任务、复制路径、新建文件、新建文件夹、重命名、删除各有独立线条图形，下载 / 上传共用托盘箭头 |
| 上传的路径加固 | 文件名必须**单个路径段**（含 `/`、`\`、`.`、`..` 一律 400），否则一个请求就能跳出用户正在看的目录 |
| 下载完成提示只在**看得见保存时**才说「已保存」 | 「字节到了页面」不等于「文件被保存了」。旧实现拿到 blob 就报「已下载」，而那时浏览器还没打开保存对话框——用户的取消是一次静默失败，大文件尤其明显（激活早就在第一个网络往返里用掉了）。现在**先选目标再请求**（`showSaveFilePicker` / `showDirectoryPicker` 需要点击带来的瞬态激活），页面**自己把字节写进所选句柄**，报的是**磁盘接受的字节数**；没有该 API 时退回浏览器下载流，提示改说「已开始下载…，保存位置由浏览器决定」。三种结果互不混淆：`handle` / `canceled` / `unsupported`——取消不消耗任何字节，而权限拒绝**不能**被报成取消。写失败一律 `abort()` 而非 `close()`：关闭会把半截文件发布到用户选定的名字下，读起来像成功 |

## 五、端口转发

| 功能 | 说明 |
| --- | --- |
| 正向映射 | 等价 `ssh -L`：远端 dev server 变成可打开的 `http://localhost:<port>` |
| 骑在连接池上 | 映射复用池化的 SSH 连接；连接断开即自动关闭，再次调用可重开 |
| 重复映射去重 | 同一目标再次映射返回已有条目，不叠加 listener |
| 监听地址可选 | 默认 `127.0.0.1`（仅本机）；`0.0.0.0` 暴露到局域网 |
| 拨号目标可选 | `remoteHost` 默认 `127.0.0.1`（远端服务自身），可指向远端可达的其他主机 |
| 持久化 | 映射写入 `dsh-ssh.json` 的 `forwards` 分区，重启后仍在列表里 |
| 意图与事实分离 | `enabled`（用户想要什么）与 `live`（当前是否真有 listener）分开存：按钮文案由事实决定，启动行为由意图决定——否则重启后连接未建立、按钮却写着「断开」就是谎报 |
| 已存映射严格端口 | 本地端口被占用就报错，**不静默漂移**到临时端口，否则保存的 URL 下次启动就失真 |
| 启动自动开启 | 面板有总开关（`autoStart`）；在稍后的 tick 上执行、从不抛出——不可达的主机不该拖慢或拖垮插件自身的激活 |
| 端口预检 | `GET /forward/probe` 提前告知 `EADDRINUSE` / `EACCES` 及不同文案；但**权威仍是 `open()` 抛出的绑定错误**，预检只是提前说明原因 |
| 断开两条路径一致 | 端口行「断开」与主机「断开连接」走同一个 `closeAlias()`：映射保留、意图置 `false`、**不记失败原因**——主动断开不是故障，面板不该亮红字 |
| 远端应用白名单 | 远端应用可能自带 host / 回调校验（Vite `server.allowedHosts`、Next `allowedDevOrigins`、OAuth redirect URI），需一并放行 localhost |

详见 [ui.md](./ui.md) 的端口转发与持久会话区。

## 五之二、断线与重连

| 功能 | 说明 |
| --- | --- |
| 后台重连 | 连接意外断开后自动重试，不需要用户先做一次操作；1 秒起指数退避、60 秒封顶、默认不限次数 |
| 只在有人用时重试 | 判定依据是「已挂载工作区 / `holds > 0` / 有 `enabled` 的保存转发」，全都没有就停——关掉的工作区不会在后台被拨回来 |
| 「断开」是终态 | 手动断开与改配置都会取消后台循环：按钮说了断，就真的不再拨号 |
| 不可恢复的错误立即停 | 未知别名、读不到私钥、主机密钥不匹配标记为 fatal，不每分钟重复同一个失败 |
| 恢复保存的转发 | 只由后台重连触发（前台首次连接不触发），重开该主机 `enabled` 的映射；关掉的映射不会被重新打开 |
| 状态可读 | 面板主机卡片显示「重连中（第 N 次，M 秒后）」/「重连已停止」+ 原因；`ssh_workspace_status` 的 `reconnecting` 给出同样的字段 |
| 立即重试 | `POST /hosts/reconnect` 跳过等待；失败时返回真实错误，而不是乐观的「正在重试」 |
| 事件有节制 | 前 3 次、之后每 5 次以及结束那次写 `reconnect` 事件，长时间断网不会冲掉 40 条环形缓冲里的其它信息 |
| 可关闭 | `engine.reconnect: false` 退回旧的「只在操作时重连一次」 |
| 接缝接管可查 | 每个 `patch-*.js` 的安装结果记成 `seams[]`（`installed` / `absent` / `failed`）。`failed` 会在 `ssh_workspace_status` 里显式打印 `SEAM NOT INSTALLED`、进诊断报告，并把状态胶囊变红——宿主改名导致某个包装装不上，代价被限制在那项功能上，而不是整个插件 |

实现见 [architecture.md](./architecture.md#后台重连libenginereconnectjs)；接缝接管的落盘位置见
[architecture.md](./architecture.md#接缝接管的结果表seams)。

## 五之三、远端 Skills 发现

远端仓库里的 `.dsh/skills` 与 `.agents/skills` 可以像本地一样被 `skill` 工具发现和加载。
这件事与「接管 `ctx.fs`」不是一回事：技能正文里的一句话会直接进模型上下文，所以这一路**默认关闭**，
按主机白名单开启。

| 功能 | 说明 |
| --- | --- |
| 默认关闭 | 配置里不写 `remoteSkills` 就什么都不发生：不拨号、不列目录、注册的 provider 直接答空。宿主把 provider 的 `description` 读进模型目录的**那一刻**就是提示词可见，这与「模型主动去打开一个文件」是不同的风险等级 |
| 主机白名单 | 只对 `remoteSkills.hosts` 里**点名**的别名生效；`*`、`bo?x` 这类通配写法被拒绝并记一条警告，因为那等于自动信任每一台主机 |
| 两个根、一层深 | 会话工作区下的 `.dsh/skills` 与 `.agents/skills`：`<root>/<名字>/SKILL.md`（目录 bundle）或 `<root>/<名字>.md`（平铺）。不递归、不跟随目录符号链接 |
| 只在已挂载的根里 | 会话 `cwd` 不在任何已挂载的远端根内时直接答空且**零 SSH 操作**——没接管这个工作区时，这不是失败 |
| 路径算术不用 `node:path` | 宿主的 `discoverRoot` 用 `path.join` 拼 `SKILL.md`，在 Windows 上会把 `ssh://box/data/proj` 拼成 `.\ssh:\box\data\proj\...`——这串既不是远端路径也不报错，候选会被静默丢弃。本插件自建发现循环，全程 `normalizeRemotePath` / `formatRemotePath`，并有断言钉住 locator 里不出现反斜杠 |
| frontmatter 子集 | 只认 `key: 标量`（可带引号）、布尔（`true/false/yes/no/on/off`）、一层嵌套映射、块标量 `|` / `>`。多出来的行**跳过而不是报错**——第三方 `SKILL.md` 里一个奇怪的键不该让整个技能消失。为此不引入 YAML 依赖 |
| 旧键一律拒绝 | `modelInvocable` / `userInvocable` / `disableModelInvocation` 是上一版拼写，出现即判定该文件不是可用技能，而不是猜一个值 |
| 非法候选在返回前就被滤掉 | 名字不匹配 `^[a-z0-9]+(?:-[a-z0-9]+)*$`、缺 `description`、`invocation` 取值非法的候选**不返回**。宿主的 `validateCandidate` 是 `throw` 且不在 `try` 里，放进去会让整个会话的技能目录读取失败，本地技能跟着一起消失 |
| 有界 | 每个根最多列 200 个条目、每台主机最多 32 个技能、单个 `SKILL.md` 最多 64 KiB、整趟 5 秒。上限值非法时**回落到默认而不是放宽** |
| 超限是跳过不是截断 | 超过 `maxBytes` 的文件整份跳过；截断后的 frontmatter 会解析成垃圾。前 8 KiB 含 NUL 或 UTF-8 解码失败同样跳过 |
| 不完整不等于空 | 某个根读失败时 `complete: false` 且**保留已读到的候选**——宿主据此不缓存，「这台主机没有技能」不会被写进缓存盖住一次断线 |
| 读也过围栏 | `remote-fs.js` 的围栏只挂在写路径上（`assertWithinRemoteRoots` 只被 `#assertWritable` 调用），所以 `get()` 每次加载正文前自己调一次 `assertFencedRealpath`：远端被种下的符号链接不会把读取带出工作区。拒绝发生在读字节之前 |
| 缓存与失效 | 每个「别名 + cwd」缓存 5 分钟；挂载 / 停用、注册被销毁时清空。远端改了技能不必重启，重新挂载或等 TTL 即可 |
| 诊断只记数量 | `remote-skills` 事件记「从哪个别名发现几个、跳过几个」，**不记正文也不记描述** |
| 诊断报告可扫读 | 报告正文按行着色：`WARN` / `verdict: needs attention` 黄，`## 小节` 加粗，`UNKNOWN` / `NOTE` / `verdict: could not judge` 静默灰，`verdict: ok` 绿；只有点到具体坏掉的东西（`failed`、`NOT PINNED`、`store error:`、`skipped:`）才红。颜色来自行首那个词本身，不是第二份判定；复制与手动回退仍是同一段纯文本。面板里每条 finding 的徽章用同一条规则（警告黄、坏掉红、无法判断灰），两处不会对同一条 finding 给出不同说法 |

**刻意不做的四件事**（边界，不是待办）：

| 不做 | 理由 |
| --- | --- |
| 远端 `AGENTS.md` | 技能是「按需加载」——目录与描述进上下文，正文靠 `skill` 工具取；`AGENTS.md` 是**常驻**指令段，一旦被远端控制，等于把提示词注入面长期打开。要做的话必须先有和 `remoteSkills` 同级甚至更严的开关 |
| 远端技能的自动安装 / 自动更新 | 只发现，不写远端。写远端会把「只读的发现」变成「可以改远端仓库」 |
| 跨主机的技能聚合 | 一次只用当前会话那台主机。聚合会让 A 主机的技能在 B 主机上生效，而用户以为自己只连了 B |
| 给远端技能提升权限 | 技能不能改变会话 mode、不能绕过写围栏。它是文本，不是能力 |

配置见 §八 的 `remoteSkills` 一节，实现见 [architecture.md](./architecture.md#远端技能发现libsurfaceremote-skillsjs)。

| 浏览目录对话框 | 主机卡片的「浏览目录」打开 `DirectoryBrowser`：逐级浏览（目录**单击选中**、**双击**进入，顶部路径栏 sticky；挂载用选中的目录）、「挂载此目录」，成功后附能力提示；**不再提供上传、下载或队列内联条**（传输只从文件树行菜单进入）。与「新建远程工作区」（`RemoteWorkspaceDialog`）是**两个组件**，但共用同一套路径栏与列表行为（见下两行） |
| 列表跟随输入 | 两个 picker 的路径栏不再只在回车时生效。同一目录内的前缀**只本地收窄**（大小写不敏感，零往返）；键入带尾斜杠的路径（`/home/me/` 明确表示「这是目录」）在停顿 `PATH_PREVIEW_DEBOUNCE_MS`（200 ms）后**只发一次**列目录请求；整条拼全的真实目录名只收窄成一行、**不自动进入**——进目录永远是补尾斜杠、回车或双击。**尾斜杠就是「在目录里」**：导航后草稿写成 `/raid/`，删掉斜杠即回到父目录并按 `raid` 收窄。预览请求不写输入框、不先清空列表（失败时旧行还在），且**只在主机答完后**才把 `path` 指向该目录，所以「挂载此目录」永远不会指向还在拼写的路径。输入框**没有 `onBlur` 复位**：双击的第一下会先 blur，复位会让行在两次点击之间移位 |
| 一键列目录 | 两个 picker 各只需名字，所以列表不再走 `sftp.readdir`：那要服务器为每个条目做一次 `lstat`（实测 25 000 条的目录在 300 ms 链路上 30 s 不返回，同机 `ls` 只要 44 ms）。现在是一次 `engine.exec` 跑 `ls -1ap \"$dir\" \| awk`，**上限在远端就生效**（大目录最多只传 `limit` 个名字），同一轮往返里用 `pwd -P` 解析登录目录、用 `test -w` 报可写性，stdout 只走名字、stderr 只走一行标记。命令只列**目录**（`ls -p` 的尾斜杠即类型，文件与符号链接都被排掉），所以响应里不需要逐名的 `type` 列。任何形状不符（非 POSIX 登录 shell、缺 `awk`、目录不可读、退出码非 0、计数不自洽、脚本自认 `fallback`）一律**回退到 SFTP**——这是优化，不是第二套实现。列目录不进审计环（与 `readdir` 同理，否则每次按键都会把多行脚本塞进环里） |
| 可写探测 | `/ls` 同时回报 `writable`，目录不可写时红色警告并**禁止创建**——写入能力是 Agent 工作的前提 |
| 折叠单链目录 | 列表里「每层只有一个子目录」的一串会折成**一行**（`src/app/feature`），点进去才展开——省的是点击次数，不是新的导航方式（点击仍走普通进入目录）。折叠发生在同一条一次往返的 `ls` 命令里：`find -type d` 用 **lstat**，所以**软链永不折叠**（链接可以离开当前目录，指向父目录的链接更会无限折下去）；层数上限 **16**；某层出现 0 或 2 个以上子目录就停；可写性仍取自**调用者问的那个目录**，标记行回传的也是它而不是链尾。**只有快路径折叠**：SFTP 回退要逐层 `readdir`，那正是折叠省掉的开销——差异只影响呈现，不影响有哪些条目 |
| 远程工作区标记 | 侧栏行、工作区选择器、会话页工作区按钮显示远端标记图标而非普通文件夹。**同名不误标**：本地与远程可以合法共用标题，两边都有的标签不标识任何一方，标题规则只在完整读过宿主 store 后生效（`/status` 回退只按 id） |
| 停用置灰 | `/status` 下发 `workspaces[].sessionIds`，停用工作区的**会话行**也一并置灰；**只置灰、不拦点击**——行、按钮、展开全都照常，真用不了的地方由宿主自己报「已停用」 |
| 文件树与预览 | 「工作区文件」侧栏直接列出远端目录，文本预览经 SFTP 读取 |
| `@` 远程引用 | 补全候选来自**远端**目录（递归索引 + 模糊排名，含 `/` 逐级下钻，目录符号链接不跟随），选中插入 `@相对路径` |
| 拖拽 / 右键进任务 | 文件与文件夹可直接拖到聊天输入框（悬停虚线高亮，松开插入引用 chip；指针在输入框内时按落点插入，拖动期间显示竖向光标，不可映射时回退追加），或右键「添加到任务」 |
| 持久远端会话区 | 只读列出当前打开的持久 shell；列表为空时整区不渲染 |
| HMR 幂等 | 拖入一个文件只生成一个 chip：已处理事件集合挂在全局并以事件对象为键，一次派发只被消费一次 |

## 七、主机与安全

| 功能 | 说明 |
| --- | --- |
| 主机硬停用（电源开关） | 存储主机的卡片左侧是 `role="switch"` 电源开关。关＝**立刻**关闸并拆掉这台主机上的一切：引擎准入（`HOST_DISABLED`）、在途命令与通道（abort）、池化连接（forget）、持久 shell、正向与已存转发、反向转发、变更监视、远端终端；顺序是「先持久化 `enabled:false`，再关闸，再拆」，持久化失败则什么都不拆。开启只持久化并开闸，**不主动拨号**（拨号仍归连接意图与首次使用）。关之前弹确认框，按 `/hosts` 刚读到的**实时**计数列出连接 / 在途命令 / shell / 转发 / 反向 / 监视 / 终端；会话与工作区属于宿主，插件不关，只按 `/status.disabledHosts` 置灰（`data-sshwsp-hostoff`），点开后仍由路由 409 说明原因。`~/.ssh/config` 主机没有开关（没有记录可写）；存储记录与 config 块同名时以存储为准，开关仍在——它写的是那条存储记录，关掉的也是这个别名。`/hosts/test`、`/hosts/reconnect` 与所有拨号路径对停用主机一律 409 |
| 主机来源 | `$DSH_HOME/dsh-ssh-workspace/dsh-ssh.json` 优先（旧根路径可读并迁移），缺失时回退读取 `~/.ssh/config` 的具体 `Host` 块；已配好的主机无需重复配置 |
| `~/.ssh/config` 只读 | 面板不改写 `~/.ssh/config`；与存储同名的主机以存储为准，但**编辑与删除都拒绝**（`configAlias` 标记，面板不给按钮、路由 409：删掉存储条目只会露出那个 `Host` 块，改它会让本机其它 ssh 客户端解析到的东西悄悄变样），要改就去那个文件里改；`Include` 跟随、`Match` 求值；带 `ProxyCommand` 的主机在解析时**明确拒绝**并说明原因（`ProxyJump` 已支持） |
| 认证方式 | `key`（含 `keyPath` 与口令）/ `password` / `agent`（含 `agentPath`） |
| 表单内测试连接 | 主机表单底栏的「测试」在**保存之前**真拨一次：`POST /test` 的 `form` 分支按屏幕上的字段构造描述符（`store.descriptorForForm`，空口令沿用已存凭据）并 `engine.probeDescriptor` 连上即断——**不写存储**（主机条目与 `knownHosts` 都不动，主机密钥只比对不 pin）、不池化连接、不启动重连；成功显示耗时、失败显示服务端原话，字段一改结果立即失效 |
| 凭据加密 | 密码与私钥口令存进 `dsh-ssh.json` 的 `secrets` 段，AES-256-GCM，密钥为 `$DSH_HOME/dsh-ssh-workspace/dsh-ssh.key`（仅本用户可读；旧根路径密钥仍被读取）；**从不回传浏览器**，编辑时留空表示保留原值 |
| 明文迁移 | 老版本留在共享存储里的明文凭据在启动时一次性搬进加密段，best-effort——读不懂的存储原样放过而不是覆盖 |
| 主机密钥 TOFU | 首连记录服务器主机密钥 SHA256 指纹；之后指纹变更**拒绝连接**并提示新旧指纹，防中间人；主机重装后在面板「忘记主机密钥」重新信任 |
| 文件权限 | 存储文件 0600、目录 0700（POSIX）；旧文件补一次 `chmod`（best-effort，win32 上 mode 语义有限，不能因此阻断） |
| 并发写 | `mutateHosts` 原子读改写 + 零依赖文件锁，避免面板与工具同时改存储时丢更新 |
| 路由加固 | 仅回环来源 + `Host` 头必须是本端口的回环拼写（堵 DNS rebinding）+ 写操作要求 JSON `Content-Type`；`/download` `/upload` 另行各自施加双重校验 |
| 连接复用与回收 | 每别名一条长连接；空闲 **30 分钟**回收，有操作在飞的连接不回收；握手超时 **15 s**、keepalive **15 s**、扫描周期 **60 s** |
| 能力探测 | 挂载时一次往返探测 `rg` / `git` / `inotifywait`，只把**已知缺失**的项报成提示（探测不出来不算失败）；经**原始连接**探测，绕开停用围栏 |

详见 [hosts.md](./hosts.md) 与 [protocol.md](./protocol.md)。

## 八、配置项

| 字段 | 默认 | 含义 |
| --- | --- | --- |
| `enabled` | `true` | 总开关；`false` 时插件完全不安装 |
| `announceToAgent` | `false` | 是否向每个 agent 注入能力说明（系统提示词段落） |
| `localPassthrough` | `['$DSH_HOME/attachments', '$DSH_HOME/plugins']` | 在 `ssh://` 会话中保留本机语义的本机绝对前缀；`false` / `[]` 关闭。词法匹配，不接受整目录 `$DSH_HOME`。消息里 `@` 点名的 Windows 盘符 / UNC 路径同样直通（引用表上限 256） |
| `localPassthroughScheme` | `local` | 显式点名本机路径的 scheme 名（`local:/abs/path`）。**≥ 3 个字符**（1 个字符会与 Windows 盘符抢同一段文本，例如 `c:/x`）；小写字母、数字与 `+ - .`；`ssh`、`file`、`sftp`、`dsh-app` 与常见 URL scheme 是保留名（完整清单与理由由 `/status` 的 `passthrough.schemeRules` 下发）。**同一时间只能配置一个**：换名字即整体替换，旧前缀立刻失效，两个不能并列。**前缀名不区分大小写**（`Local:` / `LOCAL:` 等价于 `local:`），而冒号后面的**路径部分按平台**：Windows 不区分大小写，macOS / Linux 区分。**只是首次默认**，面板存过之后以 `dsh-ssh.json` 的 `passthrough.scheme` 为准（面板位置：`ssh://` 会话的「文件引用设置」一区 →「显式文件引用 scheme」） |
| `localPassthroughFallback` | `false` | `@` 点名的 POSIX 绝对路径远端报不存在时，是否回退到本机同名文件。只影响读动词；同样只是首次默认 |
| `engine.idleTimeoutMs` | `1800000` | 连接空闲超过该时长后回收（毫秒） |
| `engine.connectTimeoutMs` | `15000` | 单次 SSH 握手超时（毫秒） |
| `engine.keepaliveIntervalMs` | `15000` | keepalive 心跳间隔（毫秒） |
| `engine.sweepIntervalMs` | `60000` | 空闲连接扫描周期（毫秒） |
| `engine.reconnect` | 见下 | 断线后的后台重连策略；`false` 关闭 |
| `engine.reconnect.baseDelayMs` | `1000` | 首次重试等待（毫秒），之后按 2 的幂增长 |
| `engine.reconnect.maxDelayMs` | `60000` | 单次等待上限（毫秒） |
| `engine.reconnect.maxAttempts` | `0` | 最多尝试次数；`0` 表示不限次数 |
| `engine.reconnect.jitter` | `0.2` | 向下抖动比例（不会超过上限） |
| `remoteSkills.enabled` | `false` | 是否发现远端技能。**默认关闭**：技能描述一旦被读到就进模型上下文，与「模型主动打开一个文件」是不同风险等级 |
| `remoteSkills.hosts` | `{}` | 主机白名单：`{ "别名": { roots?, maxEntries?, maxSkills?, maxBytes?, timeoutMs? } }`。键必须是精确别名，`*` / `?` 通配写法被拒绝（那等于自动信任每台主机） |
| `remoteSkills.hosts.<别名>.roots` | `['.dsh/skills', '.agents/skills']` | 相对会话工作区根的技能目录，一层深：`<root>/<名字>/SKILL.md` 或 `<root>/<名字>.md` |
| `remoteSkills.hosts.<别名>.maxEntries` | `200` | 单个根最多列多少个条目 |
| `remoteSkills.hosts.<别名>.maxSkills` | `32` | 单台主机最多返回多少个技能 |
| `remoteSkills.hosts.<别名>.maxBytes` | `65536` | 单个 `SKILL.md` 的字节上限；超过整份跳过（截断的 frontmatter 会解析成垃圾） |
| `remoteSkills.hosts.<别名>.timeoutMs` | `5000` | 单趟发现的时间预算，超出后已读到的保留、`complete: false` |

`engine` 下各项均为可选，非法值回落默认，通常无需配置。

面板里另有 `forwards.autoStart`（启动时自动开启已存隧道），写在存储里而非插件配置。

## 九、依赖与降级矩阵

远端主机**不需要**装任何本插件的东西，但有三项工具决定部分能力是否满血：

| 远端依赖 | 影响的能力 | 缺失时的表现 |
| --- | --- | --- |
| `ripgrep`（`rg`） | `glob` / `grep` | 命令以退出码 **127** 失败，附安装提示（`sudo apt install ripgrep` / `brew install ripgrep`）；工具层呈现为带提示的失败 |
| `git` | 「变更」面板的回合快照与 diff | 按「无仓库」降级：只列文件工具改动，每回合一条 warn，**不阻断会话** |
| `inotifywait` | 文件树 / 预览的变更自动刷新 | 回退到轮询（基础 2 s，空闲退避至 10 s），几秒延迟 |
| `posix-rename@openssh.com`（服务器扩展） | 原子写入 | 退化为「先删后改名」，此时写入不再原子 |

前三项在挂载时探测，缺失项在挂载结果与面板里直接提示。全部**本地**工作区不受任何影响。

## 十、明确的边界

| 边界 | 说明 |
| --- | --- |
| `ProxyJump` 跳板机 | **支持**：按 `ssh -J` 的形状逐跳建独立连接（最多 8 跳），目标只看到直接邻居；`a,b` 多跳按顺序、`user@host:port`、方括号 IPv6、`none` 强制直连都接受，每跳各自认证并固定自己的主机密钥。自引用与重复跳在解析时拒绝 |
| `ProxyCommand` | **拒绝**：它是任意本地命令执行，配置文件是数据、不能变成「读配置 = 执行程序」。带 `ProxyCommand` 的主机在解析时**明确拒绝并说明原因**，而不是悄悄按直连去试 |
| 文件名编码 | SFTP 只给字节，`readdir` 默认按 UTF-8 解出名字；传 `encoding: 'buffer'` 或具体编码时按该编码转换。非 UTF-8 文件名（如 GBK 主机的历史文件）在所有显示路径上都按 UTF-8 解读，可能出现乱码 |
| 远端命令的沙箱 | 远端命令以远端登录用户权限运行，**本机沙箱策略不适用**——这是设计取舍，不是缺口 |
| 下载整个目录 | 两条路都可以：浏览器端走 `/download-tree`（默认一个 zip 归档，`?format=tar` 可回退，见上），工具端用 `recursive: true` 落到本机的一个目录。浏览器端**不**给出解压后的目录——它拿不到目录，只拿得到文件 |
| 读取不受围栏限制 | 写入围栏只约束写与删；读取任何路径都允许（与部署本地后端的口径一致） |
| `inspectForeground` 精度 | 远端 PTY 无法廉价读等价信息，宁可答「未知」也不猜 |
